# 제품 도메인 규칙

이 문서는 `miriondon` 가계부 서비스의 금융 도메인 비즈니스 로직과 데이터 취급에 관한 필수 기준입니다.

## 1. 민감 정보 보호

- 거래 설명, 계좌·카드 이름, 잔액, 가맹점, 명세서, 사용자 식별자는 민감 정보입니다.
- 소스 코드, 로그, 테스트 픽스처, 오류 메시지, 스크린샷에 실제 개인 금융 데이터를 남기지 않습니다. 테스트 시에는 명시적인 가명·더미 데이터를 사용합니다.

## 2. 화폐와 금액 계산

- 금액은 부동소수점(`float`, `double`, `number`의 소수 연산)으로 계산하거나 저장하지 않습니다.
- KRW 금액은 **정수 원 단위**로만 다루며, 향후 다중 통화 지원 시 통화별 최소 화폐 단위(예: USD의 cent)를 명시적으로 모델링합니다.

## 3. 거래 유형과 계좌 이체

- 수입과 지출은 명시적인 거래 유형(Type) 또는 부호로 구분합니다.
- 계좌 간 이체는 연결된 두 이동(출금 계좌 차감 + 입금 계좌 증액)으로 모델링하며, 수입·지출 합계를 부풀리지 않습니다.

## 4. 거래일과 시각 기준

- 사용자가 입력한 거래일과 시스템 처리 시각(created_at, updated_at)은 엄격히 구분합니다.
- 별도 요구사항이 없으면 거래일은 `Asia/Seoul` 기준의 달력 날짜로 해석합니다.

## 5. 금융 기록의 불변성과 변경 제약

- 금융 기록을 자동으로 병합, 변경, 삭제하지 않습니다.
- 모든 금융 데이터의 수정·삭제는 명시적인 사용자 흐름, 권한 검사, 그리고 요구사항에 맞는 변경 이력 기록을 전제로 합니다.
