# 미리온돈 제품 기획안

작성일: 2026-11-03

수정일: 2026-11-05

대상 버전: 초대 기반 무료 알파·모바일 퍼스트 반응형 웹(모바일 웹 우선, PC 웹 지원). 기능별 동작과 수용 기준은 [MVP 기능 명세서](./mvp-functional-spec.md)를 따른다.

근거: [기존 가계부 스프레드시트 분석](./spreadsheet-analysis.md).

보안 기준: [금융 데이터 암호화·키 관리 규칙](./encryption-policy.md). KMS 봉투 암호화와 별도 세션 쿠키로 보호한 Redis 키 캐시를 채택하고 원본 파일은 보관하지 않는다. 제공사·키 단위·캐시 수명 등은 구현 설계 대상이다.

## 1. 제품의 목적

미리온돈은 이미 쓴 돈과 앞으로 나갈 고정지출·할부를 미리 생활비에 반영하고, 어느 결제 계좌에 얼마를 더 준비해야 하는지 알려주는 가계부다. 예정 지출을 포함한 카드 실적과 단계별 기준까지 부족한 금액을 확인해 사용할 카드를 판단하도록 돕는다.

혼자 또는 가족·부부·연인 등 돈을 함께 관리하는 사람과 사용할 수 있다. 공동 가계부의 구성원은 같은 가계부의 기록을 함께 관리한다.

사용자가 내려받은 카드 이용내역과 결제예정·청구내역 파일을 가져오는 방식으로 시작한다. AI는 구조·열 의미를 해석하고 분류를 추천하며, 프로그램이 원본 값 추출·검증·금액 계산을 수행한다. 은행 잔액·수입·이체·정산은 사용자가 기록한다.

> 이미 쓴 카드값과 앞으로 나갈 돈까지 반영해, 이번 달 남은 생활비를 확인하세요.

예정 지출을 포함한 카드 실적과 결제 계좌별 추가 준비액을 함께 제공한다. AI는 기록 부담을 줄이는 입력 보조 수단이며 제품의 주된 효용은 예정 금액을 포함한 계산·대조·공동 관리다.

## 2. 출발점과 해결할 문제

기획자는 스프레드시트로 예산·거래·카드 실적·준비금·받을 돈과 실제 잔액을 함께 관리한다. 통장 잔액에는 이미 쓴 카드값과 앞으로 나갈 돈이 남아 있어 그대로 생활비로 볼 수 없다.

고정지출을 실제 결제 전에 적어두는 것이 핵심이다. 월말 자동결제 예정액도 생활비와 카드 실적에 포함해야 지금 더 쓸 돈과 혜택 기준에 부족한 실적을 판단할 수 있다. 카드사 화면의 이미 발생한 사용분만으로는 이 목적을 충분히 해결하지 못한다.

| 확인한 불편                              | 개선 방향                                                |
| ---------------------------------------- | -------------------------------------------------------- |
| 연도마다 파일 복사와 전년도 값 이관      | 월·연도 경계 없는 거래·예산·실적·준비금 연결             |
| 거래마다 카드 조건에 따라 Y/N 반복 입력  | 카드 조건에 따른 기본값 자동 적용, 필요한 예외만 수정    |
| 이체한 거래 상태와 변경 차액을 수동 관리 | 선택·전체 거래 단위 준비 처리와 다음 이체 조정 연결      |
| 한 결제를 분류별로 여러 행에 기록        | 원결제 한 건 안의 분류 분할과 카드사 할인 비례 배분      |
| 잔액오차 원인을 찾기 어려움              | 실제 잔액과 계산 근거·차이를 제시, 고급 이력 추적은 후속 |

남은 생활비, 계좌별 추가 준비액, 예정 포함 카드 실적, 돌려받을 돈을 함께 관리하는 흐름이 제품의 핵심이다. 이 문제의 중요도는 한 사용자의 실제 경험으로 깊이 확인했으며, 다른 사용자에게 같은 편익이 있는지는 알파에서 검증한다.

## 3. 첫 버전과 사용자·가계부

### 무료 초대 알파

- 모바일 퍼스트 반응형 웹(모바일 웹 우선 구현, PC 웹 순차·확장 지원)으로 제공하며 카카오 로그인만 제공한다.
- 초대받은 사용자만 가입한다. 기존 가계부 소유자·관리자는 가계부 설정에서 이메일 및 역할을 지정해 초대장을 발송하거나 초대 링크를 복사해 신규 사용자를 초대할 수 있다. 초대를 발송하면 대상자는 수락 전까지 '초대 대기' 상태로 관리되며 발송자가 취소할 수 있다.
- 회원가입·로그인과 여러 기기 동기화를 포함한다. 한 기기에만 기록을 저장하지 않는다.
- 첫 알파에는 구독료·결제 기능을 넣지 않는다. 공개 가입·유료화·네이티브 모바일 앱은 후속 범위다.

개인 가계부와 공동 가계부를 지원한다. 공동 사용을 가입 조건으로 두거나 개인 가계부 생성을 공동 사용의 필수 절차로 강제하지 않는다. 첫 검증 대상은 기획자와 주변 신혼부부를 중심으로 하되, 용어·데이터 구조를 부부 전용으로 고정하지 않는다. 공간·구성원 수 제한과 미성년자 정책은 별도 검토 대상이다.

### 역할과 기록 유지

- 생성자는 한 명의 소유자가 되며 관리자는 여러 명 지정할 수 있다.
- 가계부의 거래는 모든 구성원이 입력·수정할 수 있다.
- 분류·예산 등 공동 가계부 설정은 소유자·관리자가 변경한다. 모든 구성원은 본인의 자산·카드를 등록·관리하며, 고정 수입·고정 지출은 소유자·관리자·구성원 모두 등록·수정·중지할 수 있다. 소유자·관리자는 다른 참여 구성원의 자산을 대신 등록할 수 있다.
- 가계부 삭제·소유권 이전 같은 최상위 작업은 소유자만 수행한다. 소유권은 다른 구성원에게 이전할 수 있다.
- 새 구성원은 기존 가계부의 과거 기록을 볼 수 있다. 탈퇴자는 가계부 접근이 종료되지만 기존 기록과 합계는 유지한다.
- 삭제한 가계부는 30일 이내 서비스 운영자에게 문의해 복구를 요청한다. 사용자용 직접 복구 기능은 두지 않는다. 운영자는 소유 권한을 확인하고 복구한다.

초대 만료·관리자 지정 및 해제·삭제 후 백업 정리 같은 세부 절차는 기능 명세서의 구현 전 설계 항목으로 관리한다.

### MVP에서 제외

- 금융기관 자동 연동, 은행 거래 파일 가져오기, 문자·푸시 알림 자동 수집과 알림 텍스트 일괄 입력. 사용자가 직접 첨부하는 단건 결제 캡처는 MVP에 포함한다.
- 실제 자동 송금·결제, 한 거래 금액 일부만 준비 처리하는 기능.
- PDF·일반 영수증 인식과 여러 이미지·복수 거래의 일괄 등록. 문자·알림·카드 앱의 단건 결제 내역 캡처 한 장으로 초안을 만드는 범위는 MVP에 포함한다. 지원 카드 파일 형식은 실제 표본 검증 후 확정.
- 입금 자동 정산, 사람별 자동 정산 규칙, 상대방이 먼저 결제했을 때 별도 보낼 돈 관리.
- 개인자금 지급 이후 개인 지출 관리 강제·자동 연동.
- 개별 거래 없이 가족 카드 사용 합계만 따로 관리하는 방식.
- 마지막 잔액 일치 이후의 변경을 모아 원인을 찾는 고급 추적.
- 공제 판정·세액 계산·절세 추천·연말정산 화면. 데이터 확장 요구는 유지.
- 모든 카드 약관의 상시 자동 갱신과 혜택 금액 전체의 최적화·자동 카드 추천.
- 네이티브 모바일 앱, 공개 가입, 구독·결제, 외화 환율·금 참고 시세 외의 시세와 수익률·대출 이자·상환 일정 등 전문 자산관리 자동 계산. 생활비 외 자산·부채의 등록·수동 금액 갱신·합계 조회는 MVP에 포함한다.

## 5. 핵심 기능과 계산 원칙

### 생활비·실제 잔액·시작금액

분류별 남은 생활비는 월별 예산에 전월 이월금을 더하고 해당 월 생활비 반영 지출을 뺀 금액이다. 초과 지출의 음수도 다음 달로 이월한다.

실제 보유금은 은행의 실제 잔액을 사용자가 입력한다. 대조용 생활비는 관리 범위의 실제 보유금과 아직 받지 않은 수입·받을 돈, 아직 처리하지 않은 지출 의무를 반영한다. 준비 완료한 돈을 다시 쓸 수 있는 생활비로 합산하지 않는다.

대조 기준 금액은 계좌·현금의 실제 보유금 합계에 미입금 수입·받을 돈을 더하고 미출금 지출 의무를 뺀다. 외화 계좌와 외화 현금은 확인된 원화 평가액을 포함하고, 평가액이 확인되지 않았다면 그 사실을 알린다. 이미 출금된 금액과 계좌 간 내부 이동, 준비금과 청구대금은 중복 반영하지 않는다. 자산현황의 자산별 상세에서는 오차가 있을 때만 금액을 알림 배너로 표시하고, 배너의 버튼으로 계산 근거를 모달에서 확인한다. 자산현황은 미회수 금액이 있을 때만 버튼을 표시하고, 전체 기간의 상대별 미회수 금액은 모달에서 보여준다.

받을 돈도 예정금액으로 반영하므로 남은 생활비를 지금 즉시 인출할 수 있는 현금 잔액과 같다고 설명하지 않는다. 같은 자금을 계좌·가계부 사이에서 중복 포함하지 않게 설계한다.

```text
예산상 생활비 = 월별 예산 + 전월 이월금 - 생활비 반영 지출
미회수 금액 = 현재 회수 대상 금액 - 회수한 금액
잔액 차이 = 실제 보유금·예정 입출금으로 산정한 대조용 생활비 - 예산상 생활비
첫 달 시작금액 = 대조용 생활비 - 첫 달 예산 + 첫 달 생활비 반영 지출
```

사용 시작 기준은 선택한 월의 1일이며, 가입 시점의 현재 월뿐만 아니라 과거 임의의 월도 시작월로 선택하거나 이후 가계부 설정에서 시작월을 과거로 앞당길 수 있다. 첫 달의 전월 이월금(시작금액)은 사용자가 직접 입력·수정할 수 있으며, 현재 월 시작 시에는 현재 잔액과 월중 거래를 반영해 자동 역산할 수도 있다. 과거 월부터 시작할 때는 직접 입력(또는 0원)을 기본으로 권장한다. 역산 시 분류별 예산 비율로 자동 배분하고 수정할 수 있게 하며, 음수와 원 단위 잔여도 합계를 맞춘다.

거래가 바뀔 때마다 시작금액을 자동으로 바꿔 오차를 없애지 않는다. 시작월 중에는 사용자가 직접 이월금을 수정하거나 자동 역산을 다시 실행해 맞출 수 있다. 잔액 차이만 보여주며 완료·미완료 상태나 오차에 따른 저장 차단을 두지 않는다. 2번째 달부터는 전월 실제 잔액이 자동 이월되므로 시작금액 직접 수정 및 역산 기능은 시작월에 한해 제공한다. 계좌 포함 범위·기준 시점·역산 예외는 계산 설계에서 검증한다.

가계부 설정은 자산·카드(기본 탭), 분류·예산, 고정 수입·지출, 구성원·권한, 가계부 관리로 나눈다. 자산·카드에서 자산과 카드를 나누고 각각 구성원별로 표시한다. 자산은 구성원 안에서 등록 시 선택한 구분별로 관리하며 자산현황과 같은 자산을 참조한다. 고정 수입·지출에서는 매월 반복되는 고정 수입과 고정 지출을 한 화면에서 관리하며, 소유자·관리자·구성원(member) 모두 추가·수정·일시중지·삭제할 수 있다. 고정 수입·지출 설정은 기본 예산과 마찬가지로 신규 월이 생성될 때만 예정 거래로 복사 생성되며, 이미 생성된 월의 수입·지출 내역 수정·삭제와는 완전히 분리된다. 조회할 수 있는 설정은 수정 권한이 없어도 읽기 전용으로 보여주고, 조회 권한이 없는 메뉴는 숨긴다. 구성원 초대와 역할 변경은 구성원·권한에서 관리한다. 소유자는 참여 구성원의 역할을 소유자로 변경해 소유권을 이전할 수 있으며 이전 후 관리자가 된다. 소유권 이전과 가계부 삭제는 소유자만 할 수 있다.

### 분류·기본 예산·월별 예산

분류는 한 단계로 유지한다. `생활/동물`은 상하위가 아닌 하나의 분류다. 가계부 생성 때 추천 항목을 클릭해 추가하거나 직접 입력하며, 가계부 설정에서 언제든 새 분류를 추가하거나 이름을 수정할 수 있다. 분류명을 수정하면 전체 기간의 거래와 통계에 일괄 반영된다. 새 분류는 이름만 입력해 추가하며 기본 예산 0원으로 생성된다. 이미 생성된 월에도 예산이 0원으로 추가되어 기존 예산 계획을 흔들지 않고, 이후 새로 생성되는 미래 월부터 기본 예산이 자동 반영된다. 월별 예산 역시 고정 수입·지출과 동일하게 신규 월 생성 시에만 기본 예산에서 복사되며, 이미 생성된 월의 예산은 기본 예산 변경과 완전히 분리된다(기생성 예정월은 `예정월 초기화`로 고정 항목·예산을 함께 초기화 후 재생성 가능). 가계부 설정의 분류 목록 하단에는 활성 분류의 기본 예산 총액을 함께 표시한다. 연결 거래가 없는 분류는 완전 삭제할 수 있다. 거래가 있는 분류는 비활성화하며 과거 거래·통계를 보존한다. 당월 지출 내역은 지금까지 기록된 내역을 그대로 인정하고 추가 기록은 불허한다. 단, 고정 거래나 미래 할부, 또는 현재 월 이후의 미래 월에 등록된 거래가 1건이라도 존재하는 경우 비활성화를 차단하며, 당월 잔여액(이월금·예산·지출 잔여)이 남아있는 경우 타 활성 분류와의 월별 예산 상계(필요 시 음수 예산 허용)를 통해 잔여액을 0원으로 맞춘 뒤 비활성화하여 익월 이월금을 0원으로 소멸시킨다. 비활성화된 분류는 설정에서 언제든 재활성화할 수 있다.

구성원이 로그인하면 가계부별로 현재 월부터 두 달 뒤까지 없는 월을 미리 준비한다. 예를 들어 11월에는 다음 해 1월까지 준비하며, 미접속 기간의 누락 월도 시작월 이후부터 보완한다. 여러 구성원이 로그인해도 같은 월은 중복 생성하지 않고 기존 월의 예산·거래·이월은 유지한다.

기본 예산은 새 월의 기준값이고 월별 예산은 예상 실수령액·큰 지출에 따라 조정할 수 있다. 가계부 설정에서는 분류와 기본 예산(0 이상 정수)을 관리하고, 월별 현황에서는 선택한 월의 분류별 예산을 조정한다. 월별 예산은 분류 간 잔액 이관 및 비활성화 상계를 위해 음수(-) 금액을 허용하되, 해당 월 가용 잔여액이 0 미만이 되지 않는 한도 내에서 허용한다. 선택 월의 입금 완료·예정 수입의 생활비 예산 반영액을 구분해 예산과 비교한다. 예산이 더 많으면 경고하고 수입이 더 많으면 미배정 금액을 안내하되 저장을 막지 않는다. 수입 기록이 없으면 등록을 안내하며 전월 이월은 비교에서 제외한다. 기본값 변경은 이미 생성한 월 예산을 덮어쓰지 않는다. 금월·미래 월은 기본값으로 리셋할 수 있지만 과거 월은 리셋할 수 없다. 리셋은 예산만 바꾸고 거래·이월금을 초기화하지 않는다.

### 지불 상태와 거래 단위 준비 처리

지출을 추가하거나 수정할 때 지불 상태를 선택한다. 지출 목록에서도 현재 상태를 확인한다.

| 지불 상태 | 의미                                                   |
| --------- | ------------------------------------------------------ |
| 준비 필요 | 아직 지불할 돈을 확보하지 않았고 실제 지불도 하지 않음 |
| 지불 대기 | 지불할 돈을 확보했지만 실제 지불은 아직 끝나지 않음    |
| 지불 완료 | 카드대금 출금이나 현금·직접 이체 등 실제 지불이 완료됨 |

같은 계좌에서 돈을 확보해 둔 경우에도 지불 대기로 기록한다. 계좌로 지출할 때는 결제수단에서 등록된 출금 계좌의 이름을 선택한다. 계좌이체도 미리 지불할 돈을 별도 계좌에 확보했다면 지불 대기로 기록할 수 있다. 현금이나 계좌이체는 준비 필요에서 지불 완료로 바로 변경할 수도 있으며, 사용자가 실제 상황에 맞게 상태를 선택한다. 상태 변경은 실제 송금이나 잔액 변경을 실행하지 않는다. 이전 월 거래를 새로 입력하거나 가져올 때는 지불 완료를 기본값으로 제시한다.

MVP는 거래 단위 선택과 전체 선택을 지원한다. 2만 원짜리 5건 중 3건을 선택하면 6만 원을 이체하거나 확보하고 그 3건을 지불 대기로 기록한다. 한 거래의 일부 금액만 준비하는 기능은 넣지 않는다.

### 생활비 계좌와 결제 계좌

계좌는 자산현황의 자산·부채와 구분해 관리한다. 한 계좌를 생활비 사용과 카드 결제에 함께 사용할 수 있으며, 카드마다 출금될 계좌를 연결한다. 생활비 관리에 포함할 계좌는 사용자가 지정한다. 계좌를 한 가지 용도로만 제한하지 않는다.

결제 계좌가 생활비 계좌와 다르면 사용자가 실제로 이체한 뒤 거래 단위로 준비를 기록한다. 같은 계좌라면 이체 없이 거래 단위로 결제할 금액을 확보한 것으로 기록한다. 확보한 금액도 실제 계좌 잔액에는 남아 있으므로 생활비 대조에서 아직 출금되지 않은 카드 대금을 제외한다.

잔액 확인 시점에 이미 출금된 금액은 실제 잔액에 반영돼 있다. 같은 계좌의 남은 카드 의무는 실제 잔액에서 한 번만 제외한다. 지불 대기와 준비 필요 의무를 중복 없이 반영한다. 실제 잔액과 지불 상태에 반영된 범위를 함께 확인한다.

### 준비 후 금액 변경과 조정

준비 완료한 거래를 취소·감액하면 차액을 다음 이체에서 빼고, 추가 청구는 더한다. 반영한 조정은 소진해 다시 적용하지 않는다. 음수 조정은 기본적으로 결제 계좌에 남겨 다음 준비에 쓰며 생활비 계좌로 자동 반환하지 않는다. 필요액보다 큰 음수 잔여를 버리지 않는다.

지불 대기 거래의 결제수단이나 결제계좌를 변경할 때는 준비 이력을 무시하고 계좌만 교체하지 않는다. 사용자가 실제 자금 처리 방식(기존 계좌 잔여 조정 유지, 계좌 간 직접 송금에 따른 준비금 이관, 생활비 계좌로의 수동 회수) 중 하나를 선택해 실제 자금 흐름과 장부를 일치시킨다.

조정은 결제 계좌·현금·원거래·기존 준비 처리와 연결한다. 같은 결제계좌를 사용하는 여러 카드의 준비액은 함께 확인할 수 있지만 다른 결제계좌의 조정은 섞지 않는다. 선택 거래 금액·조정 금액·채울 금액을 확인한 뒤 기록한다. 반영되지 않은 조정은 해당 계좌·현금에 유지한다. 준비 취소는 원래 처리에 연결하며 이후 발생한 조정을 덮어쓰지 않는다.

### 지출 반영월

수입은 실제 입금일과 별개로 예산 반영월을 선택한다. 지출 기록·수정에서는 예산 반영월 입력을 제공하지 않고 반영월을 자동 산정해 미리보기에서 보여준다. 일반 지출은 거래일, 예정 고정지출은 예정일이 속한 월에 반영한다. 할부를 새로 기록할 때는 현재 조회 중인 지출 내역 월을 입력한 회차의 반영월로 삼고, 회차 번호 차이만큼 앞뒤 월을 계산한다. 예를 들어 2027년 1월에서 2회차를 기록하면 1회차는 2026년 12월, 3회차는 2027년 2월이다. 기존 범위대로 입력 회차부터 남은 예정 회차를 생성하며 이전 회차를 역산했다는 이유로 과거 지출을 중복 생성하지 않는다. 원승인일과 회차별 반영월·예정일은 별도로 보존하고 카드 실적은 카드 조건에 따른 원거래 기준을 유지한다.

금액 수정·환불·취소는 원거래의 반영월을 보정하고 이후 이월을 다시 계산한다. 일반·고정 지출의 거래일·예정일을 직접 변경해 다른 월로 옮기는 경우에는 새 날짜의 월에 반영하고 이전·새 월의 영향을 보여준다. 기존 할부 회차의 금액을 수정하거나 원승인일을 확인할 때는 저장된 회차 반영월을 유지한다. 수입·지출을 합산하는 월별·연간 현황은 수입의 선택한 예산 반영월과 지출의 자동 산정 반영월을 기준으로 집계한다.

### 고정지출과 할부

- 매월 반복되는 고정지출(예정일·기본 예정 금액·결제수단·분류·시작월·활성/중지)은 가계부 설정의 `고정 수입 · 지출`에서 등록·관리한다. 아직 생성되지 않은 미래 예정월(현재 월 기준 최대 2개월 후까지)로 이동할 때는 사용자 확인을 거쳐 생성하며, 생성 시 활성 항목을 기준으로 예정 거래가 1회 자동 생성되어 생활비와 카드 실적에 선반영한다. 정렬을 위해 결제일을 1일로 바꾸지 않는다.
- 고정지출 설정과 이미 생성된 월의 지출 내역은 완전히 분리한다. `지출 내역`이나 `카드 파일 가져오기`에서 특정 월의 예정 거래 금액·결제수단을 보정하거나 삭제해도 해당 월 거래만 바뀌며 가계부 설정의 고정지출이나 다른 달 내역은 바뀌지 않는다. 반대로 가계부 설정에서 고정지출을 수정·일시중지·삭제해도 이미 생성된 월의 지출 내역은 변경·삭제하지 않고 앞으로 새로 생성되는 신규 월부터만 반영한다. (신규 고정지출을 최초 추가할 때만 `현재 월 이후 지출 내역에도 지금 바로 추가` 선택 옵션을 제공해 이미 생성된 현재 월 및 이후 예정월에 즉시 추가할 수 있다. 이미 생성한 미래 예정월을 최신 고정 설정으로 다시 만들고 싶다면 해당 예정월 상단의 `예정월 초기화`로 미완료 고정 항목만 비운 뒤 재생성할 수 있다.)
- 이미 생성된 월의 예정 금액이 실제 청구 금액과 다르면 `지출 내역`이나 `카드 파일 가져오기`에서 기존 예정 거래를 보정하고, 이미 준비했다면 차액 조정과 연결한다. 매 건 결제 확인 버튼을 필수 업무로 추가하지 않는다.
- 지출 기록에서 전체 승인금액 다음에 일시불·할부를 선택한다. 할부는 할부 유형(무이자·유이자·부분 무이자), 전체 개월 수, 이번 회차 번호를 입력하고 할인 후 승인금액을 나눈 이자 미포함 예상 회차 납부액을 확인·수정한다. 할부는 원거래를 중심으로 이번 회차부터 마지막 회차까지의 월별 예정 회차를 연결해 생성한다. 60만 원 3개월 할부의 생활비·준비액은 월 20만 원씩이다.
- 이후 회차 금액은 이자와 카드사 청구 방식에 따라 달라질 수 있으므로 승인금액을 개월 수로 나눈 값을 확정 청구액으로 간주하지 않는다. `할부거래 관리`에서 진행 중·완료·취소된 할부를 원거래 단위로 묶어 남은 청구 예정 합계, 향후 월별 청구 예정표, 미지불 회차별 실제 청구액(이자·수수료) 보정을 제공한다.
- `할부거래 관리`에서는 아직 지불하지 않은(`준비 필요`) 남은 회차들을 한 건의 정산 거래로 합치는 조기 완납(일시불 선결제)과 미도래 회차를 정리하는 할부 취소를 지원한다. 이미 첫 달 승인월에 전체 원금이 카드 실적으로 반영된 경우 조기 완납 거래는 카드 실적을 중복 합산하지 않는다.

### 한 결제의 분류별 분할과 할인

한 결제를 여러 분류로 나누더라도 원결제 한 건을 유지한다. 준비금·실적·파일 대조는 원거래 기준이고 생활비 통계는 분류별 금액 기준이다. 분할 합계는 원결제와 일치해야 한다.

기본 분류 하나에서 시작해 항목을 추가·삭제하며 여러 분류와 금액을 입력한다. 한 항목만 남으면 단일 분류로 처리하며 전체 금액과 할인 금액을 표시한다. 별도 기록하는 할인은 카드사 할인이다. 상품 자체 할인은 결제금액에 이미 반영된 것으로 취급한다. 사용자가 분류별 할인 금액을 직접 입력하거나 자동 배분 버튼을 눌러 분류별 금액 비율로 배분할 수 있다. 자동 배분은 버튼을 누를 때만 수행하며 입력된 값은 이후 변경 시 임의로 덮어쓰지 않는다. 추가된 모든 항목에서 분류와 금액을 입력해야 하며, 분류별 금액 합계는 결제금액과 같아야 한다. 분류별 할인 합계는 전체 카드사 할인과 같고 각 할인액은 해당 분류 금액 이내여야 한다. 조건이 맞지 않으면 저장을 막고 수정할 내용을 안내한다.

| 분류      | 할인 전   | 카드사 할인 | 생활비 반영액 |
| --------- | --------- | ----------- | ------------- |
| 식품/외식 | 80,000원  | 4,000원     | 76,000원      |
| 생활/동물 | 20,000원  | 1,000원     | 19,000원      |
| 합계      | 100,000원 | 5,000원     | 95,000원      |

잔여액 배분 순서·분할 후 부분 취소·할부·정산 조합은 상세 계산 설계에서 정한다. 모든 최종 등록 거래는 분류를 반드시 선택하며 분할된 항목도 각각 선택한다.

### 화면 구성

사이드바의 `결산`에서 `월별`, `연간` 탭을 전환하며, `자산 현황`은 별도 메뉴로 제공한다. 연간 결산은 수입 예산 반영월과 지출 반영월을 기준으로 집계한다. 집계 대상은 전체 또는 여러 구성원을 선택하며, 수입·공제는 수입 귀속자, 지출은 결제수단 소유자 기준이다. 전체에는 소유자 확인 필요와 탈퇴 구성원의 기록도 포함한다.

연간 요약은 선택한 대상의 `연간 수입 총액`, `연간 지출 총액`, `연간 잔액`을 표시한다. 수입 총액은 실수령액이며 등록된 입금 완료·예정 수입을 포함한다. 연간 잔액은 해당 연도 1월부터 기준월까지의 선택 수입 실수령액에서 선택 지출을 뺀 값으로 전년도 이월을 포함하지 않는다. 현재 연도는 이번 달, 지난 연도는 12월까지 집계하고 미래 연도는 기준월이 없다. 등록된 예정도 반영하며 은행 잔액이나 월별 결산의 남은 생활비와 구분한다. 수입과 지출 기록이 모두 없으면 0원이 아닌 미기록으로 표시한다. 가계부 전체의 월별 생활비 수입과 저장된 분류 예산을 비교해 예산 미배정 금액을 월별로 안내하며, 예산 자료를 확인할 수 없는 달은 별도 표시한다. 실수령액 중 생활비에 반영하지 않은 수입은 월별 미배정 금액과 분리해 안내한다.

`월별 수입 · 지출` 그래프는 실수령 수입과 생활비 지출을 비교한다. `분류별 지출 / 예산(이월 제외)` 표는 모든 화면에서 분류별 1~12월과 연간 합계를 교차 표시하고 생활비 지출과 저장된 가계부 예산을 `지출 / 예산` 순서로 보여준다. 모바일에서는 지출과 예산을 두 줄로 표시해 열 너비를 줄인다. 분류 열을 고정하고 표 내부에서 좌우로 이동한다. 표 아래 접힌 그래프에서는 분류를 여러 개 선택하며 기본값은 전체다. 선택 분류의 가계부 전체 지출은 누적 막대, 같은 분류의 예산 합계는 선으로 표시한다. 구성원을 일부 선택하면 선택 구성원 지출 합계선을 추가한다. 표의 분류를 누르면 해당 분류만 선택하고 그래프를 연다. 선택 분류가 없으면 그래프 대신 선택을 요청한다. 마우스, 터치, 키보드로 선택한 월의 선택 분류별 금액을 확인한다.

수입·공제 영역은 연간 합계와 1~12월의 실수령액을 기본 표시한다. 연간 합계를 펼치면 입력한 지급·공제 합계와 항목별 연간 합계를, 각 월을 펼치면 해당 월의 합계와 수입별 항목을 확인한다. 입금 완료와 예정은 같은 월에 합산한다. 공제 상세가 없으면 공제 없음으로 단정하지 않으며 입력된 장부 금액을 세무상 확정 금액으로 제시하지 않는다.

차트와 표에는 등록된 예정 거래를 포함하되 미생성 월, 생성된 월의 기록 없음, 실제 기록된 0원을 구분한다. 미생성 월에 이미 등록된 거래가 있으면 포함하며 조회 때문에 월을 생성하거나 미등록 예산·내역을 추정하지 않는다. 월 예산은 이월을 제외한 저장 배정액이며 0원·음수도 그대로 표시한다. 그래프는 선택 분류의 예산이 일부라도 없으면 그 달의 예산선을 끊는다. 연간 예산은 저장된 예산과 자료가 있는 개월 수를, 연간 지출은 연중 기록을 표시하고 범위가 다른 두 합계의 차액·소진율을 잔액이나 성과로 표시하지 않는다. 가계부 예산을 구성원별로 임의 배분하지 않는다. 카드 실적은 월별 현황에서 확인하며 귀속연도별 세무 통계는 후속 범위다.

월별 현황에서 남은 생활비·분류별 예산·카드별 이용 실적(예정 거래 포함)과 단계별 부족액·결제 준비 필요액·미회수 금액·잔액 차이를 확인한다. 상대별 미회수 금액은 선택한 예산 반영월 거래 중 현재 미입금 금액을 보여주며, 자산현황에서는 전체 기간의 상대별 미입금 잔액을 보여준다. 해당 가계부에 기록된 지출을 집계한다. 카드·계좌의 등록과 수정·사용 중지는 가계부 설정의 자산·카드에서 관리하고, 카드 실적은 월별 현황에서 확인하며 해당 조건으로 바로 이동한다. 자산 사용 중지는 해당 자산의 수정 화면에서 진행한다. 잔액 또는 보유량이 남아 있거나 카드 결제계좌, 고정 지출의 결제계좌, 고정 수입의 입금계좌로 연결된 자산은 사용 중지할 수 없다. 연결된 설정을 변경하거나 해제하고 잔액을 정리한 뒤 다시 시도한다. 사용 중지 시 기존 거래·잔액·예정 지출·준비금과 연결 관계를 보존하고 관련 영향을 확인한다.

지출 내역은 `일반 지출`, `고정 지출`, `할부 지출` 테이블을 분리해 건수·합계를 각각 보여주고 `내역 검색` 및 `분류`·`결제 수단`·`실사용자`·`지불 상태` 다중 필터(`전체` 포함, 모바일은 `상세 검색` 시트)를 제공하며, 상단에서 카드 내역 가져오기·지불 관리(`준비 필요` 건수)·할부 관리·회수금 관리(`미회수` 금액)로 이동한다(거래일은 `MM.DD` 형식, 표 열 너비 `table-fixed` 정렬). 지불 관리·할부거래 관리·회수금 관리에서도 지출 내역과 동일한 월 선택 상태를 공유한다(지출 내역에서 회수금 관리로 진입하면 선택 월 기준, 현황·자산에서 진입하면 전체 기간 기준). 할부는 할부 지출 테이블의 사용처 옆 회차 배지(`N/M회차`)뿐 아니라 `할부거래 관리` 화면에서 원거래별 진행 현황·남은 원금과 회차·향후 월별 청구 예정표·회차 금액 보정·조기 완납·할부 취소를 통합 관리한다. 반복 고정지출과 고정수입은 가계부 설정의 `고정 수입 · 지출`에서 관리한다. 지불 관리에서는 상단에서 `자산 현황 보기`로 바로 이동할 수 있고, `내역 검색`, `기간`(`전체` / `이번 달만` / `이전 달만` — `지불 완료` 탭은 선택 월만 조회하므로 미노출), `결제 계좌`·`결제 수단` 다중 필터(`전체` 포함)로 준비 필요·지불 대기·지불 완료 거래를 나누어 보며(표 맨 앞에 `거래일(MM.DD)` 열 분리) 선택한 거래의 지불 상태를 일괄 변경한다. 준비 필요 화면에서 계좌·현금별 `거래 합계`, `조정 금액`과 `채울 금액`을 함께 표시하고 제목 옆 `?` 팝오버로 기준을 안내한다. 거래를 선택하기 전에는 표시 중인 준비 필요 거래 전체를 기준으로 보여주고, 선택 후에는 선택 거래 기준으로 계산한다. 지불 대기로 변경할 때 준비금 조정은 해당 계좌·현금에만 반영한다. 계좌가 다르면 채울 금액을 이체하고, 같으면 이체 없이 확보한다. 모든 지불 상태 전환에서는 기본값으로 지불 상태만 변경하며, 사용자가 계좌 잔액 반영을 선택한 경우에만 출금·입금·반환 계좌의 보유금에 반영한다. 계좌·현금의 입금·준비 오차 보정은 조정 금액 수정으로 관리한다. 외부 은행 송금은 자동 실행하지 않는다. 가져오기 후 기존 월·검색 조건으로 돌아온다.

### 카드 청구대금 출금

실제 카드대금이 전액 출금된 거래는 사용자가 지불 완료로 변경한다. 결제일이 지났다는 이유만으로 출금을 확정하지 않으며, 출금은 새 지출로 중복 집계하지 않는다. 부분 출금 금액과 미납 잔액을 기록하는 기능은 MVP에서 제공하지 않는다. 일부만 출금됐다면 전액 지불 완료로 표시하지 않으며, 이 기간의 실제 잔액과 장부상 잔액에는 차이가 생길 수 있다.

### 실사용자·정산

결제수단의 소유자는 카드·계좌에 등록하고 거래에서 참조한다. 지출을 새로 기록할 때 실사용자는 선택한 결제수단 소유자를 기본값으로 한다. 결제수단을 변경할 때마다 이전에 실사용자를 직접 선택했더라도 새 결제수단의 소유자로 자동 변경하고, 이후 사용자가 다시 선택할 수 있다. 기존 거래를 열기만 한 경우 저장된 실사용자를 유지하며 회수 상대·회수 금액은 자동 변경하지 않는다. 구성원은 본인을 포함해 등록된 이름으로 표시한다. 실사용자는 별도 목록으로 관리한다. 가계부 구성원은 기본 포함하고 가입하지 않은 가족·친구는 미참여 인물로 추가할 수 있다. 미참여 인물 등록으로 참여 권한을 주거나 실사용자 변경만으로 정산을 만들지 않는다. 미참여로 등록해두었던 인물이 추후 구성원으로 초대·가입할 때의 데이터 동기화(연결·통합)를 지원한다. 초대 시 또는 가계부 설정의 미참여 목록에서 기존 미참여 인물과 신규 구성원을 연결하면, 과거 지출의 실사용자 기록 및 회수(정산 채권) 상대방 정보가 해당 구성원 계정으로 일괄 승계·통합되어 장부 단절을 방지한다.

지출 기록의 `회수 금액` 섹션에서 상대와 회수 대상 금액을 추가·수정·제외한다. 회수 대상이 없으면 상대를 추가하지 않는다. 처음에는 전액을 제안하고, 상대별 받은 내역·미회수 금액과 새 입금을 함께 관리한다. 회수한 금액은 상대별 누적액으로 입력하며 기존 기록보다 늘어난 금액을 새 입금으로 기록한다. 기존 기록보다 줄이려면 입금 내역을 먼저 정정한다. 새 입금을 기록할 때 상대별 입금계좌를 선택하며 입금일은 입력하지 않는다. 실사용자와 회수 상대는 별개다. 전체 카드 결제액을 준비하되 내 부담액만 생활비 지출로 잡는다.

회수 대상 금액을 줄이거나 미입금 상대를 제외하면 원지출의 예산 반영월에 내 부담이 늘어나고 이후 이월을 재계산한다. 거래 취소·환불·감액 시에도 회수한 금액보다 회수 대상 금액을 줄이거나 입금 내역이 있는 상대를 임의로 제거하는 저장은 차단한다. 별도 반환 부채를 만들지 않으며 기존 입금 내역부터 사용자가 정정한 뒤 수정을 진행한다. 카드 준비금과 실제잔액은 자동 변경하지 않으며 입금을 일반 수입으로 중복 기록하지 않는다. 회수 금액 섹션의 변경은 지출 저장 시 함께 확정하며 지출 취소 시 원본을 유지한다.

회수 상대가 가계부 구성원이면 그 상대의 송금계좌를 선택한다. 등록된 계좌가 아니면 `가계부에 등록되지 않은 계좌`를 선택할 수 있다. 등록된 계좌를 선택하면 해당 계좌에서 입금계좌로 이동하는 연결 관계를 기록하고, 외부 계좌를 선택하면 가계부 밖에서 들어오는 정산으로 기록한다. 실제 잔액은 사용자가 직접 갱신한다.

예정 반영 후 금액은 집계 범위에 따라 계산한다. 생활비 범위 밖에서 안으로 들어올 금액은 생활비의 예정 유입으로 표시한다. 출발·도착 계좌가 모두 전체 자산 범위에 있다면 양쪽 이동을 상계해 전체 자산을 늘리지 않는다.

지출 목록은 미회수 금액과 회수한 금액을 보여주며 원지출에서 관리한다. 회수금 관리 하위 화면에는 전체 기간의 미입금 거래를 모아 보여준다.

지출 내역의 회수금 관리 하위 화면은 거래별 회수 대기와 회수 완료 탭을 제공한다. 일부만 받았으면 미회수 금액이 있으므로 회수 대기에 남고, 회수 대상 금액을 모두 회수한 거래는 회수 완료에서 확인한다. 회수 완료 거래의 상세에서 상대별 회수한 금액과 회수 기록을 확인·정정할 수 있다. 회수 대기에서 거래를 선택해 `회수 완료`로 기록한다. 회수한 금액은 유지하며 선택한 거래의 미회수 금액만 처리한다. 상대별로 입금계좌 하나를 선택하고 같은 상대의 선택 거래에 적용한다. 일부만 받았다면 해당 거래의 지출 상세로 이동해 금액을 직접 입력하고, 저장하거나 취소하면 회수금 관리 목록으로 돌아온다. 받을 돈을 미리 등록하지 않았더라도 입금 후 지출 상세에서 회수 대상 금액과 회수한 금액을 함께 기록할 수 있다. 입금 기록은 미정산액을 줄이며 일반 수입으로 중복 기록하거나 실제 보유금을 자동 갱신하지 않는다. 거래·사람별 배분을 확인하고 잔액 갱신은 사용자가 선택한다. 상대방이 먼저 결제했다면 사용자가 실제 송금한 뒤 지출로 기록한다.

귀속자·지급처·입금 계좌·실제 입금일 또는 예정일·예산 반영월을 기록한다. 수입 기본 정보의 `귀속연도`는 확인한 자료를 바탕으로 선택 입력하며, 근로소득의 명세서 귀속 연월 또는 다른 수입의 소득 귀속 기간도 별도로 선택 입력한다. 모르면 비워 두며 입금일·예산월·귀속 연월·기간으로 귀속연도를 자동 확정하지 않는다. 고정수입 설정에는 귀속연도를 고정하지 않고 자동 생성된 수입마다 확인해 입력한다. 기존 기록은 미입력으로 유지하고 사용자가 수정할 수 있으며 입금 완료 처리와 수입 종류 변경 시 입력값을 보존한다. 지급처와 종류별 추가 정보도 선택 입력이다. 수입 목록은 예산 반영월, 지출 목록은 자동 산정된 반영월을 기준으로 지난 달과 예정된 달을 조회한다.

수입과 고정수입은 종류별 기본 항목을 가진 지급·공제 목록 하나로 기록한다. 별도의 입력 방식 선택이나 실수령액 직접 입력 필드는 두지 않는다. 각 목록의 항목명·금액을 수정하고 행을 추가·제거할 수 있다. 지급 한 건만 남기고 공제 항목을 모두 제거해도 기록할 수 있으며, 지급 합계에서 공제 합계를 뺀 실수령액을 읽기 전용으로 강조한다. 지급 항목은 한 개 이상 있어야 하고 공제 항목이 없으면 공제 없음으로 계산한다. 남아 있는 행의 미입력 금액은 0원으로 간주하지 않는다. 차감이 없는 행은 제거하거나 0원을 입력할 수 있고 빈 공제액을 0원으로 채우는 명시적 동작도 제공한다. 기본 금액·세율·보험료를 임의로 추정하지 않는다.

실수령액만 아는 경우에도 일반 지급 항목 하나에 금액을 입력하고 불필요한 공제를 제거해 기록한다. 별도 실수령액 추가 버튼·전용 항목·금액 기준 구분·혼용 제한은 두지 않는다. 지급·공제 합계는 사용자가 입력한 장부 값이며 세무상 확인된 세전 소득·과세표준·원천징수 확정액으로 자동 취급하지 않는다. 공제 행이 없다는 사실도 법적으로 세금이 없음을 확인한 것으로 간주하지 않는다. 추후 세무 기능에서 확인 자료와 대조하며, 현재는 항목명·금액·지급/공제 구분·사용자 과세 구분 입력을 보존한다. 종류별 고유 정보는 금액 목록과 구분한다.

근로소득의 상세 입력에서는 기본급·수당 등의 지급과 세금·보험료 등의 공제를 분리한다. 과세 구분이 필요한 근로·사업·이자·배당·연금·기타·퇴직소득은 지급 행에서만 지급 명세에 따라 과세·비과세·확인 필요를 선택하며, 미확인이어도 기록할 수 있다. 기본 항목을 제공하되 사용자가 추가·수정·삭제할 수 있으며 지급 항목에만 `과세`·`비과세`·`확인 필요`를 기록한다. 기본 항목과 저장된 항목 구성을 구분하고 거래·고정수입별로 이름·금액·지급/차감 구분을 보존한다. 구성 변경이 과거 기록이나 다른 달 기록을 바꾸지 않는다. 사업소득은 매출·지급 총액과 부가세 정보, 이자소득은 이자 지급액과 원천징수, 배당소득은 배당·분배금과 국내외 원천징수·수수료, 연금소득은 연금 구분·수령 방식과 연금 지급액·실제 공제액을 표시한다. 기타소득은 지급 사유·필요경비와 지급액·원천징수, 퇴직소득은 퇴직급여·퇴직소득세·근속기간·연금계좌 이체, 자산 처분은 처분대금·실제 차감액·취득가액·비용·손익을 구분한다. 그 밖의 입금과 종류 확인 필요에는 소득세를 기본 항목으로 강제하지 않는다. 종류별 고유 정보는 금액 영역에서 바로 확인한다. 별도의 공통 세무 정보 섹션이나 소득 분류·국내외 구분을 다시 고르는 입력은 두지 않는다. 실제 국내외 원천징수·보험료는 공제 행에 기록하고 확인 근거는 메모에 남길 수 있다. 자산 처분·그 밖의 입금·종류 확인 필요에는 과세 구분을 일괄 요구하지 않는다. 실제 입금액·사업 매출은 과세소득금액과 다르며 사업 손익·필요경비 자동 산출은 범위에 포함하지 않는다.

자산 처분은 실수령한 처분대금과 생활비 예산에 반영할 금액을 구분한다. 예산 반영액은 기본 0원이며 사용자가 직접 배정한다. 처분대금 전액을 수익이나 양도소득으로 확정하지 않으며 미확인 취득가액으로 손익을 만들지 않는다. 연간 결산은 예산 반영액 기준의 생활비 수입과 실수령액을 구분하고, 세무 상세는 입력된 값만 집계한다. 예산 반영월 기준의 집계를 신고용 소득 합계로 제시하지 않는다.

본인 계좌 이체·대출 실행·대여 원금 회수·보증금 반환·지출금 회수는 일반 수입과 구분해 관련 자산·부채·내부 이동·원지출에 연결한다. 이자만 회수한 대여금 이자소득으로 기록하고 원금은 중복 수입으로 잡지 않는다. 연금계좌로 직접 옮긴 퇴직급여도 생활비 계좌 입금으로 간주하지 않는다. 종류별 정보와 금액은 기존 금융 상세 암호화 정책을 적용하며 자동 세액 계산·연말정산·종합소득세 신고는 후속 범위다.

예상 수입은 수입예정금으로, 이미 받은 수입은 실제 보유금으로 구분한다. 매월 반복되는 직장인 급여 등의 고정수입은 가계부 설정의 `고정 수입 · 지출`에서 등록·관리(수입 종류와 선택적인 지급·차감 상세 포함)하며, 미생성 미래 월을 사용자 확인 후 생성할 때 해당 월의 수입예정금으로 1회 자동 선반영되어 월 예산과 비교된다. 전월 급여를 금월 예산에 배정할 수도 있으며 이미 입금된 돈을 예정 수입에 다시 넣지 않는다. 고정수입 설정 역시 이미 생성된 월의 수입 내역과 완전히 분리되어 가계부 설정에서 내용을 수정·일시중지·삭제해도 기존 생성 월의 수입은 바뀌지 않으며, `수입 내역`에서 특정 월의 금액·명세를 고쳐도 해당 월 건만 변경된다. (신규 고정수입을 최초 추가할 때만 `현재 월 이후 수입 내역에도 지금 바로 추가` 선택 옵션을 제공해 이미 생성된 현재 월 및 이후 예정월에 즉시 추가할 수 있으며, 이미 생성한 미래 예정월은 할부·직접 입력·완료 내역을 보존한 채 미완료 고정 항목만 초기화해 재생성할 수 있다.) 별도 통장 운용이나 전용 자금 잠금 설정을 강제하지 않는다.

예정 수입은 같은 기록에서 실제 입금일·실수령액을 확인해 입금 처리한다. 새로운 수입으로 복제하지 않으며 입금계좌·종류별 금액 상세·귀속월·예산월을 보존한다. 실제잔액은 자동 가산하지 않고 관련 계좌의 최종 수정 시각과 선택적 갱신 경로를 제공한다.

개인자금·용돈으로 빼는 돈은 가계부 지출로 처리한다. 이후 개인 사용을 별도 가계부로 기록할지 여부는 사용자에게 맡기며 자동 연동하지 않는다. 생활비 결제수단으로 개인자금을 사용해 돌려받을 돈이 있다면 회수 상대를 나로 기록하고, 개인자금 계좌에서 반환하면 회수한 금액을 기록한다. 반환은 새 소득과 구분한다.

### 연속성

분류별 이월·음수 잔액, 카드 전월실적·넘어온 납부액, 미래 고정지출·할부·미정산·조정을 월·연도 경계 없이 이어간다. 파일 복사·전년도 수동 이관은 요구하지 않는다.

## 6. 가계부와 구성원

가계부는 기록과 통계의 관리 단위다. 참여한 구성원은 해당 가계부의 수입·지출·자산·정산과 과거 기록을 함께 조회한다. 각 가계부의 데이터는 별도로 관리하며 다른 가계부와 자동으로 합산하거나 공유하지 않는다.

개인 기록을 별도로 관리하려면 개인 가계부를 만든다. 역할은 가계부 설정·구성원 관리와 삭제·소유권 이전 등 수행 권한을 구분한다. 탈퇴 후 접근은 종료하며 기존 기록은 보존한다. 가계부에 참여하지 않은 사람의 접근은 차단한다.

## 7. 카드 정보와 AI 파일 가져오기

### 카드 정보 등록과 조건

사용자는 공용 카드에서 상품을 선택한다. 없는 카드는 AI가 공식 자료를 찾아 정리하고 사용자가 상품명·발급사·버전·링크 등으로 본인이 등록하려는 카드와 일치하는지 먼저 확인한다. 확인한 카드는 개인용으로 즉시 사용하고 AI가 찾은 조건으로 실적을 처리할 수 있다.

카드 등록은 상품 선택, 실적·혜택 조건 확인, 내 카드 설정 순서로 진행한다. 체크·신용카드 모두 카드번호 마지막 4자리를 필수 입력하며 숫자 4자리로 검증하고 앞자리 0을 보존한다. 전체 카드번호·유효기간·CVC는 입력받거나 저장하지 않는다. 카드 목록에 표시명과 마지막 4자리를 함께 표시하고 수정할 수 있다. 마지막 4자리는 고유 식별자가 아니며 거래는 별도 내부 카드 ID로 연결한다. 실적 제외 조건은 관리비·공과금 등 세부 항목을 체크해 확인하며 목록에 없는 항목은 직접 추가한다. 체크카드는 출금계좌와 필요한 후불교통 정보를, 신용카드는 결제계좌와 결제일을 설정한다. 결제일별 카드사 청구기간은 별도로 관리하며 결제일만으로 청구기간을 확정하지 않는다.

공용 카드 조건은 운영자가 검수한다. AI가 찾지 못했거나 애매한 조건은 확정값으로 만들지 않고 검수 대상으로 표시한다. 출처·확인일·버전을 유지하고, 개인 설정이 공용 조건과 다르면 개인용 카드로 따로 저장한다. 개인 설정을 공용 카드 조건으로 자동 등록하거나 덮어쓰지 않는다.

실적 계산은 프로그램이 한다. 예정 고정지출, 카드별 할부 인정 방식, 세금 등 제외 항목, 할인 거래 전체 제외·할인액 제외·전액 인정 조건을 구분한다. 예정 포함 실적과 단계별 부족액을 보여주고 사용자가 사용할 카드를 판단한다. 현재 사용자 카드의 기간은 1일~말일이며 모든 상품에 같은 조건을 가정하지 않는다.

### 파일 가져오기와 대조

1. 대상 카드와 이용내역 또는 결제예정·청구내역 파일을 선택한다.
2. 프로그램이 파일을 읽고 AI가 구조·열 의미·거래 범위·취소·할부 표현을 해석한다. 수식·매크로·AI 생성 코드는 실행하지 않는다.
3. 프로그램이 원본 값으로 변환하고 날짜·금액·부호·통화·합계·누락·중복 후보를 검증한다.
4. 신규 거래와 기존 예정·할부 연결 후보, 취소·청구액 보정 후보를 보여준다.
5. 사용자가 연결·변경을 확인하고 모든 최종 등록 대상 거래의 분류를 선택한다.
6. 확정한 내용만 반영하고 원본 파일·임시 사본을 폐기한다. 필요한 출처 메타데이터는 유지한다.

이용내역 연결은 카드사와 마지막 4자리를 기준으로 후보를 제시하고, 자료에 있는 상품·소유자 정보를 보조로 활용한다. 번호가 없거나 마스킹으로 4자리를 확인할 수 없거나 후보가 여러 개면 사용자가 카드를 선택한다. 번호만으로 자동 확정하지 않으며 번호를 정정해도 기존 거래의 카드 연결을 바꾸지 않는다.

행별로 기존 연결·신규·이번 반영 제외를 선택한다. 실제 등록 대상은 모두 분류를 지정하며 제외 행은 보관함에 남기지 않는다. 선택한 묶음은 전체 반영 또는 미반영하고 동일 작업번호로 결과를 확인해 중복 반영을 막는다. 통신 오류만으로 실패를 단정하지 않는다.

같은 날짜·금액·가맹점이라는 이유만으로 자동 병합하지 않는다. 결제예정 파일에 없다는 이유로 미매입 거래를 취소·삭제하지 않는다. 상품별 구매 항목이 없는 카드 파일에서 AI가 분류별 금액을 사실처럼 만들어내지 않는다.

해외 결제는 승인액·원통화와 최종 원화 청구액을 구분한다. 환율·수수료·할부 회차로 금액이 달라지면 원거래를 보정하고 이미 준비한 차액은 다음 이체에 반영한다. 월을 넘긴 금액 보정도 원래 거래월에 반영하고 이후 이월을 다시 계산한다. 당월 새 지출로 중복 기록하지 않는다.

실제 지원 카드·확장자·크기·암호 파일 처리 등은 표본 검증으로 확정한다. 모든 카드 파일 지원을 보장하지 않는다.

과거 기록 이관 및 대량 거래 등록을 위해 표준 템플릿(CSV/Excel) 다운로드 및 일괄 업로드를 지원한다. 필수 항목(일자, 유형, 금액, 분류)과 선택 항목(결제수단, 사용처, 상세내역, 메모, 실사용자(지출 대상: 구성원·미참여))을 포함하며, 미등록 분류나 결제수단은 신규 생성 또는 기존 항목 매핑을 제공한다. 현재 월 이전 과거 거래는 준비 및 출금 완료 상태로 등록되어 현재 준비 필요액을 왜곡하지 않는다.

### 데이터 보호

- 원본 파일은 보관하지 않는다. 가져오기·사용자 확인 중만 일시 처리하고 성공·실패·취소·만료 시 임시 사본까지 폐기한다. 재대조 시 파일을 다시 선택한다.
- 원본·전체 셀 덤프를 DB·객체 저장소·백업·로그·오류 수집에 남기지 않는다. 확정 거래와 필요한 출처 메타데이터는 암호화 정책에 따라 저장한다.
- 모든 저장 금액과 금융 상세는 민감정보로 다루고 KMS 봉투 암호화·별도 세션 쿠키 기반 Redis 키 캐시를 사용한다. 서버 처리 중 평문이 존재할 수 있으며 운영자 단독 복호화 불가·서버 전체 장악 방어를 보장하지 않는다.
- 외부 AI에 필요한 정보만 전달하도록 설계하고 불필요한 인증정보·카드번호·계좌번호·이름은 제거하거나 가린다. 제공사·전송 범위·안내 및 동의·제공사 보관·삭제·비용은 도입 전 확정·검증한다.
- 파일 안의 지시문은 신뢰하지 않는다. 금융 원문·키·쿠키·토큰은 로그·분석·진단에 남기지 않고 테스트에는 합성 자료를 사용한다.

## 8. 자산현황과 데이터 최신성

자산 현황 메뉴에서 계좌·현금별 보유금과 예정 입출금을 모아 보여준다. 기존 시트의 현재보유금액·수입예정금액·지출예정금액·합계 구조를 서비스의 수입·정산·준비금 기록과 연결한다. 생활비 잔액 차이를 표시하는 기능만으로 자산현황을 대체하지 않는다.

### 기본 현황과 갱신

가계부 생성자와 참여하는 각 구성원에게 원화 현금 자산을 하나씩 기본 생성한다. 같은 가계부에서 구성원별 원화 현금 자산은 중복 생성하거나 삭제·사용 중지할 수 없다. 소유자는 현금 보유액을 직접 관리한다. 최초 보유액은 사용자가 확인하기 전까지 미입력 상태이며 0원으로 확정하지 않는다. 구성원이 탈퇴해도 기존 기록은 보존하고 접근 권한은 탈퇴 정책을 따른다.

- 소유자·자산 구분·상품유형·금융사·표시명·현재 보유금·최종 수정 시각을 관리한다. 결제수단의 계좌와 같은 자산을 참조해 중복 등록·합산하지 않는다.
- 자산 입력에서 자산 구분과 유형을 최상단에 묶어 보여주고 소유자는 입력 항목의 맨 아래에 배치한다. 외화·금은 같은 묶음에서 계좌 또는 실물 보유 형태를 선택한다. 자산 등록 후에는 소유자를 변경할 수 없다.
- 현재 보유금은 실제 잔액으로 입력한다. 자산현황에서는 금액만 변경하며 이름·유형 등 자산 속성은 가계부 설정에서 수정한다. 단순 잔액 갱신을 새로운 수입·지출로 생성하지 않는다.
- 자산을 저장할 때 서버가 최종 수정 시각을 자동 기록하고 화면에 표시한다. 사용자가 시각을 직접 입력하지 않는다. 이 시각은 항목의 마지막 저장 시각이며, 이름만 수정한 경우 실제 잔액을 새로 확인했다는 뜻은 아니다. 공통 시세의 기준 시각은 자산 수정 시각과 별도로 표시한다.
- 자산별 상세 목록의 각 항목에 실제 잔액·평가액, 예정 입금액, 예정 출금액, 예정 반영 후 잔액을 나누어 표시한다. 실제 잔액은 마지막으로 직접 확인한 금액이며, 부동산·투자 등의 평가액과 부채의 남은 원금도 직접 입력한 금액이다. 소유자별·전체 합계는 같은 가계부를 기준으로 집계한다.
- 수입·정산·준비금 내역에서 예정금액을 가져오며 동일 금액을 자산현황에 다시 입력하게 하지 않는다. 관련 기록과 계산 근거를 확인할 수 있게 한다.
- 내부 이체·준비 처리·입금 기록과 실제 잔액 갱신이 같은 돈을 이중 가감하지 않아야 한다.

```text
예정 반영 후 금액 = 현재 보유금액 + 수입예정금액 - 지출예정금액
```

전체 보유 자산, 예정 반영 후 금액, 남은 생활비는 별개다. 이미 결제 계좌에 확보한 준비금과 생활비 밖의 자금을 다시 쓸 생활비로 합산하지 않는다. 가계부 구성원은 해당 가계부의 자산과 보유금을 함께 조회한다.

### 생활비 외 자산·부채의 수동 현황

예·적금·투자상품·연금·부동산·대출 등 부채도 항목을 등록하고 금액을 수동 갱신해 유형별·소유자별 합계를 보는 범위까지 MVP에 포함한다. 입력한 자산 금액과 부채 잔액으로 총자산·총부채·순자산을 구분해 보여준다. 투자·부동산 금액은 사용자 입력값이며 수익률·이자·상환 자동 계산은 제외한다. 외화와 금의 참고 평가에는 공통 시세를 사용할 수 있다.

자산 등록 시 현금·수시입출금, 저축·투자, 대여금·임차 보증금, 부채 중 구분을 선택한다. 선택한 구분에 맞는 유형만 제공한다. 저축·투자의 유형은 예·적금, 주식·펀드 등 투자상품, 연금, 외화, 금, 부동산이다. 대여금·임차 보증금은 돌려받을 자산으로, 차입금·임대 보증금은 부채로 구분한다. 예·적금은 해당 자산 자체를 금융기관 계좌로 관리하고 금융사를 기록한다. 외화와 금은 계좌 또는 실물로 구분한다. 종목별 시세는 자동으로 관리하지 않으며 투자상품의 원화 평가액은 사용자가 입력한다. 현금 기본 자산은 현금·수시입출금에 두고 부채는 자산과 구분한다. 자산별 상세는 구성원별로 나누고 각 구분별 목록과 합계, 구성원별 자산·부채·순자산 및 전체 구성원 합계를 표시한다. 기존에 분류된 항목이 새로운 구분에 맞지 않으면 구분 확인이 필요한 상태로 보존하고 사용자가 다시 분류한다. 구분 변경은 기존 잔액이나 거래를 변경하지 않는다. 합계와 상세는 해당 가계부에 등록된 자산을 포함한다.

임차인이 맡긴 보증금은 돌려받을 자산으로, 임대인이 받은 보증금은 돌려줄 부채로 기록한다. 대여금은 빌려준 원금, 차입금은 빌린 원금의 남은 금액을 기록한다. 이자는 원금과 구분하며 실제 발생한 이자는 별도 수입·지출로 기록할 수 있다. 보증금·대여금·차입금의 상대방은 구성원·미참여 중 선택하거나 사람 또는 기관의 이름을 직접 입력한다. 상대방을 기록해도 상대의 자산·부채를 자동 생성하거나 연결하지 않는다. 부동산은 보증금을 뺀 금액이 아닌 사용자가 확인한 부동산 평가액을 입력하고, 보증금 부채를 별도로 차감해 이중 차감하지 않는다. 보증금의 단순 잔액 갱신은 수입·지출을 생성하지 않으며, 실제 지불·반환은 계좌·현금과 보증금 사이의 이동으로 기록한다.

생활비 반영 범위와 자산 보유 현황은 분리한다. 저축·투자 자산을 등록했다고 생활비가 늘어나거나 부채 원금 전체가 당월 생활비에서 빠지지 않는다. 단순 현황 수정만으로 수입·지출·상환 거래를 자동 생성하지 않는다. 자산 정보에도 금융 데이터 암호화 정책을 적용한다. 세부 기준은 [MVP 기능 명세서](./mvp-functional-spec.md)의 ASSET-03을 따른다.

### 외화·금 자산과 공통 시세

외화와 금은 각각 계좌 또는 실물 보유로 등록한다. 외화는 통화와 외화 잔액, 금은 보유량과 단위를 기록한다. 계좌인 경우 금융사를 기록하며 실물에는 금융사를 요구하지 않는다. 구성원에게 기본 생성되는 현금은 원화 현금이며 외화 현금은 통화별 별도 자산으로 등록한다. 금 ETF 등 상품 가격으로 평가해야 하는 자산에는 공통 금 시세를 그대로 적용하지 않는다.

서비스는 정한 제공처에서 통화별 환율과 기준 단위별 금 시세를 하루 한 번 조회해 공통 데이터로 저장한다. 적용 시세·출처·기준 시각과 조회 시각을 표시하고, 제공처·가격 기준·조회 시각·이용 조건은 구현 전에 정한다. 조회에 실패하면 마지막 성공 시세를 사용하되 실패와 해당 시세의 기준 시각을 표시한다. 유효한 시세가 없으면 평가액을 임의로 확정하지 않는다.

외화·금은 공통 시세 적용을 기본으로 하며 원화 참고 평가액은 보유량과 시세로 자동 계산해 읽기 전용으로 보여준다. 실제 평가액과 차이가 있을 경우 사용자가 직접 입력 방식으로 전환할 수 있다. 직접 입력한 평가액은 새 공통 시세로 덮어쓰지 않는다. 자동 참고 평가와 직접 입력의 출처·시점 및 적용 상태를 구분하고, 총자산에는 선택한 원화 평가액을 한 번만 합산한다. 보유량 변경이나 평가액 갱신만으로 수입·지출을 생성하지 않는다.

### 입력 방식과 기준 시점

은행 파일은 MVP에서 제외한다. 실제 잔액은 사용자가 입력하고 수입·준비 처리·정산도 기록한다. 계산상 잔액으로 은행의 실제 잔액을 자동 덮어쓰지 않는다.

화면에는 자산 최종 수정 시각과 거래 반영 기준을 구분하고 아직 예정인 지출·미입금액 및 조건 미확정 사유를 보여준다. 일부 카드·구성원 자료만 최신이라면 전체 숫자를 실시간 확정 잔액으로 설명하지 않는다. 표시 방식은 화면 설계에서 구체화한다.

정산 완료와 잔액 갱신이 같은 입금을 두 번 반영하지 않아야 한다. 잔액 차이가 0이어도 누락이 없다는 보장은 아니며, 고급 변경 이력 추적은 MVP에서 제외한다. 대조의 완료·미완료 상태나 차이에 따른 저장 제한도 두지 않는다.

### 처음 사용

1. 초대를 받고 카카오 로그인으로 가입·참여한다. (`login`)
2. 가계부와 시작월(과거월 지원), 추천 또는 직접 입력 분류, 기본 예산을 정한다. (`onboarding`)
3. 카드·계좌의 소유자와 결제 계좌를 정한다. 없는 카드라면 AI 탐색 후 상품을 확인한다. (`card-add`)
4. 현재 실제 잔액, 기존 납부·준비금·받을 돈, 시작월 거래와 고정지출·할부를 반영한다.
5. 역산된 첫 달 시작금액과 분류별 배분을 확인·수정한다. 차이가 있어도 저장할 수 있다.
6. 예정 포함 실적·단계별 부족액·생활비·추가 준비액을 확인한다. 공동 사용이면 구성원·권한을 설정한다. (`overview`, `settings`)

시작 설정에서 카드 등록·파일 대조로 이동해도 단계·입력 초안과 복귀 위치를 보존한다. 모든 상세 자료를 가입 단계에서 강제하지 않고 자료의 포함 범위를 표시한다. 미입력을 확인된 0원으로 취급하지 않는다.

### 반복 관리

1. 카드 파일을 가져오거나(`import`) 지출·수입을 직접 입력한다. (`expense-edit`, `income-edit`)
2. 예정·기존 거래와 대조하고 분류·금액·취소·할부 연결을 확인해 등록한다.
3. 필요한 거래만 분류를 나누고 실사용자·지출금 회수(상대방·금액)를 지정한다.
4. 결제 계좌별 지불 상태(`준비 필요`, `지불 대기`, `지불 완료`)를 확인하고, 필요한 거래를 다중 선택해 일괄 상태 변경한다. (`funds`)
5. 회수금 관리에서 회수 완료된 채권을 선택해 일괄 입금 처리하거나 상세에서 부분 정산한다. (`receivables`)
6. 실제 계좌 잔액을 갱신하고 생활비·카드 실적·잔액 차이를 대조한다. (`overview`, `assets`)

### 구성원 초대 및 실사용자 동기화

1. 가계부 설정의 `구성원 · 권한`에서 이메일과 역할을 지정해 신규 구성원을 초대한다. (초대 대기 상태 관리)
2. 아직 가입하지 않은 가족·지인은 `미참여` 인물로 수기 등록하여 지출 실사용자나 지출금 회수 상대방으로 지정한다.
3. 해당 대상자가 추후 가계부에 가입·참여하면, 가계부 설정의 `[구성원 계정과 연결]`을 통해 기존 미참여 인물의 과거 지출 기록과 미회수 채권을 신규 구성원 계정으로 일괄 승계·병합하고 중복 미참여 명칭을 정리한다.

화면 배치와 입력 순서는 [MVP 기능 명세서](./mvp-functional-spec.md)의 기능 기준으로 구체화하고 사용성을 검증한다.

## 10. 사업 가설과 경쟁 환경

### 포지셔닝과 초기 타깃

초기 타깃은 여러 카드와 예정 지출을 엑셀·노션 등으로 관리하며 통장 잔액과 남은 생활비를 따로 계산하는 사용자다. 1인 가구·신혼부부·맞벌이 등 가구 형태보다 같은 관리 문제의 유무를 기준으로 모집한다. 공동 사용자는 같은 가계부의 기록을 함께 관리하며 거래·자산의 비공개·부분 공개 옵션은 제공하지 않는다.

남은 생활비를 핵심 가치로 전달하고 예정 포함 카드 실적과 계좌별 추가 준비액을 보조 가치로 설명한다. 남은 생활비에는 예정 수입·미회수 금액 등이 반영될 수 있으므로 즉시 인출 가능한 현금이나 `통장 잔액 - 카드값`과 동일하다고 설명하지 않는다. 첫 현황은 남은 생활비의 우선 노출을 유지하고 자료의 포함 범위·최신성을 함께 안내한다.

결제 캡처·글 기반 입력 보조는 MVP에 포함한다. 지출 기록 상단에서 이미지 붙여넣기·파일 선택·끌어놓기 또는 사용자가 작성한 설명으로 거래 한 건의 초안을 만들고, 원문과 변경 전후를 확인한 뒤 기존 폼에 반영한다. 날짜·사용처·금액·카드 등 확인 가능한 값만 제안하며 모르는 분류·카드는 직접 확인한다. 기존 입력·분류별 할인 배분은 임의로 덮어쓰지 않고 사용자 확인을 거친다. 실제 거래·예산·실적 변경은 기존 검증을 통과해 지출 저장을 눌렀을 때만 일어난다. 후속 카드 파일과 중복 확인을 연결하고 원본·임시 이미지는 보관하지 않는다. 문자·알림 자동 수집은 제외한다.

가입 전 체험과 마케팅·유료화 검증 기준은 [서비스 포지셔닝·성장 검증 전략](./growth-strategy.md)을 따른다. 가입 전 체험은 후속 UX 실험이며 실제 제품 UI·검증된 계산을 공유하는 비로그인 합성 데모로 설계한다.

알파 기간에는 안내한 기능을 무료로 제공한다. 정식 출시의 무료·유료 범위는 별도 검증 후 전환 전에 안내하며 영구 무료로 약속하지 않는다. 기존 기록 보존·열람·내보내기와 향후 이용 조건을 구분하고 AI 월간 처리량·추가 가계부·시뮬레이션 및 비교 리포트를 유료 후보로 검증한다. 오래된 기록의 열람을 막는 장기 보관 과금은 우선 후보에 넣지 않는다.

### 검증할 사업 가설

- 기존 엑셀 사용자 중 카드 결제 준비금과 남은 생활비를 따로 계산하는 사람이 있다.
- 파일 업로드가 남아 있어도 계산·대조·공동관리 부담이 줄면 반복 사용한다.
- 사용자가 계산 결과를 신뢰하고 일정 금액을 지불할 이유가 생긴다.
- 반복 사용으로 분류 규칙·계좌 관계·공동 관리 습관·신뢰가 쌓이면 유지에 도움이 된다.

잠재 시장 규모·유료 전환율·매출 전망은 검증 대상이다.
거래 데이터의 누적만으로 강한 락인이 보장된다고 보지 않는다. 기존 서비스의 전환 비용도 있으므로 가져오기·내보내기의 편의와 신뢰를 함께 고려한다.

### 차별화 가설

> 국내 거래 파일과 예정 지출을 함께 반영해 남은 생활비·카드 실적·결제 준비금을 확인하고, 같은 기록을 함께 보며 이체·정산을 별도 엑셀 계산 없이 정리한다.

공동 가계부·카드 준비금·AI 입력의 존재만으로 독자적인 기능이라고 주장하지 않는다. 뱅크샐러드도 [공식 소개](https://go.banksalad.com/introduce_services/)에서 공동 가계부를 안내한다(확인일: 2026-11-15). 구체적인 공유·계산 범위와 실제 사용성은 별도로 비교한다.

AI 자체보다 파일 등록부터 계산·공유까지 연결되는 경험의 편익을 검증한다. 같은 흐름을 경쟁 제품이 얼마나 잘 제공하는지는 실제 사용 비교가 필요하다.

| 가계부별 기록 범위를 혼동한다                | 통계 누락·중복            | 기록 위치와 별도 가계부의 경계를 이해하는지     |
| 가져오기가 틀리면 수동 정리가 더 오래 걸린다 | 엑셀보다 불편해짐         | 원본 대비 오류·수정량과 최종 소요시간           |
| 기존 가계부로도 충분하다                     | 전환·유료화 이유가 없음   | 동일 실제 시나리오에서 기존 도구 대비 편익      |
| 사용자는 좋아하지만 돈은 내지 않는다         | 사업성 부족               | 실제 결제·유지 여부                             |

현재 판단은 '검증할 가치가 있는 MVP 후보'이며, 차별점이나 사업성이 충분히 입증된 상태가 아니다.

## 12. 알파 검증 계획

### 준비와 진행 순서

1. 기능 명세서의 계산·권한·가져오기 수용 기준과 복합 거래 사례를 구체화한다.
2. 가장 유사한 경쟁 제품 2~3개에 동일한 합성 시나리오를 적용해 차이를 기록한다.
3. 알파테스터의 참여 의사, 기기, 카드·은행, 파일 다운로드 가능 여부를 확인한다.
4. 비식별 파일 표본으로 AI 매핑과 원본 값 추출·검증의 가능성을 확인한다.
5. 준비금·예정 거래·정산·분할·할부의 복합 계산 사례와 기준일·가계부 접근 권한을 확정하고, 기본값·예외 입력의 화면을 검토한 뒤 개인 사용 흐름부터 구현한다.
6. 공동 사용의 구성원 권한과 가계부 경계를 확인하고 실제 사용 실험을 진행한다.
7. 두 번의 카드 결제주기 동안 반복 업로드·수정 부담·계산 신뢰·공동 참여를 관찰한다.
8. 무료 알파 이후 유료화 검증을 별도로 진행한다. 첫 알파에는 과금하지 않으며 가격·과금 단위는 후속 결정이다.

### 기록할 지표

- 유입 채널별 체험 시작·완료, 초대 신청·첫 가계부 설정, 반복 기록·다음 달 사용으로 이어지는 비율. 공개 가입 전에는 초대 신청과 실제 참여를 구분한다.
- 최초 파일 등록 성공률과 소요시간
- 업로드별 수정 거래 수, 금액·부호·취소·할부 해석 오류
- 중복 후보 오탐과 누락, 원본 대비 미등록 거래
- 금융기관·파일별 마지막 반영일과 자료 누락 범위
- 주기적인 재업로드와 두 구성원의 참여
- 별도 엑셀 계산이 계속 필요한지
- 남은 생활비·이체 필요액·예정 포함 카드 실적을 실제 의사결정에 사용하는지
- 카드 조건 설정, 거래 분할, 일괄 이체·조정·정산을 처리하는 시간과 수정 부담
- 예정 거래와 실제 거래의 중복 반영·잘못된 연결 여부
- 월·연도 전환에서 수동 재입력 없이 기록이 이어지는지
- 가격·과금 단위 제시 후 업그레이드 관심, 대기 신청, 실제 결제, 유료 유지 여부를 구분한다. 클릭·신청만으로 유료 전환을 입증하지 않는다.

알파 성공 기준의 참여자 수·반복 사용 비율·허용 입력 부담은 실험 설계에서 정한다. 금액·가계부 접근 권한 오류는 사용성 지표와 별도로 수정하고 재검증한다.

## 14. 후속 확장과 구현 전 설계

### 후속 확장

- 실제 제품 UI·계산을 공유하는 비로그인 합성 데모. MVP의 캡처·글 입력 보조는 필수 분류·금액 검증·사용자 저장 확정 원칙을 유지한다.
- 금융기관 자동 연동·은행 파일·PDF·일반 영수증·복수 이미지/거래 가져오기.
- 카드 약관의 상시 갱신·전체 혜택 최적화·추천 확대.
- 귀속연도별 세무 통계, 절세·연말정산 기능, 고급 잔액오차 추적.
- 네이티브 모바일 앱·일반 공개 가입·유료 요금제. 무료 알파 검증과 구분해 결정한다.

### 후속 세무 기능을 위한 데이터 요구

MVP에서 신고·세액 계산 화면을 만들지 않더라도 원결제·분할·승인·청구·할인·실부담을 구분한다. 결제수단 소유자·실사용자·부담·정산 관계, 실제 날짜·예산 반영월·급여 귀속 연월, 할부 회차·취소 관계를 보존한다. 수입 종류·사용자 정의 세부 항목·지급처·지급·공제 행의 금액·과세 구분과 실제 국내외 원천징수 내역, 사용자가 입력한 귀속연도·명세서 귀속월·소득 귀속 기간 및 메모를 보존한다. 실수령액·생활비 예산 반영액·자산 처분대금·원금·손익을 구분하고 미확인 값은 0원과 다르게 취급한다.

생활비 부담·카드 실적 인정·미래 세무 분류는 서로 다른 기준이다. 어느 한 항목으로 세법상 귀속을 단정하지 않는다. 세무 확장을 이유로 원본 파일·전체 셀 덤프·불필요한 개인정보를 보관하지 않는다. 실제 세무 기능 도입 시 해당 연도의 법령·귀속 기준을 별도 검증한다.

### 화면·데이터 일관성

거래·수입·자산을 수정할 때 저장된 원본 속성을 그대로 불러오고 바꾸지 않은 값을 보존한다. 신규 자산도 상세·잔액 갱신·속성 수정을 제공하며 결제계좌별 실제잔액을 분리한다. 준비·정산 후에는 관련 계좌와 확인시점, 선택적 갱신 링크를 보여주고 실제잔액 갱신을 강제하지 않는다. 늦게 입력한 기록만으로 잔액 오류를 단정하지 않는다.

남은 생활비를 대표 금액으로 두고 잔액 차이는 부호·기준시점·근거를 갖춘 보조 정보로 표시한다. 금액 표는 자릿수 비교가 가능하게 정렬하고 입력 오류·키보드 초점·저장 결과 확인 상태를 각 흐름에 포함한다.

### 주요 금융 정책 결정 사항

- 최초 시작금액(이월금): 첫 달 전월 이월금은 사용자 직접 입력/수정을 기본 지원하며, 보조 도구로 자동 역산 제공. 시작월 내 명시적 재역산 허용.
- 준비 완료 후 결제계좌 변경: 기존 계좌 유지(음수 조정), 계좌 간 직접 이관(새 계좌 즉시 준비 완료), 생활비 회수(조정금 0원 소진) 중 사용자 선택.
- 정산 완료액보다 미수금이 작은 수정: 거래 취소·감액으로 받을 돈이 회수한 금액보다 작아지는 수정은 차단하며, 기존 입금 내역 선 정정 원칙 적용.
- 분류 비활성화 및 잔여금 정산: 고정·할부 및 미래 월 등록 거래가 있을 시 비활성화를 차단하며, 당월 기존 기록은 보존하되 추가 입력을 불허함. 이월금/예산 잔여액(양수·음수)이 있을 때는 타 분류와의 월별 예산 상계(음수 예산 허용)를 통해 당월 잔여액을 0원으로 정산 후 비활성화. 전월 이월금과 총예산 합계 불변 유지.
- 미참여 인물 구성원 연결: 초대 시 또는 가계부 설정에서 기존 미참여 인물과 신규 가입 구성원을 연결할 수 있으며, 과거 모든 지출의 실사용자 기록 및 회수(정산 채권) 상대방 정보가 해당 구성원 계정으로 일괄 승계·통합되고 중복 미참여 명칭은 제거됨.
- 고정 수입·지출 설정과 월별 내역 분리: 고정 수입·지출 설정은 아직 생성되지 않은 신규 월이 사용자 확인을 거쳐 생성될 때만 예정 거래로 복사 생성되며, 설정의 수정·일시중지·삭제는 이미 생성된 월의 내역을 소급 변경·삭제하지 않음. 월별 수입·지출 내역의 수정·삭제 역시 해당 월 1건에만 반영되며 가계부 설정에 영향을 주지 않음. (신규 고정 수입·지출 최초 추가 시에만 현재 월 즉시 추가 선택을 제공하며, 이미 생성한 미래 예정월은 할부 회차·직접 입력·완료 내역을 보존한 채 미완료 고정 항목만 초기화해 재생성 가능.)

7. 관리자 지정·해제 범위, 소유권 이전 절차, 합계 노출 경계·삭제 및 백업 운영.
