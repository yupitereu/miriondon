## 1. 제품의 목적

Moneiet은 이미 쓴 돈과 앞으로 나갈 고정지출·할부를 미리 생활비에 반영하고, 어느 결제 계좌에 얼마를 더 준비해야 하는지 알려주는 가계부다. 예정 지출을 포함한 카드 실적과 목표까지 부족한 금액을 확인해 사용할 카드를 판단하도록 돕는다.

혼자 또는 가족·부부·연인 등 돈을 함께 관리하는 사람과 사용할 수 있다. 공동 관리에 참여해도 개인의 상세 지출을 모두 공개할 필요는 없다.

사용자가 내려받은 카드 이용내역과 결제예정·청구내역 파일을 가져오는 방식으로 시작한다. AI는 구조·열 의미를 해석하고 분류를 추천하며, 프로그램이 원본 값 추출·검증·금액 계산을 수행한다. 은행 잔액·수입·이체·정산은 사용자가 기록한다.

> 이미 쓴 돈과 앞으로 나갈 돈을 반영해 남은 생활비, 카드 결제 준비금과 예정 실적을 알려주는 가계부. 혼자서도, 필요한 정보만 공유하며 함께 쓸 수 있다.

## 2. 출발점과 해결할 문제

기획자는 스프레드시트로 예산·거래·카드 실적·준비금·받을 돈과 실제 잔액을 함께 관리한다. 통장 잔액에는 이미 쓴 카드값과 앞으로 나갈 돈이 남아 있어 그대로 생활비로 볼 수 없다.

고정지출을 실제 결제 전에 적어두는 것이 핵심이다. 월말 자동결제 예정액도 생활비와 카드 실적에 포함해야 지금 더 쓸 돈과 혜택 기준에 부족한 실적을 판단할 수 있다. 카드사 화면의 이미 발생한 사용분만으로는 이 목적을 충분히 해결하지 못한다.

| 확인한 불편                              | 개선 방향                                                   |
| ---------------------------------------- | ----------------------------------------------------------- |
| 연도마다 파일 복사와 전년도 값 이관      | 월·연도 경계 없는 거래·예산·실적·준비금 연결                |
| 거래마다 카드 조건에 따라 Y/N 반복 입력  | 카드 조건·기본 공개 등 기본값 자동 적용, 필요한 예외만 수정 |
| 이체한 거래 상태와 변경 차액을 수동 관리 | 선택·전체 거래 단위 준비 처리와 다음 이체 조정 연결         |
| 한 결제를 분류별로 여러 행에 기록        | 원결제 한 건 안의 분류 분할과 카드사 할인 비례 배분         |
| 잔액오차 원인을 찾기 어려움              | 실제 잔액과 계산 근거·차이를 제시, 고급 이력 추적은 후속    |

남은 생활비, 계좌별 추가 준비액, 예정 포함 카드 실적, 돌려받을 돈과 공개 범위를 함께 관리하는 흐름이 제품의 핵심이다. 이 문제의 중요도는 한 사용자의 실제 경험으로 깊이 확인했으며, 다른 사용자에게 같은 편익이 있는지는 알파에서 검증한다.

## 3. 첫 버전과 사용자·가계부

### 무료 초대 알파

- PC 웹만 지원하며 카카오 로그인만 제공한다.
- 초대받은 사용자만 가입한다. 기존 가계부 소유자·관리자도 신규 사용자를 초대할 수 있다.
- 회원가입·로그인과 여러 기기 동기화를 포함한다. 한 기기에만 기록을 저장하지 않는다.
- 첫 알파에는 구독료·결제 기능을 넣지 않는다. 공개 가입·유료화·모바일은 후속 범위다.

개인 가계부와 공동 가계부를 지원한다. 공동 사용을 가입 조건으로 두거나 개인 가계부 생성을 공동 사용의 필수 절차로 강제하지 않는다. 첫 검증 대상은 기획자와 주변 신혼부부를 중심으로 하되, 용어·데이터 구조를 부부 전용으로 고정하지 않는다. 공간·구성원 수 제한과 미성년자 정책은 별도 검토 대상이다.

### 역할과 기록 유지

- 생성자는 한 명의 소유자가 되며 관리자는 여러 명 지정할 수 있다.
- 상세 공유된 거래는 모든 구성원이 입력·수정할 수 있다.
- 가계부 설정은 소유자·관리자와 관리자가 설정 수정 권한을 부여한 구성원이 변경한다.
- 가계부 삭제·소유권 이전 같은 최상위 작업은 소유자만 수행한다. 소유권은 다른 구성원에게 이전할 수 있다.
- 소유자·관리자도 타인의 비공개 상세 거래를 볼 수 없다.
- 새 구성원은 과거 공유 기록도 볼 수 있다. 탈퇴자는 가계부 접근이 종료되지만 기존 공동 기록·합계는 유지한다. 비공개 거래를 새로 공개하지 않는다.
- 삭제한 가계부는 30일 이내 서비스 운영자에게 문의해 복구를 요청한다. 사용자용 직접 복구 기능은 두지 않는다. 운영자는 소유 권한을 확인하고 복구한다.

초대 만료·소유권 이전 수락·관리자 지정 및 해제·삭제 후 백업 정리 같은 세부 절차는 기능 명세서의 구현 전 설계 항목으로 관리한다.

### MVP에서 제외

- 금융기관 자동 연동, 은행 거래 파일 가져오기, 문자·푸시 상시 수집.
- 실제 자동 송금·결제, 한 거래 금액 일부만 준비 처리하는 기능.
- PDF·이미지·영수증 인식. 지원 카드 파일 형식은 실제 표본 검증 후 확정.
- 입금 자동 정산, 사람별 자동 정산 규칙, 상대방이 먼저 결제했을 때 별도 보낼 돈 관리.
- 개인자금 지급 이후 개인 지출 관리 강제·자동 연동.
- 개별 거래 없이 가족 카드 사용 합계만 따로 관리하는 방식.
- 마지막 잔액 일치 이후의 변경을 모아 원인을 찾는 고급 추적.
- 공제 판정·세액 계산·절세 추천·연말정산 화면. 데이터 확장 요구는 유지.
- 모든 카드 약관의 상시 자동 갱신과 혜택 금액 전체의 최적화·자동 카드 추천.
- 모바일, 공개 가입, 구독·결제, 시세·수익률·대출 이자·상환 일정 등 전문 자산관리 자동 계산. 생활비 외 자산·부채의 등록·수동 금액 갱신·합계 조회는 MVP에 포함한다.

## 5. 핵심 기능과 계산 원칙

### 생활비·실제 잔액·시작금액

분류별 남은 생활비는 월별 예산에 전월 이월금을 더하고 해당 월 생활비 반영 지출을 뺀 금액이다. 초과 지출의 음수도 다음 달로 이월한다.

실제 보유금은 은행의 실제 잔액을 사용자가 입력한다. 대조용 생활비는 관리 범위의 실제 보유금과 아직 받지 않은 수입·받을 돈, 아직 처리하지 않은 지출 의무를 반영한다. 준비 완료한 돈을 다시 쓸 수 있는 생활비로 합산하지 않는다.

받을 돈도 예정금액으로 반영하므로 남은 생활비를 지금 즉시 인출할 수 있는 현금 잔액과 같다고 설명하지 않는다. 같은 자금을 계좌·가계부 사이에서 중복 포함하지 않게 설계한다.

```text
예산상 생활비 = 월별 예산 + 전월 이월금 - 생활비 반영 지출
미정산액 = 돌려받을 금액 - 사용자가 처리한 정산 완료금액
잔액 차이 = 실제 보유금·예정 입출금으로 산정한 대조용 생활비 - 예산상 생활비
첫 달 시작금액 = 대조용 생활비 - 첫 달 예산 + 첫 달 생활비 반영 지출
```

사용 시작 기준은 선택한 월의 1일이다. 월초 은행 잔액을 찾아 입력하게 하지 않고 현재 잔액과 기존 납부·준비·받을 돈·월중 거래를 반영해 첫 달 시작금액을 역산한다. 시작금액은 분류별 예산 비율로 자동 배분하고 수정할 수 있게 하며, 음수와 원 단위 잔여도 합계를 맞춘다.

초기 역산 후에는 거래가 바뀔 때마다 시작금액을 바꿔 오차를 자동으로 없애지 않는다. 잔액 차이만 보여주며 완료·미완료 상태나 오차에 따른 저장 차단을 두지 않는다. 계좌 포함 범위·기준 시점·역산 예외는 계산 설계에서 검증한다.

### 분류·기본 예산·월별 예산

분류는 한 단계로 유지한다. `생활/동물`은 상하위가 아닌 하나의 분류다. 가계부 생성 때 추천 항목을 클릭해 추가하거나 직접 입력한다. 거래가 있는 분류를 삭제하면 비활성화하고 과거 거래·통계를 보존한다.

기본 예산은 새 월의 기준값이고 월별 예산은 예상 실수령액·큰 지출에 따라 조정할 수 있다. 기본값 변경은 이미 생성한 월 예산을 덮어쓰지 않는다. 금월·미래 월은 기본값으로 리셋할 수 있지만 과거 월은 리셋할 수 없다. 리셋은 예산만 바꾸고 거래·이월금을 초기화하지 않는다.

### 지불상태와 거래 단위 준비 처리

| 사건                        | 처리                                              |
| --------------------------- | ------------------------------------------------- |
| 카드 사용·예정 지출 등록    | 생활비 부담과 필요한 준비액 반영                  |
| 생활비에서 결제 계좌로 이체 | 선택한 거래의 준비 상태 처리, 지출 재차 반영 금지 |
| 카드대금 실제 출금          | 이미 준비한 돈의 출금, 새 지출로 집계하지 않음    |
| 현금·직접 계좌이체          | 실제 지급 완료로 기록, 카드 준비 완료와 구분      |

기존 시트의 지불상태 Y는 카드에서는 준비금 확보, 현금·계좌이체에서는 지급 완료다. 이를 카드대금 출금과 혼동하지 않도록 구분한다.

MVP는 거래 단위 선택과 전체 선택을 지원한다. 2만 원짜리 5건 중 3건을 선택하면 6만 원을 이체하고 그 3건만 처리한다. 한 건의 2만 원 중 1만 원만 준비하는 기능은 넣지 않는다. 실제 송금은 사용자가 외부에서 한다.

### 준비 후 금액 변경과 조정

준비 완료한 거래를 취소·감액하면 차액을 다음 이체에서 빼고, 추가 청구는 더한다. 반영한 조정은 소진해 다시 적용하지 않는다. 음수 조정은 결제 계좌에 남겨 다음 준비에 쓰며 생활비 계좌로 자동 반환하지 않는다. 필요액보다 큰 음수 잔여를 버리지 않는다.

조정은 원거래·기존 준비 처리와 연결한다. 차액 자동 계산·확인, 이체가 없는 상계·음수 잔여 소진·오입력 취소 화면은 구현 전 설계에서 구체화한다.

### 고정지출과 할부

- 고정지출은 실제 결제 전에 예정일·금액으로 등록해 생활비와 카드 실적에 선반영한다. 정렬을 위해 결제일을 1일로 바꾸지 않는다.
- 실제 금액이 다르면 예정 거래를 보정하고, 이미 준비했다면 차액 조정과 연결한다. 매 건 결제 확인 버튼을 필수 업무로 추가하지 않는다.
- 할부는 전체 승인 원거래와 미래 회차를 연결한다. 60만 원 3개월 할부의 생활비·준비액은 월 20만 원씩이다.
- 나누어떨어지지 않는 회차 금액은 임시 배분 후 카드사 확정 금액으로 보정한다. 카드사별 규칙을 추측해 확정 청구액으로 표시하지 않는다.

### 한 결제의 분류별 분할과 할인

한 결제를 여러 분류로 나누더라도 원결제 한 건을 유지한다. 준비금·실적·파일 대조는 원거래 기준이고 생활비 통계는 분류별 금액 기준이다. 분할 합계는 원결제와 일치해야 한다.

별도 기록하는 할인은 카드사 할인이다. 상품 자체 할인은 결제금액에 이미 반영된 것으로 취급한다. 카드사 할인은 분류별 금액 비율로 자동 배분하고 원 단위 합계를 맞춘다.

| 분류      | 할인 전   | 카드사 할인 | 생활비 반영액 |
| --------- | --------- | ----------- | ------------- |
| 식품/외식 | 80,000원  | 4,000원     | 76,000원      |
| 생활/동물 | 20,000원  | 1,000원     | 19,000원      |
| 합계      | 100,000원 | 5,000원     | 95,000원      |

잔여액 배분 순서·분할 후 부분 취소·할부·정산 조합은 상세 계산 설계에서 정한다. 모든 최종 등록 거래는 분류를 반드시 선택하며 분할된 항목도 각각 선택한다.

### 통계제외·실사용자·정산

통계제외는 생활비 지출의 중복 집계를 막는 처리다. 원거래 삭제·결제 준비 제외·실적 제외·미래 세무 제외를 뜻하지 않는다.

결제수단의 소유자는 카드·계좌에 등록하고 거래에서 참조한다. 실사용자는 별도 목록으로 관리한다. 가계부 구성원은 기본 포함하고 가입하지 않은 가족·친구도 추가할 수 있다. 사람 등록으로 참여 권한을 주거나 실사용자 변경만으로 정산을 만들지 않는다.

`돌려받을 금액 있음`을 체크하면 전액을 기본 입력하고 필요하면 일부로 수정한다. 전체 카드 결제액을 준비하되 내 부담액만 생활비 지출로 잡는다. 9만 원 결제 중 내 부담이 3만 원이면 받을 돈은 6만 원이고 준비액은 9만 원이다.

여러 거래를 한 번에 받거나 여러 사람에게 시차를 두고 받는 정산은 사용자가 완료금액을 지정한다. 부분 정산은 허용한다. 입금 시 미정산액을 줄이고 실제 보유금을 갱신하며 일반 수입으로 중복 기록하지 않는다. 거래·사람별 배분과 잔액 갱신 화면은 상세 설계 대상이다. 상대방이 먼저 결제했다면 사용자가 실제 송금한 뒤 지출로 기록한다.

### 급여·비급여 수입과 개인자금

수입은 건별로 입력하고 급여·비급여를 나눈다. 귀속자·입금 계좌·실제 입금일 또는 예정일·예산 반영월을 구분한다. 급여에는 명세서상 귀속 연월도 별도로 기록한다. 예산월과 미래 연말정산 귀속을 같은 값으로 고정하지 않는다.

급여는 기본급·수당 등 지급과 소득세·보험료 등 공제를 구분한다. 기본 항목을 제공하되 사용자가 추가·수정할 수 있고 지급 항목은 명세서에 따라 과세·비과세를 선택하며 구체적인 내용은 메모한다. 지급 합계에서 공제 합계를 빼 실수령액을 계산하고 세율·보험료 자동 계산은 하지 않는다. 입력 구성은 재사용하되 변경이 과거 급여를 바꾸지 않는다. 비급여는 내용·금액 중심의 간단한 입력으로 둔다.

예상 수입은 수입예정금으로, 이미 받은 수입은 실제 보유금으로 구분한다. 전월 급여를 금월 예산에 사용할 수 있으며 이미 입금된 돈을 예정 수입에 다시 넣지 않는다. 별도 통장 운용이나 전용 자금 잠금 설정을 강제하지 않는다.

개인자금·용돈으로 빼는 돈은 가계부 지출로 처리한다. 이후 개인 사용을 별도 가계부로 기록할지 여부는 사용자에게 맡기며 자동 연동하지 않는다. 이미 지출 처리한 개인 사용을 같은 가계부에 적으면 통계제외로 중복을 막는다. 생활비 카드로 썼다면 개인자금의 반환은 새 소득과 구분한다.

### 연속성

분류별 이월·음수 잔액, 카드 전월실적·넘어온 납부액, 미래 고정지출·할부·미정산·조정을 월·연도 경계 없이 이어간다. 파일 복사·전년도 수동 이관은 요구하지 않는다.

## 6. 선택적 공개

공동생활비에 반영하는 범위와 상세 열람 범위는 별개다. 비공개라는 이유로 본인의 준비금이나 귀속된 공동 금액 계산을 누락하지 않는다.

| 공개 수준 | 다른 구성원에게 보이는 정보                         |
| --------- | --------------------------------------------------- |
| 나만 보기 | 개인 거래의 금액·사용처·건수 등 상세 미노출, 기본값 |
| 합계 공유 | 허용된 범위의 합계, 거래 상세 미노출                |
| 상세 공유 | 허용된 거래의 날짜·금액·사용처 등 상세              |

각자가 카드·계좌의 기본 공개 수준을 설정한다. 거래별로 명시한 공개 예외가 기본값보다 우선한다. 기본값 변경 시 이후 거래만 적용할지 기존 거래에도 적용할지 사용자가 선택하지만, 기존 거래에도 적용하는 경우 명시적인 거래 예외는 유지한다.

관리자·소유자도 비공개 상세에 접근할 수 없다. 목록·검색·알림·API 등에서 우회 노출되지 않도록 서버에서 검사한다. 합계 공유는 완전한 익명성을 뜻하지 않는다. 분류별 합계 공유는 후속 검토 범위다.

## 7. 카드 정보와 AI 파일 가져오기

### 카드 정보 등록과 조건

사용자는 공용 카드에서 상품을 선택한다. 없는 카드는 AI가 공식 자료를 찾아 정리하고 사용자가 상품명·발급사·버전·링크 등으로 본인이 등록하려는 카드와 일치하는지 먼저 확인한다. 확인한 카드는 개인용으로 즉시 사용하고 AI가 찾은 조건으로 실적을 처리할 수 있다.

공용 카드 조건은 운영자가 검수한다. AI가 찾지 못했거나 애매한 조건은 확정값으로 만들지 않고 검수 대상으로 표시한다. 출처·확인일·버전을 유지하고, 개인 설정이 공용 조건과 다르면 개인용 카드로 따로 저장한다. 개인 설정을 자동 공개하거나 공용 조건으로 덮어쓰지 않는다.

실적 계산은 프로그램이 한다. 예정 고정지출, 카드별 할부 인정 방식, 세금 등 제외 항목, 할인 거래 전체 제외·할인액 제외·전액 인정 조건을 구분한다. 예정 포함 실적과 목표 부족액을 보여주고 사용자가 사용할 카드를 판단한다. 현재 사용자 카드의 기간은 1일~말일이며 모든 상품에 같은 조건을 가정하지 않는다.

### 파일 가져오기와 대조

1. 대상 카드와 이용내역 또는 결제예정·청구내역 파일을 선택한다.
2. 프로그램이 파일을 읽고 AI가 구조·열 의미·거래 범위·취소·할부 표현을 해석한다. 수식·매크로·AI 생성 코드는 실행하지 않는다.
3. 프로그램이 원본 값으로 변환하고 날짜·금액·부호·통화·합계·누락·중복 후보를 검증한다.
4. 신규 거래와 기존 예정·할부 연결 후보, 취소·청구액 보정 후보를 보여준다.
5. 사용자가 연결·변경을 확인하고 모든 최종 등록 대상 거래의 분류를 선택한다.
6. 확정한 내용만 반영하고 원본 파일·임시 사본을 폐기한다. 필요한 출처 메타데이터는 유지한다.

같은 날짜·금액·가맹점이라는 이유만으로 자동 병합하지 않는다. 결제예정 파일에 없다는 이유로 미매입 거래를 취소·삭제하지 않는다. 상품별 구매 항목이 없는 카드 파일에서 AI가 분류별 금액을 사실처럼 만들어내지 않는다.

해외 결제는 승인액·원통화와 최종 원화 청구액을 구분한다. 환율·수수료·할부 회차로 금액이 달라지면 원거래를 보정하고 이미 준비한 차액은 다음 이체에 반영한다. 월을 넘긴 금액 보정도 원래 거래월에 반영하고 이후 이월을 다시 계산한다. 당월 새 지출로 중복 기록하지 않는다.

실제 지원 카드·확장자·크기·암호 파일 처리 등은 표본 검증으로 확정한다. 모든 카드 파일 지원을 보장하지 않는다.

### 데이터 보호

- 원본 파일은 보관하지 않는다. 가져오기·사용자 확인 중만 일시 처리하고 성공·실패·취소·만료 시 임시 사본까지 폐기한다. 재대조 시 파일을 다시 선택한다.
- 원본·전체 셀 덤프를 DB·객체 저장소·백업·로그·오류 수집에 남기지 않는다. 확정 거래와 필요한 출처 메타데이터는 암호화 정책에 따라 저장한다.
- 모든 저장 금액과 금융 상세는 민감정보로 다루고 KMS 봉투 암호화·별도 세션 쿠키 기반 Redis 키 캐시를 사용한다. 서버 처리 중 평문이 존재할 수 있으며 운영자 단독 복호화 불가·서버 전체 장악 방어를 보장하지 않는다.
- 외부 AI에 필요한 정보만 전달하도록 설계하고 불필요한 인증정보·카드번호·계좌번호·이름은 제거하거나 가린다. 제공사·전송 범위·안내 및 동의·제공사 보관·삭제·비용은 도입 전 확정·검증한다.
- 파일 안의 지시문은 신뢰하지 않는다. 금융 원문·키·쿠키·토큰은 로그·분석·진단에 남기지 않고 테스트에는 합성 자료를 사용한다.

## 8. 자산현황과 데이터 최신성

자산현황은 별도 화면에서 계좌·현금별 보유금과 예정 입출금을 모아 보여준다. 기존 시트의 현재보유금액·수입예정금액·지출예정금액·합계 구조를 서비스의 수입·정산·준비금 기록과 연결한다. 생활비 잔액 차이를 표시하는 기능만으로 자산현황을 대체하지 않는다.

### 기본 현황과 갱신

- 소유자·상품유형·용도·금융사·표시명·현재 보유금·잔액 확인 시점을 관리한다. 결제수단의 계좌와 같은 자산을 참조해 중복 등록·합산하지 않는다.
- 현재 보유금은 실제 잔액으로 입력한다. 단순 잔액 갱신을 새로운 수입·지출로 생성하지 않는다.
- 현재 보유금과 수입예정·지출예정, 예정 반영 후 금액을 나누어 표시한다. 소유자별·전체 합계는 같은 범위와 공개 권한으로 집계한다.
- 수입·정산·준비금 내역에서 예정금액을 가져오며 동일 금액을 자산현황에 다시 입력하게 하지 않는다. 관련 기록과 계산 근거를 확인할 수 있게 한다.
- 내부 이체·준비 처리·입금 기록과 실제 잔액 갱신이 같은 돈을 이중 가감하지 않아야 한다.

```text
예정 반영 후 금액 = 현재 보유금액 + 수입예정금액 - 지출예정금액
```

전체 보유 자산, 예정 반영 후 금액, 남은 생활비는 별개다. 이미 결제 계좌에 확보한 준비금과 생활비 밖의 자금을 다시 쓸 생활비로 합산하지 않는다. 자산현황에서도 비공개 계좌·보유금은 관리자에게 자동 공개하지 않는다.

### 생활비 외 자산·부채의 수동 현황

저축·투자·연금·부동산·기타 자산·대출 등 부채도 항목을 등록하고 금액을 수동 갱신해 유형별·소유자별 합계를 보는 범위까지 MVP에 포함한다. 입력한 자산 금액과 부채 잔액으로 총자산·총부채·순자산을 구분해 보여준다. 투자·부동산 금액은 사용자 입력값이며 시세·수익률·이자·상환 자동 계산은 제외한다.

생활비 반영 범위와 자산 보유 현황은 분리한다. 저축·투자 자산을 등록했다고 생활비가 늘어나거나 부채 원금 전체가 당월 생활비에서 빠지지 않는다. 단순 현황 수정만으로 수입·지출·상환 거래를 자동 생성하지 않는다. 비공개 자산의 열람 제한과 금액 암호화도 동일하게 적용한다. 세부 기준은 [MVP 기능 명세서](./mvp-functional-spec.md)의 ASSET-03을 따른다.

### 입력 방식과 기준 시점

은행 파일은 MVP에서 제외한다. 실제 잔액은 사용자가 입력하고 수입·준비 처리·정산도 기록한다. 계산상 잔액으로 은행의 실제 잔액을 자동 덮어쓰지 않는다.

화면에는 잔액 확인 시점과 거래 반영 기준을 구분하고 아직 예정인 지출·미입금액 및 조건 미확정 사유를 보여준다. 일부 카드·구성원 자료만 최신이라면 전체 숫자를 실시간 확정 잔액으로 설명하지 않는다. 표시 방식은 화면 설계에서 구체화한다.

정산 완료와 잔액 갱신이 같은 입금을 두 번 반영하지 않아야 한다. 잔액 차이가 0이어도 누락이 없다는 보장은 아니며, 고급 변경 이력 추적은 MVP에서 제외한다. 대조의 완료·미완료 상태나 차이에 따른 저장 제한도 두지 않는다.

## 9. 주요 사용자 흐름

### 처음 사용

1. 초대를 받고 카카오 로그인으로 가입·참여한다.
2. 가계부와 시작월, 추천 또는 직접 입력 분류·기본 예산을 정한다.
3. 카드·계좌의 소유자·결제 계좌·기본 공개를 정한다. 없는 카드라면 AI 탐색 후 상품을 확인한다.
4. 현재 실제 잔액, 기존 납부·준비금·받을 돈, 시작월 거래와 고정지출·할부를 반영한다.
5. 역산된 첫 달 시작금액과 분류별 배분을 확인·수정한다. 차이가 있어도 저장할 수 있다.
6. 예정 포함 실적·목표 부족액·생활비·추가 준비액을 확인한다. 공동 사용이면 구성원·권한을 설정한다.

### 반복 관리

1. 카드 파일을 가져오거나 지출·수입을 직접 입력한다.
2. 예정·기존 거래와 대조하고 분류·금액·취소·할부 연결을 확인해 등록한다.
3. 필요한 거래만 분류를 나누고 실사용자·받을 돈·공개 예외를 수정한다.
4. 결제 계좌별 거래를 선택하거나 전체 선택해 필요한 합계·조정을 확인한다.
5. 실제 송금 후 선택한 거래만 준비 처리하고 반영한 조정을 소진한다.
6. 돌려받은 금액을 수동 정산하고 실제 잔액을 갱신한다. 일반 수입으로 중복 반영하지 않는다.
7. 생활비·카드 실적·잔액 차이를 확인한다. 월·연도가 바뀌어도 같은 기록을 이어간다.

화면 배치와 입력 순서는 [MVP 기능 명세서](./mvp-functional-spec.md)의 기능 기준으로 구체화하고 사용성을 검증한다.

## 10. 사업 가설과 경쟁 환경

### 검증할 사업 가설

- 기존 엑셀 사용자 중 카드 결제 준비금과 남은 생활비를 따로 계산하는 사람이 있다.
- 파일 업로드가 남아 있어도 계산·대조·공동관리 부담이 줄면 반복 사용한다.
- 경제공동체의 상세 지출 비공개가 공동 관리 도입에 도움을 준다.
- 사용자가 계산 결과를 신뢰하고 일정 금액을 지불할 이유가 생긴다.
- 반복 사용으로 분류 규칙·계좌 관계·공동 관리 습관·신뢰가 쌓이면 유지에 도움이 된다.

잠재 시장 규모·유료 전환율·매출 전망은 검증 대상이다.
거래 데이터의 누적만으로 강한 락인이 보장된다고 보지 않는다. 기존 서비스의 전환 비용도 있으므로 가져오기·내보내기의 편의와 신뢰를 함께 고려한다.

## 12. 알파 검증 계획

### 준비와 진행 순서

1. 기능 명세서의 계산·권한·가져오기 수용 기준과 복합 거래 사례를 구체화한다.
2. 가장 유사한 경쟁 제품 2~3개에 동일한 합성 시나리오를 적용해 차이를 기록한다.
3. 알파테스터의 참여 의사, 기기, 카드·은행, 파일 다운로드 가능 여부를 확인한다.
4. 비식별 파일 표본으로 AI 매핑과 원본 값 추출·검증의 가능성을 확인한다.
5. 준비금·예정 거래·정산·분할·할부의 복합 계산 사례와 기준일·공개 권한을 확정하고, 기본값·예외 입력의 화면을 검토한 뒤 개인 사용 흐름부터 구현한다.
6. 공동 사용과 공개 설정을 연결하고 실제 사용 실험을 진행한다.
7. 두 번의 카드 결제주기 동안 반복 업로드·수정 부담·계산 신뢰·공동 참여를 관찰한다.
8. 무료 알파 이후 유료화 검증을 별도로 진행한다. 첫 알파에는 과금하지 않으며 가격·과금 단위는 후속 결정이다.

### 기록할 지표

- 최초 파일 등록 성공률과 소요시간
- 업로드별 수정 거래 수, 금액·부호·취소·할부 해석 오류
- 중복 후보 오탐과 누락, 원본 대비 미등록 거래
- 금융기관·파일별 마지막 반영일과 자료 누락 범위
- 주기적인 재업로드와 두 구성원의 참여
- 별도 엑셀 계산이 계속 필요한지
- 남은 생활비·이체 필요액·예정 포함 카드 실적을 실제 의사결정에 사용하는지
- 카드 조건 설정, 거래 분할, 일괄 이체·조정·정산을 처리하는 시간과 수정 부담
- 예정 거래와 실제 거래의 중복 반영·잘못된 연결 여부
- 월·연도 전환에서 수동 재입력 없이 기록이 이어지는지
- 가격 제시 후 실제 결제와 계속 사용 여부

알파 성공 기준의 참여자 수·반복 사용 비율·허용 입력 부담은 실험 설계에서 정한다. 금액·공개 권한 오류는 사용성 지표와 별도로 수정하고 재검증한다.

## 14. 후속 확장과 구현 전 설계

### 후속 확장

- 금융기관 자동 연동·은행 파일·문자·알림 수집·PDF·이미지·영수증 가져오기.
- 카드 약관의 상시 갱신·전체 혜택 최적화·추천 확대.
- 절세·연말정산 기능, 분류별 합계 공개, 고급 잔액오차 추적.
- 모바일·일반 공개 가입·유료 요금제. 무료 알파 검증과 구분해 결정한다.

### 후속 세무 기능을 위한 데이터 요구

MVP에서 세무 화면을 만들지 않더라도 원결제·분할·승인·청구·할인·실부담을 구분한다. 결제수단 소유자·실사용자·부담·정산 관계, 실제 날짜·예산 반영월·급여 귀속 연월, 할부 회차·취소 관계를 보존한다. 사용자 정의 급여 지급·공제와 과세·비과세 입력도 유지한다.

생활비 통계제외·실적 인정·미래 세무 분류는 다른 목적의 속성이다. 어느 한 항목으로 세법상 귀속을 단정하지 않는다. 세무 확장을 이유로 원본 파일·전체 셀 덤프·불필요한 개인정보를 보관하지 않는다. 실제 세무 기능 도입 시 해당 연도의 법령·귀속 기준을 별도 검증한다.

### 구현 전 설계·검증 항목

세부 기능 기준은 [MVP 기능 명세서](./mvp-functional-spec.md)를 따른다.

1. 실제 잔액·납부 의무·준비금·받을 돈·예정 수입의 기준 시점과 자금 범위, 복수 가계부 중복 방지.
2. 초기 역산·분류 배분, 예산 0원·음수·정수 잔여, 초기 거래와 재가져오기의 중복 방지.
3. 분할·할부·부분 취소·정산·월 경계 수정의 계산 사례와 원거래 연결.
4. 선택 준비 처리·조정 상계·음수 잔여·오입력 수정·실제 잔액 갱신의 화면 흐름.
5. 우선 카드·파일 표본과 지원 형식·한도, 예정·기존 거래 연결과 확인 범위.
6. 반복 지출 생성 시점·미래 변경, 카드 조건 버전·공용 검수 결과의 개인 적용.
7. 관리자 지정·해제·설정 권한 범위, 소유권 이전 절차, 합계 노출 경계·삭제 및 백업 운영.
8. 수입 예산월 기본값·대상 기간, 여러 상대·거래의 정산 배분 화면.
9. KMS 제공사·키 단위·캐시 수명·키 교체·복구·삭제·지원 진단.
10. 외부 AI 제공사·전송 범위·안내 및 동의·제공사 보관·삭제·호출 비용과 한도.
