# 서비스 포지셔닝·성장 검증 전략

관련 문서: [제품 기획안](./product-plan.md), [MVP 기능 명세서](./mvp-functional-spec.md), [금융 데이터 보호 기준](./encryption-policy.md).

이 문서는 핵심 가치 전달, 후속 UX 실험, 사용자 유입과 유료화 검증 기준을 정의한다. 현재 제공 범위는 초대 기반 무료 알파이며, 캡처·글 기반 단건 입력 보조는 MVP 범위이며, 가입 전 체험·공개 가입·유료 요금제의 출시 여부와 순서는 검증 결과로 결정한다. 가격·체험 기간·과금 단위는 확정된 판매 조건이 아니다.

## 1. 포지셔닝과 모집 대상

> 이미 쓴 카드값과 앞으로 나갈 돈까지 반영해, 이번 달 남은 생활비를 확인하세요.

핵심 가치는 예정 지출까지 포함한 남은 생활비다. 예정 포함 카드별 실적·단계별 부족액과 결제 계좌별 추가 준비액을 보조 가치로 전달한다. AI는 입력과 대조의 수고를 줄이는 수단이다.

- 초기 대상은 여러 카드·예정 지출·결제 준비금을 관리하며 별도 엑셀·노션 계산을 유지하는 사용자다.
- 혼자 관리하거나 구성원과 같은 기록을 함께 관리할 수 있다. 가구 형태보다 관리 문제와 기존 작업 방식으로 모집 대상을 구분한다.
- 같은 가계부의 기록은 구성원이 함께 관리한다. 비공개·부분 공개를 신규 옵션이나 유료 혜택으로 제시하지 않는다.
- 공동 관리, 카드 준비금, AI 입력 각각의 존재를 독점적인 기능으로 주장하지 않는다. 국내 카드 조건·예정 지출·지불 관리·회수를 연결하는 전체 작업의 부담 감소를 검증한다.

### 금액 설명 기준

- 예산상 남은 생활비, 실제 보유금, 예정 입출금, 계좌별 추가 준비액을 구분한다. 남은 생활비는 즉시 인출 가능한 현금과 같지 않다.
- `통장 잔액 - 카드값`만으로 남은 생활비를 산정하거나 이를 확정적인 재무 진단으로 제시하지 않는다. 기존 계산의 자금 범위·기준월·회수·예정 수입·할부 조건을 따른다.
- 최상단 남은 생활비와 계산 근거·자료 최신성을 함께 안내한다. 실제 잔액은 사용자가 확인한 값이며 은행 실시간 조회값으로 표현하지 않는다.
- 카드 결제 준비액은 절약액·수익·혜택 획득액이 아니다. 리포트에는 확인한 결제 준비액·처리한 거래 등 검증 가능한 사실만 표시한다.
- 입력 속도와 오류율은 실측 전까지 목표로만 관리하고 '3초 입력', '0ms', '100% 정확'을 보장 문구로 사용하지 않는다.

## 2. 가입 전 체험

### 범위와 시나리오

첫 체험은 실제 `apps/client`의 화면·입력 검증·계산 모듈을 공유하는 비로그인 합성 데모 모드로 설계한다. 합성 데이터 저장소를 사용하고 실제 계정·금융 기록·외부 AI·송금 기능과 분리한다. 랜딩 전용 계산 로직은 별도로 만들지 않는다. 대표 시나리오만 열어 초기 범위를 제한한다.

현재 HTML 화면설계서는 UX 확인용 시뮬레이션이며 운영 계산의 원본으로 사용하지 않는다. 제품 구현 시 검증된 계산·UI를 서비스와 데모에서 공유한다. 실제 LLM 호출 없이 다음 시나리오의 전후 변화를 보여준다.

| 시나리오                 | 보여줄 변화                                                                         |
| ------------------------ | ----------------------------------------------------------------------------------- |
| 카드로 일시불 지출 기록  | 통장 실제 잔액은 그대로이고 해당 월 남은 생활비와 결제 준비액이 바뀜                |
| 미래 고정지출 등록       | 해당 월 생활비와 예정 포함 카드 실적에 함께 반영되며 실적은 확인된 카드 조건을 따름 |
| 한 결제를 두 분류로 분할 | 원결제 한 건을 유지하며 두 분류의 금액 합계가 전체와 일치함                         |

합성 예시임을 표시하고 초기화·다시 체험을 제공한다. 실제 송금, 은행 조회, 실시간 AI 기능이 실행된 것처럼 표현하지 않는다. 체험은 실제 금융 기록·통계와 분리한다. 초대 알파 단계의 다음 행동은 초대 신청 또는 기존 초대의 참여이며 공개 가입을 우회하지 않는다.

체험 완료는 핵심 가치의 이해 여부를 보는 지표다. 실제 전환 동기는 첫 장부 설정·기존 도구에서의 이동·반복 기록·다음 달 사용으로 별도 검증한다. 제품과 공유할 계산·입력 검증이 준비되기 전에는 별도 랜딩 위젯을 먼저 구현하지 않는다.

### 실제 입력의 승계

처음에는 합성 데이터 체험을 우선한다. 실제 금액을 수정하는 기능을 도입하더라도 사용자의 명시적인 선택 후 초기 설정 초안으로만 전달한다. 계좌·자금 범위·기준월·기존 거래·준비금·회수 관계를 확인하기 전 실제 장부나 시작금액으로 확정하지 않는다.

브라우저 임시 저장을 도입하려면 대상 값·보관 기간·삭제·공용 기기 처리 기준을 먼저 정의한다. 실제 금융 상세를 `localStorage`에 무기한 보관하는 방식은 채택하지 않는다. 카드번호·계좌번호·이름 등 불필요한 정보는 체험에서 요구하지 않는다.

## 3. 초기 설정과 캡처·글 입력 보조

### 초기 설정

처음부터 모든 설정을 요구하기보다 남은 생활비와 준비액을 확인하는 데 필요한 순서를 검증한다. 잔고와 아직 출금되지 않은 지출 의무의 차이를 설명하되, 두 금액만 입력받고 실제 장부가 완성됐다고 안내하지 않는다. 기존 시작월·계좌 범위·예산·분류·거래 반영·시작금액 확인 흐름과 연결한다.

이미 공동 가계부에 초대받은 구성원에게 새 가계부 설정을 반복시키지 않는다. 미입력을 확인된 0원으로 바꾸지 않고 자료가 덜 반영된 범위를 표시한다. 잔액 차이를 이유로 저장을 차단하지 않는다.

### 캡처·글 기반 단건 입력 보조 (MVP)

기존 지출 폼 상단에서 사용자가 직접 올린 결제 문자·알림·카드 앱 단건 캡처와 작성한 설명으로 초안을 채운다. PC에서 이미지 붙여넣기·파일 선택·끌어놓기를 지원한다. 한 건 입력을 보조하며 복수 거래 일괄 등록과 문자·푸시 알림 자동 수집은 제외한다. 단순 단건에 AI 사용을 강제하지 않는다.

1. 사용자가 캡처 한 장 또는 작성한 설명으로 초안을 요청한다. 현재 가계부의 활성 분류·등록 결제수단 중 필요한 정보와 최소 텍스트만 해석 대상으로 삼는다.
2. 원문·첨부 미리보기와 현재 입력/제안 값을 대조하고 폼 반영을 확인한다. 모호한 분류·카드는 후보 선택 또는 직접 입력으로 확인한다.
3. 사용자가 원문과 결과를 대조하고 분류·금액·할인·결제수단 등을 수정한다. 기존 수동 입력을 바꾸는 경우 변경을 확인할 수 있어야 한다.
4. 모든 분류 지정과 금액·할인 합계 등 기존 검증을 통과한 뒤 저장한다. 저장 전에는 실제 기록·예산·실적을 변경하지 않는다.

명확한 단건은 수동 입력을 짧게 유지하고, 과거 분류·카드를 재사용하더라도 확인 가능한 기본값이나 후보로 제시한다. 마트·종합몰처럼 상품 종류가 다양한 사용처는 과거 분류로 자동 확정하지 않는다. 분류별 할인 자동 배분은 전용 버튼을 누른 경우에만 수행한다.

AI 오류·시간 초과 시 원문·첨부와 기존 폼을 유지하고 재시도·수동 입력으로 계속한다. 기존 거래와 중복 후보를 확인하며 캡처로 저장한 거래는 후속 카드 파일 대조에도 연결한다. 이미지 원본과 임시 사본은 처리 후 폐기하고 외부 전송·보관 정책은 MVP 출시 전에 검증한다. 모델의 자기 보고 확신도만으로 정확성을 보장하거나 저장을 자동 확정하지 않는다. 정수 계산·합계·필수값 검증은 프로그램이 담당한다.

### 도입 판단

수동 입력 대비 완료 시간·수정 항목 수·저장 성공률·재사용률과 요청당 비용을 비교한다. 단건 입력을 느리게 하거나 잘못된 추천을 고치는 부담이 크면 적용 대상을 줄인다. 제공사 보관 정책·전송 안내와 동의·호출 한도·민감정보 최소화를 MVP 출시 전에 검증한다. PC로 캡처를 가져오는 수고와 직접 입력 대비 실제 완료 시간도 함께 확인한다.

## 4. 파일 가져오기 개선

AI는 파일 구조와 열 의미·분류를 보조하고 프로그램이 원본 값 추출·검증·계산을 수행한다. 최소 구조 표본과 검증된 양식 매핑을 재사용하되, 표본을 고정된 상단 행 수로 제한하지 않는다. 다중 시트·거래표·합계 행·통화·누락 가능성에 맞게 검증한다.

가맹점별 추천 요청은 중복을 줄일 수 있지만 실제 거래 행은 보존한다. 분류 이력은 해당 가계부의 활성 분류와 사용자 확인 범위에서 재사용하고 암호화·접근 경계를 적용한다. 원본 파일과 임시 사본은 보관하지 않는다.

음수만으로 승인 취소를 자동 상계하지 않는다. 기존 거래의 분류·분할·메모를 보존하며 최종 청구액 등의 보정은 차이와 후속 영향을 확인한 뒤 확정한다. 같은 날짜·금액·사용처만으로 자동 병합하지 않는다.

## 5. 가격·구독 검증 가설

무료 초대 알파에는 결제·구독을 넣지 않고 알파 기간에는 안내한 기능을 무료로 제공한다. 알파 무료 제공이 정식 출시 이후의 영구 무료를 뜻하지 않는다. 정식 출시의 무료·유료 범위는 반복 사용과 지불 의사를 검증해 별도로 결정하고 전환 전에 조건을 안내한다. 기존 기록의 보존·열람·내보내기와 새 기능 이용 조건을 구분한다.

| 항목           | 검증 방향                                                                                                     |
| -------------- | ------------------------------------------------------------------------------------------------------------- |
| 가격           | 연 39,000~49,000원을 실험 후보로 두고 지불 의사와 유지율을 확인. 확정 가격·할인 약속이 아님                   |
| 과금 단위      | 개인·사용자·가계부 중 단위를 정의하고, 공동 가계부의 구독 주체와 다른 구성원의 이용 범위를 확정               |
| 체험           | 결제수단 선등록 없는 30~45일 체험을 후보로 검증. 실제 카드 청구·지불 관리 주기를 경험했는지 확인              |
| 무료/유료 경계 | 알파 기간 무료 제공과 정식 요금제를 구분. 기본 기록·열람·내보내기 및 기능 이용 조건을 검증하고 전환 전에 안내 |
| 체험 종료      | 기존 기록 보존·열람·내보내기·공동 편집·구성원 접근에 미치는 영향을 가격 공개 전에 정의                        |
| AI 한도        | 요청당 비용·사용량·재시도·남용 가능성을 산정한 뒤 사용 한도 결정. 무제한 제공을 선약하지 않음                 |
| 초기 할인      | 기간과 조건을 정한 프로모션을 검토하며 평생 할인은 약속하지 않음                                              |

유료 후보는 AI 파일 해석·자연어 입력의 월간 처리량, 추가 가계부, 시뮬레이션·비교 리포트 등 비용·확장 축으로 검증한다. 추가 가계부와 리포트의 실제 수요를 확인하며, 처리량 한도만으로 후보 가격을 설득할 수 있다고 가정하지 않는다. 알파 핵심 기능 전체를 유료 기능이라고 일괄 지정하지 않는다. 오래된 기록의 열람을 막는 장기 보관 과금은 우선 후보에 넣지 않는다. 자동 카드 최적화·절세 추천은 현재 MVP 범위에 포함하지 않는다.

### 매출과 순수익

월 순수익 300만 원은 운영 목표 후보이며 달성이 검증된 전망이 아니다. 가격과 유료 계약 수에 따른 월 환산 매출은 다음과 같다. 아래 계약 수는 인원 수와 다르며 과금 단위를 정한 뒤 산정한다.

| 가정                       |   월 환산 매출 |
| -------------------------- | -------------: |
| 900건 × 연 39,000원 ÷ 12   |    2,925,000원 |
| 1,100건 × 연 49,000원 ÷ 12 | 약 4,491,667원 |

연간 결제액의 월 환산이며 실제 월별 입금액·순수익과 다르다. 순수익은 결제 수수료·환불·서버·AI·마케팅·운영 비용과 세금 등을 반영해 산정한다. 계약 수만으로 순수익을 보장하지 않는다.

결제 연동 전 가격·제공 범위와 함께 업그레이드 관심 또는 얼리버드 대기 신청을 측정할 수 있다. 대기 신청임을 명시하고 구매·할인 확정처럼 표현하지 않는다. 클릭률·대기 신청률과 실제 결제·유료 유지율을 별도로 기록한다.

## 6. 유입·유지 검증

유튜브 화면 시연을 초기 채널 후보로 검증한다. 얼굴 없는 화면 녹화·음성 안내는 제작 방식의 선택지이며 지속 제작 시간과 사용자 유입 효과를 확인한다. 모든 시연은 합성 데이터를 사용한다.

- 통장 잔액과 남은 생활비가 다른 이유.
- 고정지출을 미리 반영해 카드 실적과 생활비를 확인하는 방법.
- 여러 카드·계좌를 함께 관리하며 별도 계산을 줄이는 방법.
- 한 결제의 분류 분할과 회수를 원거래에 연결하는 방법.

기능 시연과 실제 절약 효과를 혼동하지 않는다. 혜택·카드 조건을 설명할 때는 상품별 공식 조건과 확인 시점을 표시한다. 짧은 영상 재가공도 독립적인 성과로 가정하지 않고 원본·짧은 영상별 유입을 구분한다.

검증 흐름은 `콘텐츠 유입 → 체험 시작·완료 → 초대 신청·실제 참여 → 첫 장부 설정 → 반복 기록 → 다음 달 사용`이다. 공개 가입 이후에는 초대 단계를 가입 단계로 바꿔 측정한다. 원문·거래금액·사용처·자연어 텍스트 등 금융 상세를 분석 이벤트·이메일 도구에 보내지 않고 필요한 행동·집계 지표만 수집한다.

월별 안내는 확인한 거래·결제 준비 현황과 다음 행동을 설명한다. 상세 금융 금액을 이메일에 기본 노출하지 않고 로그인 후 확인하도록 연결한다. 알림 정책은 출시 전에 정의한다.

금융기관 연동은 고정된 유료 고객 수를 넘겼다는 이유만으로 시작하지 않는다. 입력 부담·이탈 감소 기대, 제공사 비용·보안·법적 조건, 운영 여력을 함께 검토해 도입을 결정한다.
