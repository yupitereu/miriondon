## 1. 목적과 범위

예정 고정지출·할부를 포함한 남은 생활비, 카드별 실적과 단계별 부족액, 결제 계좌별 준비금과 받을 돈을 관리한다. 자산현황에서 현재 보유금과 예정 입출금·예정 반영 후 금액을 함께 확인한다. 카드 거래 파일을 가져온 뒤 필요한 내용을 확인하고, 실제 송금·잔액·정산은 사용자가 기록한다.

### 제외

- 네이티브 모바일 앱, 유료 구독·결제, 일반 공개 가입.
- 마이데이터·오픈뱅킹, 은행 거래 파일 가져오기, 문자·푸시 알림 자동 수집과 알림 텍스트 일괄 입력, 자동 송금·결제. 사용자가 직접 첨부하는 단건 결제 캡처는 MVP에 포함한다.
- PDF·일반 영수증 인식과 복수 이미지·복수 거래 일괄 등록. 단건 결제 캡처 초안은 EXP-05 범위에 포함한다. 실제 지원할 카드 파일 형식은 표본 검증 후 확정한다.
- 한 거래 금액의 일부만 준비 처리하는 기능.
- 입금 자동 정산, 별도 보낼 돈 관리, 실사용자별 자동 정산 규칙.
- 개인자금 지급 이후 개인 지출 관리의 강제·자동 연동.
- 잔액이 맞았던 시점 이후의 변경을 모아 원인을 찾는 고급 추적.
- 연말정산·절세 계산·추천 화면. 후속 확장에 필요한 거래 사실은 유지한다.
- 모든 카드 약관의 상시 자동 갱신, 혜택 금액 전체의 최적화·카드 자동 추천.

### 가입 전 체험의 적용 경계

가입 전 체험은 [성장 검증 전략](./growth-strategy.md)에 정의한 후속 설계 대상으로, 알파의 필수 수용 기준이나 공개 가입·유료 기능으로 간주하지 않는다. 결제 캡처·글 기반 지출 입력 보조는 EXP-05에 정의한 MVP 기능이다.

- 체험은 실제 제품의 UI·입력 검증·계산 모듈을 공유하는 비로그인 합성 데모로 설계한다. 랜딩 전용 계산 로직을 만들지 않으며 현재 HTML 시뮬레이션을 운영 계산으로 사용하지 않는다. 합성 저장소는 실제 기록·통계·외부 AI·송금 경로와 분리하고 초기화할 수 있어야 한다.
- 체험 입력은 장부에 바로 저장하지 않는다. 사용자가 초기 설정 초안으로 승계한 뒤 계좌 범위·기준월·기존 거래·준비금을 확인하고 기존 검증을 거친다. 미입력을 0원으로 간주하지 않으며 실제 장부 전환·반복 사용을 별도로 측정한다.

| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 가계부                | 구성원·예산·거래·권한을 관리하는 단위. 한 명으로도 사용 가능                                                                                                                                                                            |
| 예산 반영월           | 수입을 생활비 관리에 반영할 월. 실제 입금일과 별도로 사용자가 선택                                                                                                                                                                      |

| 미참여 (인물)         | 가계부에 가입하지 않았으나 지출 실사용자 또는 회수 상대로 수기 등록하는 가족·지인. 사후 초대·가입 시 구성원 계정과 연결 가능                                                                                                            |
| 지불 관리 / 준비 처리 | 카드 결제 계좌 등에 필요한 자금을 확보·이체했는지 추적하는 기능. 상태는 '지불 준비 필요', '지불 대기', '지불 완료'로 관리                                                                                                               |
| 지출금 회수 / 받을 돈 | 대신 결제한 금액 중 돌려받기로 기록한 미정산 채권 관리. '회수 대상 금액(원금)', '미회수 금액(잔액)', '회수한 금액(완료)'으로 관리                                                                                                       |

1. KRW 금액은 정수 원 단위로 계산한다. 모든 배분 합계는 원래 금액과 일치해야 한다.
2. 지출 등록, 준비금 이체, 카드대금 출금을 각각 새 지출로 중복 집계하지 않는다.
3. 계좌 간 이동·정산금 입금을 일반 수입으로 집계하지 않는다.
4. 한 실제 결제는 하나의 원거래다. 분류 분할·할부 회차·취소·파일 대조는 원거래와 연결한다.
5. 거래일은 기본적으로 Asia/Seoul의 달력 날짜로 다루고 업로드 시각과 구분한다.
6. 금융 기록의 병합·변경·삭제는 사용자 확인 흐름과 서버 권한 검사를 거친다.
7. 원본 파일 없이도 확정 거래의 금액·출처 메타데이터·적용 규칙을 유지하되, 전체 셀 덤프를 보관하지 않는다.

## 3. 계정·가계부·역할

### AUTH-01 로그인과 초대

- 카카오 로그인만 지원한다. 초대받은 사용자만 무료 알파에 가입할 수 있다.
- 기존 가계부 소유자·관리자는 가계부 설정의 구성원 관리에서 초대할 사람의 이메일(카카오 계정)과 역할(관리자/구성원)을 지정해 초대장을 발송하거나 초대 링크를 복사해 전달할 수 있다.
- 초대장을 발송하면 대상자는 '초대 대기' 상태로 등록되며, 초대받은 사용자가 카카오 로그인으로 가계부에 가입·참여하면 '참여 중'으로 전환된다. 초대 발송자는 수락 전 대기 중인 초대를 취소할 수 있다.
- 구성원 목록 및 관리 화면에서 현재 로그인한 본인 계정은 이름 옆에 `(나)`로 식별하여 표시한다.
- 로그인 후 여러 기기에서 같은 기록을 사용할 수 있다. 한 기기에만 데이터를 보관하지 않는다.
- 별도의 개인·공동 가계부 유형 구분 없이 단일 가계부 모델로 생성·운영한다(혼자 사용하거나 필요 시 구성원을 초대·추가해 함께 사용).
- 초대 토큰 수명·재사용 방지·첫 알파 진입 초대 발급 방식은 구현 설계에서 정한다.

### AUTH-02 권한

| 작업                                              | 소유자 | 관리자        | 구성원 |
| ------------------------------------------------- | ------ | ------------- | ------ |
| 가계부 거래 조회·입력·수정                        | 가능   | 가능          | 가능   |
| 고정 수입·고정 지출 등록·수정·중지                | 가능   | 가능          | 가능   |
| 공동 분류·예산 등 가계부 설정 수정                | 가능   | 가능          | 불가   |
| 본인의 자산·카드 등록·관리                        | 가능   | 가능          | 가능   |
| 다른 참여 구성원의 자산 대리 등록                 | 가능   | 가능          | 불가   |
| 구성원 초대 · 초대 취소                           | 가능   | 가능          | 불가   |
| 관리자 지정·해제 (일반 구성원 ↔ 관리자)           | 가능   | 가능          | 불가   |
| 참여 중인 구성원 내보내기                         | 가능   | 일반 구성원만 | 불가   |
| 가계부 이름·아이콘 수정, 소유권 이전, 가계부 삭제 | 가능   | 불가          | 불가   |
| 참여하지 않은 다른 가계부 기록 열람               | 불가   | 불가          | 불가   |

- 생성자가 소유자가 되며 한 가계부의 소유자는 한 명이다. 관리자는 여러 명 지정할 수 있다.
- 소유자·관리자는 다른 참여 구성원의 자산을 대신 등록할 수 있다. 자산 소유자와 등록자를 구분해 기록한다.
- 고정 수입·고정 지출은 가계부 설정의 `고정 수입 · 지출` 탭에서 소유자·관리자·구성원(member) 모두 등록·수정·일시중지·삭제할 수 있다. 공동 분류·예산 수정 권한은 소유자·관리자만 가지며 구성원은 조회만 할 수 있다.
- 구성원·권한(구성원 관리) 및 미참여 인물 관리 화면에서 참여 구성원의 역할과 구성원·미참여 인물별 `세무 기록 설정`(`근로자` · `근로자의 부양가족` · `해당 없음`, 개인사업자)를 설정하며 미참여 인물의 이름 수정·삭제도 지원한다. 소유자가 다른 구성원을 소유자로 지정할 때 현재 소유자가 관리자로 변경됨을 경고하고 확인 후 소유권을 이전한다. 초대 대기 중인 사용자는 초대 취소를 제공한다. 개별 설정 권한 위임은 제공하지 않는다.
- 가계부 거래의 금액·분류 등은 모든 구성원이 수정할 수 있다.
- 소유권은 다른 참여 구성원에게 이전할 수 있으며 이전 후 기존 소유자는 관리자가 된다. 소유자와 관리자 모두 다른 구성원을 관리자로 지정·해제할 수 있으나(소유자 변경 및 본인 직접 해제 불가), 다른 관리자를 가계부에서 내보내는 것은 소유자만 가능하며 관리자는 일반 구성원만 내보낼 수 있다. 가계부 이름·아이콘 수정은 소유자 전용(`가계부 관리` 탭)으로 유지하며, 선택한 아이콘은 가계부 전환기(모바일 헤더·`전체` 시트·태블릿 레일·PC 사이드바)에 함께 표시한다.
- 새 구성원은 기존 가계부의 과거 기록을 볼 수 있다. 탈퇴한 구성원의 가계부 접근은 종료한다.
- 탈퇴해도 기존 공동 기록·합계는 유지한다.

### AUTH-03 삭제와 복구

- 가계부 삭제는 소유자만 실행할 수 있다. 삭제 중인 가계부에는 구성원이 접근할 수 없다.
- 삭제일부터 30일간 서비스 운영자에게 문의해 복구를 요청한다. 사용자용 직접 복구 버튼은 제공하지 않는다.
- 운영자는 요청자의 소유 권한을 확인하고 복구한다. 이를 위해 금융 상세를 열람할 필요가 없도록 설계한다.
- 30일 후 영구 삭제 대상으로 처리한다. 실제 삭제 작업과 백업 잔존·삭제 일정은 운영 설계에서 확정하며 즉시 모든 백업에서 제거된다고 표시하지 않는다.

## 4. 시작 설정·분류·예산

### INIT-01 시작월과 잔액

- 사용자가 시작 기준월을 선택하며 관리 범위는 그 달 1일부터다. 가입 시점의 현재 월뿐만 아니라 과거 임의의 월도 시작 기준월로 선택할 수 있으며, 가계부 설정에서 시작 기준월을 과거로 앞당기는 기능을 제공한다.
- 시작월을 현재 월로 지정할 때는 현재 실제 계좌 잔액을 입력해 첫 달 전월 이월금을 역산할 수 있다. 역산에는 **생활비에 포함으로 지정한 계좌와 현금만 포함**하며, 겸용 계좌의 미지불 의무(`지불 준비 필요·지불 대기`)는 차감한다. 반면 과거 월부터 시작하는 경우에는 과거 특정 시점의 실제 잔액 역산이 부정확하므로 사용자가 직접 이월금을 입력(또는 0원으로 시작)하는 것을 기본으로 한다.
- 계산 기준 시점은 항상 **시작월 1일 기준**이며, `지불 완료`·`입금 완료` 거래는 실제 잔액에 이미 반영된 것으로 간주하고 `지불 준비 필요·지불 대기`·`입금 예정`·`미회수`만 예정 입출금으로 가감한다. 월 중 가입 시 1일~가입일 거래를 입력하지 않았다면 사용자가 직접 이월금을 보정할 수 있다.
- 시작월의 거래와 진행 중인 고정지출·할부, 이미 준비한 금액, 기존 카드 납부 의무, 받을 돈을 함께 반영할 수 있어야 한다. 시작월 이전 승인 거래의 이번 달 납부액을 누락하지 않는다.
- 첫 달의 전월 이월금(시작금액)은 사용자가 직접 금액을 입력하거나 수정할 수 있으며, 입력 편의를 위해 현재 실제 잔액과 시작월 거래 자료를 바탕으로 한 '자동 역산(추천)' 기능을 제공한다.
- 자동 역산 시 산출된 시작금액은 분류별 예산 비율로 자동 배분되며, 사용자가 분류별 이월금을 자유롭게 수정할 수 있다. 음수 이월금도 허용하며 합계 일치를 검증한다.
- 잔액 대조의 완료·미완료 상태를 두지 않는다. 차이가 있어도 저장·사용할 수 있고 잔액 차이만 보여준다.
- 거래가 추가·수정될 때마다 시스템이 시작금액을 자동으로 변경하지 않는다. 시작월 중에는 사용자가 직접 분류별 이월금을 수정하거나 [현재 잔액 기준 자동 역산]을 다시 실행해 맞출 수 있다. 2번째 달부터는 전월 실제 잔액이 자동 이월되므로 시작금액 수정 및 역산 기능은 시작월에 한해 제공한다.
- 시작 설정에서 카드 등록·가져오기로 이동할 때 단계·초안·복귀 위치를 보존한다. 성공·취소·실패 후 원래 단계로 돌아오고 등록 결과를 연결한다. 모든 세부 자료 입력을 가입 조건으로 강제하지 않는다.
- 미입력 자료와 확인된 0원을 구분하고 계산에 포함한 자료 범위를 표시한다.

### BUD-01 한 단계 분류

- 가계부 생성 때 분류를 정하며, 가계부 설정에서 언제든 새 분류를 추가하거나 기존 분류명과 배치 순서를 수정할 수 있다. 추천 항목은 클릭으로 추가하고 직접 입력도 가능하다.
- 상하위 분류는 사용하지 않는다. 예를 들어 `생활/동물`은 단일 분류명이다.
- 분류명을 수정하면 과거, 현재, 미래 모든 월의 해당 거래 및 통계에 동일하게 일괄 반영되며, 활성 분류의 배치 순서(드래그 또는 위·아래 이동으로 설정)는 가계부 설정·거래 선택 목록·결산 표 등 분류 노출 순서에 공통 적용된다.
- 새 분류는 이름만 입력해 간편하게 추가할 수 있으며, 추가 시 기본 예산과 이미 생성된 월의 예산은 0원으로 등록된다. 이후 분류 목록에서 기본 예산을 입력하여 저장할 수 있으며, 가계부 설정의 분류 목록 하단에 기본 예산 총액을 표시한다. 월별 예산은 고정 수입·지출과 동일하게 아직 생성되지 않은 신규 월이 생성될 때만 기본 예산에서 복사되며, 이미 생성된 월의 예산은 기본 예산 변경과 분리된다(기생성 예정월은 `예정월 초기화`로 고정 항목·예산을 함께 초기화 후 재생성 가능).
- 연결된 거래(과거·현재·예정 지출·수입, 고정 거래, 할부)가 전혀 없는 분류는 완전 삭제할 수 있다.
- 거래가 있거나 사용 이력이 있는 분류는 완전 삭제 대신 비활성화로 처리하며, 다음 규칙을 따른다:
- 고정지출·고정수입 또는 미래 잔여 할부 회차가 연결된 분류는 비활성화를 차단하며, 선행 거래의 분류 변경이나 삭제를 안내한다.
- 현재 월 이후의 미래 월에 해당 분류로 등록된 거래(미래 지출 또는 예정 거래)가 1건이라도 존재하는 경우 비활성화를 차단하며, 미래 거래를 먼저 정리(삭제 또는 타 분류 변경)하도록 안내한다.
- 당월(현재 월) 지출 내역에는 지금까지 기록된 기존 거래를 그대로 인정·보존하되, 비활성화 이후부터는 해당 분류로의 신규 거래 추가 등록이 차단된다.
- 비활성화 시점에 해당 분류의 당월 최종 잔여액(`전월 이월금 + 당월 예산 - 당월 지출`)이 0원이 아닌 경우, 정산 대상 활성 분류를 지정하여 월별 예산 상계를 통해 최종 잔여액을 0원으로 맞춘 뒤 비활성화한다.
- 양수(+) 잔여액: 비활성화 분류의 당월 예산을 삭감(필요 시 음수 예산 적용)하고, 동일 금액을 대상 활성 분류의 당월 예산에 가산한다.
- 음수(-) 잔여액: 대상 활성 분류의 당월 예산에서 해당 금액을 차감하여 비활성화 분류의 당월 예산에 가산(충당)한다.
- 이 처리는 전체 총예산 합계와 전월 이월금 원본을 전혀 왜곡하지 않으면서 비활성화 분류의 익월 이월금을 0원으로 소멸시킨다.
- 비활성화된 분류는 가계부 설정의 기본 예산이 0원으로 자동 조정되고, 지출·수입 등록 및 파일 가져오기 등 신규 거래 선택 목록에서 제외된다. 과거 거래와 월별 통계는 그대로 보존된다.
- 가계부 설정 하단의 비활성 분류 목록에서 언제든 재활성화할 수 있다.

### BUD-02 기본 예산·월별 예산·이월

- 가계부에 접근 가능한 구성원이 로그인하면 가계부별로 현재 월부터 두 달 뒤까지의 월별 가계부가 준비됐는지 확인하고 없는 월만 생성한다. 예를 들어 11월 로그인 시 11월·12월·다음 해 1월을 준비한다. 가계부 설정이 끝나지 않았다면 초기 설정을 완료한 뒤 준비한다. 새 월을 처음 준비할 때는 등록된 활성 고정지출과 고정수입(반복 급여)을 해당 월의 예정 거래로 1회 자동 생성하며, 한 번 생성된 월에 대해서는 이후 고정 수입·지출 설정 변경을 이유로 거래를 재생성하거나 덮어쓰지 않는다.
- 여러 구성원이 로그인하거나 같은 요청을 반복해도 같은 가계부·월은 한 번만 생성한다. 기존 월의 예산·거래·이월을 덮어쓰지 않으며, 로그인하지 않은 기간의 누락 월은 다음 로그인 시 시작월 이후부터 순서대로 보완한다. 준비 범위 밖 월을 조회하거나 미래 거래를 기록하는 기능을 이 기간으로 제한하지 않는다.
- 분류별 기본 예산을 두고 새 월에는 해당 시점의 기본값을 적용한다. 기본 예산은 0 이상 정수만 허용한다.
- 월별 예산은 예상 수입·큰 지출 계획에 맞게 변경할 수 있다. 월별 변경이 기본값을 바꾸지 않는다. 월별 결산에서 선택한 월의 분류별 예산을 수정하며, 가계부 설정에서는 분류와 기본 예산을 관리한다.
- 월별 예산은 원칙적으로 0 이상 정수를 입력하되, 분류 간 잔여금 이관이나 비활성화 정산을 위해 음수(-) 금액을 허용한다. 단, 해당 분류의 당월 가용 잔여액(`전월 이월금 + 당월 예산 - 당월 지출`)이 0 미만이 되지 않는 한도 내에서만 음수 예산을 허용한다.
- 예산 반영월이 선택 월인 입금 완료·예정 수입의 실수령액을 합산해 해당 월 분류 예산 합계와 비교한다. 전월 이월은 비교에서 제외한다. 차이가 있으면 월별 결산 상단에 예산이 수입보다 얼마나 적거나 많은지와 `예산 수정` 버튼을 표시한다. 수입 기록이 없으면 차이를 계산하지 않고 예산 수정에서 수입 등록을 안내한다.
- `예산 수정` 모달에는 `예산에 반영할 수입`, 분류별 입력값과 `예산 합계`를 표시한다. 불일치 경고는 수입 금액 위에, `오차`의 제목과 부호 있는 금액(수입 − 예산)은 예산 합계 아래에 오류 색으로 표시한다. 오차가 0원이면 경고와 오차 행을 숨긴다. 유효한 예산을 저장할 때 오차가 남아 있으면 확인을 요청한다. 확인하면 저장하고, 취소하면 입력값을 유지한 채 모달에 남는다.
- 기본 예산 변경은 이미 생성된 월별 예산을 덮어쓰지 않는다.
- 현재 월과 미래 월에는 기본 예산으로 리셋하는 기능을 제공한다. 과거 월에는 제공하지 않는다.
- 리셋은 대상 월 예산만 바꾸고 거래·정산·이월금을 초기화하지 않는다.
- 남은 분류별 금액과 초과 지출에 따른 음수 금액은 다음 달에 이월한다. 연도 전환에도 같은 규칙을 따른다.

## 5. 계좌·카드·사람과 카드 조건

### PAY-01 결제수단·미참여 인물

- 카드·계좌에 소유자를 등록한다. 거래마다 소유자를 반복 입력하게 하지 않는다. 구성원은 본인을 포함해 등록된 이름으로 표시하며 목록·입력·정산 화면에서 일관되게 사용한다.
- 카드에는 청구 대금이 출금되는 `결제 계좌`와 준비금을 채워 보낼 출발 계좌인 `송금 계좌`를 등록 시 필수 연결하고 계좌별 준비금을 합산한다(결제 계좌와 같으면 동일 계좌로 지정). 가계부 설정의 자산·카드에서 자산·부채와 카드를 구분해 등록하고 표시명·소유자·연결 계좌(결제 계좌·송금 계좌)·조건 등 허용된 속성을 수정한다. 계좌는 자산현황과 같은 항목을 사용한다.
- 자산 사용 중지는 해당 자산의 수정 화면에서 진행한다. 잔액 또는 보유량이 0이 아니거나 카드 결제계좌·송금계좌, 고정 지출의 결제계좌, 고정 수입의 입금계좌로 등록된 자산은 사용 중지를 차단한다. 차단 사유별로 잔액 정리와 카드·고정 지출·고정 수입 연결 변경 또는 해제 안내를 표시한다. 카드 사용 상태와 무관하게 결제계좌·송금계좌 연결이 남아 있으면 차단하며, 저장 시 서버에서 잔액과 카드·고정 지출·고정 수입 연결을 다시 확인한다. 카드·계좌 사용 중지는 새 거래 선택과 과거 기록 보존을 구분한다. 거래·잔액·결제 준비·예정 거래 등 연결 관계를 확인하고 영향과 필요한 조치를 안내한다. 연결된 기록이나 잔액을 자동 삭제·변경하지 않는다. 그 밖의 연결 상태별 사용 중지 가능 조건과 잔액 처리 방식은 구현 전 확정한다.
- 카드 관리에는 설정과 관리 정보만 보여주고 사용 실적·단계별 달성 현황은 월별 결산에 표시한다.
- 지출 입력 시 선택할 수 있는 인물 목록에는 가계부 구성원을 기본 포함하고, 가입하지 않은 가족·친구는 '미참여' 인물로 등록해 추가할 수 있다.
- 미참여 인물 등록은 로그인·조회 권한을 부여하지 않는다. 미참여 지정만으로 받을 돈을 자동 생성하지 않는다.
- 미참여 인물의 이름 수정 및 삭제 정책은 다음과 같다:
- **이름 수정**: 이름을 변경하면 해당 미참여 인물이 지정된 과거 지출 내역 및 받을 돈(미정산) 기록의 이름도 함께 일괄 갱신된다.
- **삭제 및 과거 기록 보존**: 미참여 인물을 삭제하더라도 기존 지출 내역이나 받을 돈의 이름 기록은 문자열 스냅샷으로 그대로 보존되며 금융 데이터가 임의로 변경·삭제되지 않는다. 삭제 후에는 신규 지출 입력 목록에서만 제외된다.
- **삭제 전 경고**: 해당 미참여 인물로 등록된 과거 거래나 미정산 내역이 존재하는 경우, 연결된 내역 건수를 명시하고 기존 기록이 유지된다는 점을 사용자에게 고지한 뒤 삭제 확인을 받는다.
- 미참여 인물이 추후 가계부 구성원으로 초대·가입할 때의 데이터 동기화(연결·통합)를 지원한다:
- 구성원 초대 시 기존 미참여 인물 중 연결할 대상을 지정하거나, 가계부 설정의 미참여 목록에서 특정 구성원 계정과 연결할 수 있다.
- 연결 시 해당 미참여 인물로 등록되어 있던 과거 모든 지출 기록 및 받을 돈(미정산액) 상대방 정보가 해당 구성원 계정으로 일괄 승계·통합된다.
- 통합 완료 후 별도의 미참여 명칭은 목록에서 제거되어 단일 구성원으로 표시된다.
- 사람과 결제수단 변경이 과거 명의·사용 관계를 지우지 않도록 기록한다.

### CARD-01 카드 선택·AI 탐색·공용 검수

1. 사용자는 등록된 공용 카드에서 상품을 선택한다.
2. 없는 카드는 카드사·상품 정보를 입력해 AI가 공식 자료를 찾아 정리하도록 요청한다.
3. 사용자가 상품명·발급사·버전·공식 링크 등으로 본인이 등록할 카드와 일치하는지 먼저 확인한다.
4. 확인한 카드는 개인용으로 사용하고 AI가 찾은 조건으로 실적을 계산할 수 있다.
5. 찾지 못했거나 애매한 조건은 확정값으로 만들지 않고 운영자 검수 대상으로 표시한다.
6. 공용 카드 조건은 운영자가 검수한 뒤 제공한다. 사용자 확인은 상품 식별이며 공용 조건 검수를 대신하지 않는다.

- 공식 자료의 출처·확인일·조건 버전을 기록한다.
- 개인 설정이 공용 조건과 다르면 별도 개인용 카드로 저장한다. 공용 정보를 덮어쓰거나 개인 설정을 공용 카드 조건으로 자동 등록하지 않는다.
- 공용 조건이 나중에 바뀌어도 개인 조건·과거 계산을 조용히 덮어쓰지 않는다. 버전 적용 절차는 상세 설계 항목이다.
- 카드 등록은 상품 선택, 조건 확인, 내 카드 설정 순서로 제공한다. 카드사를 먼저 선택하고 해당 카드사의 상품을 검색하며, 목록에 없는 카드사는 직접 입력할 수 있다. 상품 선택 화면에서 체크·신용 종류와 버전을 구분하고 공용 상품 검색과 선택한 카드사에서 찾은 AI 탐색 결과를 보여준다.
- 조건 확인 화면은 실적 기간·제외 항목·할인 거래 및 할부 실적 조건, 혜택 단계·한도, 출처·확인일·검수 상태와 미확정 항목을 보여준다. 실적 제외 항목은 관리비·공과금·세금·보험·교육·상품권·교통·금융비용 등 세부 항목별 체크박스로 선택하고, 목록에 없는 조건은 직접 추가한다. 실적 제외와 혜택 제외는 별개이며 AI가 확인하지 못한 조건은 미확정으로 표시한다. 실적 단계는 상품별로 여러 개를 표시하며 단계별 기준 금액·혜택·한도를 확인하고 추가·수정·삭제할 수 있다. 월별 결산에는 별도의 목표 선택 없이 확인된 모든 실적 단계의 달성 여부와 부족액을 보여준다. 사용자가 변경한 조건은 개인 조건으로 보존한다.
- 내 카드 설정은 소유자·표시명·카드번호 마지막 4자리·연결 계좌(`결제 계좌`·`송금 계좌` 필수)를 기록한다. 체크·신용카드 모두 마지막 4자리는 필수이며 공백·문자·4자리 미만/초과 입력은 저장을 막는다. 앞자리 0을 보존하는 문자열로 저장하고 전체 카드번호·유효기간·CVC는 입력받거나 저장하지 않는다. 목록에 표시명과 마지막 4자리를 함께 보여주고 수정 시에도 검증한다. 마지막 4자리는 중복될 수 있으므로 유일성 제약을 두지 않으며 거래 연결에는 내부 카드 ID를 사용한다. 번호 정정만으로 기존 거래 연결을 변경하지 않는다.
- 신용카드는 결제일을, 체크카드는 일반 출금계좌와 필요 시 후불교통 출금계좌·출금일을 표시한다. 발급일은 필요한 경우 입력한다.
- 월별 결산의 카드 현황에서 카드사·카드의 결제일에 대응하는 청구 대상 기간을 사용한다. 결제일만으로 실제 청구기간과 청구액을 확정하지 않는다. 체크카드의 일반 결제는 별도 결제 준비 대상으로 취급하지 않으며 후불교통은 별도 출금 가능성을 유지한다.

### CARD-02 실적 계산

- AI는 조건을 추출하고 프로그램이 금액을 계산한다.
- 예정 고정지출을 포함한 실적과 각 단계의 기준 금액·달성 여부·부족액을 보여준다. 사용자는 이를 보고 평소 사용할 카드를 판단한다.
- 할부 실적은 첫 달 전체 승인금액 인정 또는 월별 납부액 인정 등 카드 조건을 적용한다.
- 세금 등 제외 대상, 할인받은 거래 전체 제외·할인액만 제외·전액 인정 조건을 구분한다.
- 현재 사용 카드의 집계는 매월 1일~말일이다. 전체 카드 상품의 보편 정책으로 단정하지 않고 공식 조건을 기록한다.
- 조건 미확정으로 결과가 불완전하면 해당 사유를 표시한다. 모르는 조건을 확정한 것으로 계산 완료 표시하지 않는다.

## 6. 지출·분할·예정 거래

### EXP-01 거래 입력

- 지출 기록·수정에는 예산 반영월 입력을 두지 않는다. 일반 지출은 거래일, 예정 고정지출은 예정일의 월을 반영월로 저장한다. 신규 할부는 현재 선택한 지출 내역 월이 입력 회차의 반영월이며, `다른 회차의 월 = 선택 월 + (대상 회차 번호 − 입력 회차 번호)`로 자동 계산한다. 원승인일은 별도로 보존하고 기존 할부 수정은 저장된 회차 반영월을 유지한다.
- 금액 수정·환불·취소는 원거래 반영월에서 보정한다. 일반·고정 지출의 날짜를 사용자가 직접 바꾼 경우에만 새 날짜의 월로 이동하며 양쪽 월의 예산·이월 영향이 반영된다. 변경 없이 기존 기록을 열거나 금액만 고칠 때 임의로 월을 이동하지 않는다. 자동 산정된 반영월은 미리보기·저장 결과에서 확인할 수 있고 수입의 예산 반영월 입력은 유지한다.

- 카드·현금·직접 계좌이체 지출을 수동으로 입력·수정한다. 계좌이체는 결제수단에서 등록된 출금 계좌를 이름으로 선택하고 거래에 연결한다. 사용 중지된 계좌는 새 거래에 선택할 수 없으며 기존 거래의 연결은 유지한다.
- 거래의 날짜, 결제수단, 금액, 분류와 필요한 사용처·메모·실사용자·정산 정보(카드 결제 시 할인 포함)를 기록한다. 사용처와 별도로 상세내역을 선택 입력하며 비워두어도 저장할 수 있다. 입력한 상세내역은 지출 목록과 수정 화면에서 확인한다.
- 소유자 참조·카드 조건 등은 자동 적용하고 예외만 수정하게 한다. 기존 Y/N 열 전체를 반복 입력하게 하지 않는다.
- 실사용자는 신규 기록 시 결제수단 소유자로 기본 지정한다. 카드·계좌·현금 등 결제수단을 변경할 때마다 수동 지정 이력과 관계없이 새 수단의 소유자로 자동 변경하며, 이후 실사용자를 직접 수정할 수 있다. 실제 결제수단 변경이 없는 기존 거래 조회·수정 진입에서는 저장값을 유지한다. 실사용자 자동 변경만으로 소유자·회수 상대·회수 대상 금액·입금 기록을 변경하지 않는다.
- 생활비 반영 금액, 승인금액, 카드사 할인(카드 결제에 한해 입력), 청구·납부 금액을 구분하며 미래 세무 집계용 원거래 사실을 보존한다.
- 모든 최종 등록 거래는 분류가 있어야 한다. 분할 거래는 각 분할의 분류가 필요하다.
- 지출 추가·수정에서 `지불 준비 필요`(미확보·미지불), `지불 대기`(금액 확보·미지불), `지불 완료`(실제 지불 완료)를 선택하고 목록에 표시한다. 현금·직접 계좌이체는 입력한 거래일이 오늘 또는 과거이면 지불 완료, 미래이면 지불 준비 필요를 기본값으로 제안한다. 카드는 승인일만으로 완료 처리하지 않으며 결제 계좌와 송금 계좌가 같으면 지불 대기, 다르면 지불 준비 필요를 제안한다. 사용자가 폼에서 직접 선택한 상태는 날짜나 결제수단을 바꿔도 유지한다. 기존 기록을 열 때는 저장된 상태를 유지하며 거래일을 변경한 경우 직접 상태를 선택하지 않았다면 해당 날짜의 기본값을 제안한다. 현금·직접 계좌이체의 지불 준비 필요에는 송금 계좌를 표시한다. 상태 선택만으로 계좌 잔액을 변경하지 않는다.
- 지불 관리에서 거래를 선택해 확보를 기록하면 지불 대기가 된다. 같은 계좌에서는 실제 이체 없이 확보를 확인한다. 지불 대기·지불 완료 등 다음 단계로 전환하는 확인 화면에서는 계좌 잔액 반영을 기본으로 선택하며, 사용자가 해제하면 지불 상태만 변경한다.
- 지불 대기에서 지불 준비 필요로 되돌릴 때도 기본값은 지불 상태만 변경하며, 별도 계좌·현금에서 반환이 이루어진 경우 계좌 잔액 반영을 선택해 반환 계좌를 지정할 수 있다. 계좌에 남아 있는 준비금은 계좌별 보정 금액 수정으로 관리한다. 지불 상태와 금액·결제수단은 각각 변경한다. 지불 완료 거래의 금액·결제수단을 수정하거나 지불 대기·지불 완료 거래를 삭제하기 전에 실제 지불·준비 내역을 확인하고 상태를 정정한다(`지불 준비 필요` 상태이면서 회수 입금 이력이 없는 거래와 할부 1회차 외의 지불 대기·지불 완료·할부 2회차 이후 거래는 직접 삭제 불가).
- 과거 거래를 가져올 때의 지불 상태는 가져오기 흐름의 확인 기준을 따른다. 수동 입력의 기본값은 결제수단과 거래일로 제안한다.
- 수정 화면은 상세내역·예산월·원승인금액·할인(카드 결제에 한함)·분류 분할·실사용자·받을 돈을 그대로 불러온다. 바꾸지 않은 값을 신규 입력 기본값으로 덮어쓰지 않는다.
- 변경 전후 생활비·준비금 조정·실적·미수금·이후 이월의 영향을 확인한다. 취소하면 원본을 유지하고 오류 시 입력 초안을 보존한다.

### EXP-02 한 결제의 분류별 분할

- 기본은 분류 하나이고 필요하면 하나의 원거래 안에서 여러 분류로 나눈다. 분류 항목을 추가·삭제하며 한 항목만 남으면 단일 분류로 처리한다. 카드 결제 시에는 분류가 하나여도 전체 금액·할인 금액을 표시하고 상단에 입력한 금액과 할인 금액을 기준으로 자동 반영하며, 계좌이체·현금은 할인 입력 UI와 자동 배분 버튼을 숨기고 할인을 0원으로 처리한다(결제수단을 카드에서 계좌이체·현금으로 바꾸면 입력된 전체·분류별 할인을 0원으로 초기화한다).
- 추가된 모든 분할 항목은 분류와 0원보다 큰 금액을 입력해야 한다. 분할금액 합계는 전체 결제금액과 같아야 한다. 분류 미선택이나 금액 합계 불일치 시 저장을 막고 수정할 항목 또는 차액을 안내한다.
- 카드 결제의 일시불 거래에서는 사용자가 분류별 할인액을 직접 입력하거나 자동 배분 버튼을 눌러 분할 전 금액 비율로 배분할 수 있다. 유이자 · 부분 무이자 할부 거래에서는 분류별 원금과 이자·수수료를 각각 나누어 입력하거나 자동 배분 버튼으로 원금 비율에 따라 이자·수수료를 배분할 수 있으며, 무이자 할부와 계좌이체·현금은 추가 배분 열과 자동 배분 버튼을 숨긴다. 자동 배분은 버튼을 눌렀을 때만 수행하고 정수 원 단위 잔여를 처리한다. 기존 배분값은 다른 입력 변경 시 임의로 덮어쓰지 않는다. 각 할인액은 0원 이상 해당 분류 금액 이내이며 합계는 카드사 할인 총액과 같아야 하고, 각 이자·수수료는 0원 이상이며 합계는 이번 회차 이자·수수료와 같아야 한다. 조건에 맞지 않으면 저장을 막고 오류를 안내한다. 직접 수정한 배분은 다시 조회·수정할 때 보존한다.
- 상품 자체 할인은 이미 결제금액에 반영된 것으로 취급한다. 별도의 상품 할인 입력 기능을 추가하지 않는다.
- 실적·준비금·파일 대조는 원거래 한 건 기준으로 처리하고 분류별 통계만 분할 기준으로 집계한다.
- 예: 100,000원을 80,000원·20,000원으로 나누고 카드사 할인 5,000원이 있으면 할인 4,000원·1,000원, 순액 76,000원·19,000원이다.
- 원 단위 잔여의 배분 순서와 부분 취소·할부·정산이 결합한 분할 보정은 구현 전 계산 설계 대상으로 남긴다. 사용자 확인 없이 기존 분류 배분을 임의로 바꾸지 않는다.

### EXP-03 고정지출

- 매월 반복할 고정지출(내용, 분류, 결제수단, 실사용자, 매월 예정일, 적용 시작월, 기본 예정 금액)은 `가계부 설정 > 고정 수입 · 지출`에서 등록·수정·일시중지·삭제한다. 소유자·관리자·구성원 모두 편집할 수 있으며, 정렬 때문에 거래일을 1일로 바꾸지 않는다.
- 아직 생성되지 않은 미래 예정월(현재 월 기준 최대 2개월 후까지)로 이동할 때는 바로 생성하지 않고 생성 예정 건수(고정 수입·고정 지출·기반영 할부 회차)를 안내하는 확인 모달을 거쳐 사용자가 확정할 때만 생성한다. 2개월을 초과하는 미래 월은 예정월로 생성할 수 없다. 생성 시 활성 고정지출(해당 월 >= 적용 시작월) 기준으로 예정 거래가 1회 자동 생성되어 생활비와 카드 실적에 선반영된다(결제 계좌와 송금 계좌가 다른 카드는 `지불 준비 필요`, 그 외 동일 계좌 카드·계좌이체·현금은 `지불 대기`). 이미 생성된 월을 다시 열거나 조회할 때는 삭제·수정된 건을 재생성하지 않는다.
- **고정지출 설정과 월별 내역의 완전 분리**:
- `가계부 설정 > 고정 수입 · 지출`에서 고정지출을 수정·일시중지·재개·삭제하더라도 **이미 생성된 월(과거·당월·기생성 미래 월)의 예정 거래를 자동으로 덮어쓰거나 삭제하지 않으며, 앞으로 새로 생성되는 신규 월부터만 변경 내용을 적용한다.**
- 이미 생성한 미래 예정월을 최신 고정 설정으로 다시 만들고 싶을 때는 해당 예정월 상단의 `예정월 초기화`로 미완료 고정 수입·지출만 삭제하고 미생성 상태로 되돌려 재생성할 수 있다. 이때 할부 회차·직접 입력한 거래·완료(`지불 완료`/`입금 완료`) 처리된 내역은 삭제하지 않고 보존한다.
- 신규 고정지출을 **최초 추가**할 때만 사용자가 필요에 따라 `현재 조회 중인 월(시작월 이상일 때)에도 지금 바로 1건 추가` 옵션을 선택해 당월 내역에 즉시 반영할 수 있다.
- `지출 내역`이나 `카드 파일 가져오기`에서 이미 생성된 월의 예정 거래 금액·결제수단·날짜·상태를 보정하거나 삭제해도 **해당 월의 그 거래 1건만 변경**되며, 가계부 설정의 고정지출이나 다른 월의 거래는 바뀌지 않는다. 실제 청구 금액이 예정 금액과 다르면 별도 지출을 중복 등록하지 않고 해당 월의 원거래를 보정하며, 매 건 결제 확인 버튼을 필수 업무로 추가하지 않는다.

### EXP-04 할부

- 지출 기록에서 전체 승인금액 다음에 납부방식으로 일시불 또는 할부를 선택한다. 할부라면 할부 유형(`무이자` · `유이자 · 부분 무이자`), 전체 개월 수(2~36개월), 이번 회차 번호를 입력한다. `이번 회차 총 납부액`은 입력란이 아닌 자동 계산 요약으로 표시되며, `무이자`일 때는 `이자·수수료` 입력란과 분류별 이자 열을 숨기고 할인 후 승인금액을 개월 수로 나눈 금액(원 단위 나머지는 첫 회차에만 합산)이 자동 계산되며 `이번 회차 납부원금` 기준으로 분류별 금액을 배분한다. `유이자 · 부분 무이자`를 선택하면 `이번 회차 납부원금`과 `이번 회차 이자·수수료`를 분리 입력받아 합계(`이번 회차 총 납부액`)를 실결제·생활비 기준으로 자동 계산하고, `분류별 금액`에서는 `이번 회차 납부원금`과 `이자·수수료`를 각각 분할 배분(원금 비율 자동 배분 지원)하며 남은 원금은 납부원금 기준으로만 차감한다. 현금이나 직접 계좌이체에는 할부를 적용하지 않는다.
- 저장 시 이번 회차부터 마지막 회차까지의 월별 예정 회차 거래를 생성해 원거래(할부 원부)와 연결한다. 600,000원 3개월 할부는 생활비·준비액에 월 200,000원씩 반영한다. 첫 달 전체 실적 인정 카드라면 실적은 첫 달 600,000원(1회차 기준), 이후 0원이다.
- 회차 목록·표에는 실제 카드 결제일과의 혼동을 막기 위해 `예정일`을 노출하지 않고 `반영월`만 표시하며, 원승인일은 별도로 보존한다. 특정 회차의 `이번 회차 납부원금`을 수정하면 이전 회차와 이미 `지불 대기`·`지불 완료` 상태인 회차의 원금을 제외한 잔여 원금을 남은 `지불 준비 필요` 회차 수로 균등 재계산(원 단위 나머지는 첫 잔여 회차 합산)하며, 잔여 원금 초과 입력은 저장을 차단한다.
- **할부 수정 잠금 및 연동 범위**:
  - `1회차`이면서 타 회차에 `지불 대기`·`지불 완료` 내역이 없는 경우에는 `결제 수단`, `결제 금액`, `할인 금액`, `납부방식`, `개월 수`, `회차`, `할부 유형`, `납부원금`, `이자·수수료`를 모두 수정할 수 있으며, 변경 시 2회차 이후와 `지출 내역`·`지불 관리`·`결산`에 함께 반영된다(일시불 전환 시 잔여 회차 및 할부 목록에서 제외).
  - `2회차 이후` 회차이거나 타 회차 중 `지불 대기`·`지불 완료` 상태가 존재하는 경우에는 `결제 수단`·`결제 금액`·`할인`·`납부방식`·`개월 수`·`회차` 수정을 잠그고 사유를 안내하며, `할부 유형`과 `지불 완료`가 아닌 회차의 `납부원금`·`이자·수수료`만 수정할 수 있다. `지불 대기` 회차의 금액이 바뀌면 해당 결제계좌의 차액 조정금에 반영하며, `지불 완료` 회차는 지불 상태를 먼저 되돌린 뒤 수정한다.
- 이후 회차 납부액은 이자와 카드사 청구 방식에 따라 달라질 수 있으므로 승인금액을 개월 수로 나눈 값을 확정 청구액으로 표시하지 않는다. `할부 현황(installments)` 화면에서 다음 기능을 제공한다(전용 추가 버튼이나 상단 지불 관리 이동 버튼 없이 관리 전용 뷰로 제공하며, 신규 할부는 전역 `지출 추가`에서 납부방식을 `할부`로 선택해 등록한다):
- **월별 할부 청구 예정·진행 현황**: 할부 현황는 상단 월 선택기와 기간 필터를 두지 않고 전체 기간 기준으로 조회한다. 상단 2열 요약(`진행 중인 할부(건수 및 남은 회차·청구 개월 수)`·`남은 청구 예정 합계`) 바로 아래에 `월별 할부 청구 예정` 세로 아코디언(기본 상위 4개월·이번 달 인라인 펼침, 5개월 이상 더보기; 각 행은 `사용처 + 회차` / `지불 상태 배지 + 상세 내역(memo)` / 우측 `금액 ›` 구성으로 클릭 시 회차 수정으로 이동)을 배치한다. 하단 `할부 내역`은 별도 상태 탭 없이 내역 검색·결제 수단 필터로 진행 중 원거래 아코디언 카드를 조회하고(접힘 요약: 사용처·상세 내역(`memo`)·결제 수단·개월 및 할부 유형·진행 바·남은 납부액·다음 청구 예정; 펼침 시 회차 행 클릭 상세 수정과 `조기 완납`·`할부 삭제` 제공), 최근 3개월 내 완료·조기 완납(또는 미지불 선결제 포함) 건이 존재할 때만 하단 `최근 완료 · 조기 완납` 섹션을 조건부로 노출한다(3개월 초과 완료 건은 월별 `지출 내역`에서 조회).
- **조기 완납(일시불 선결제)**: 남은 미지불(`지불 준비 필요`) 회차를 지정 예산 반영월(기본 현재 월)의 단일 선결제 거래로 합산 정리하고, 실제 선결제 금액(수수료 감면/추가 반영)과 지불 상태를 선택한다. 기존 `지불 준비 필요` 미래 회차는 제거하고 할부 상태를 완료 처리하며, 승인월에 이미 전체 승인금액으로 카드 실적이 반영된 경우 조기 완납 거래는 카드 실적을 중복 합산하지 않는다. 남은 회차에 `지불 대기`나 지출금 회수(정산) 내역이 연결된 경우 먼저 정리하도록 차단한다.
- **할부 삭제**: 모든 회차가 `지불 준비 필요` 상태이고 지출금 회수 내역이 연결되지 않은 할부만 원거래와 회차를 일괄 삭제한다. `지불 대기`·`지불 완료` 회차나 회수 내역이 연결된 경우 먼저 정리하도록 차단한다.
- 입력 회차 이전의 월도 역산할 수 있으나 역산만으로 과거 회차를 새 지출로 추가하지 않는다. 입력 회차부터 남은 예정 회차의 생성 범위를 유지해 기존 과거 내역과 중복되지 않게 한다.
- 장기 반복 납입을 전부 카드 할부로 추정하지 않는다.

### EXP-05 결제 캡처·글 기반 입력 보조 (MVP)

- 지출 기록 상단에 선택형 AI 입력 보조를 제공한다. 사용자가 직접 첨부하는 결제 문자·앱 알림·카드 앱 단건 내역 캡처와 직접 작성한 설명을 입력받는다. PC에서 이미지 붙여넣기·파일 선택·끌어놓기를 지원한다. 이미지는 PNG/JPEG/WebP 한 장, 10MB 이하로 시작하며 복수 거래·복수 이미지 일괄 등록과 문자·알림 자동 수집은 제외한다. 여러 거래가 보이면 한 건을 확인하거나 해당 거래 영역으로 다시 올리게 한다.
- 날짜·사용처·승인금액·할인·등록 결제수단과 분류별 금액 등 원문에 근거가 있는 내용만 구조화된 초안으로 제안한다. 승인금액·누적 이용액·결제예정액·취소금액을 구별하고 불분명한 값은 미확인으로 둔다. 가맹점만 보고 분류를 확정하거나 카드사 이름·마스킹 번호만으로 등록 카드를 임의 선택하지 않는다. 후보를 선택하거나 수동 입력한다. 실사용자·회수 상대·지급 상태·카드 조건을 원문에 없는데 추정하지 않는다.
- 해석 요청은 현재 가계부의 필요한 활성 분류·결제수단 정보와 최소 원문만 사용한다. 모델 출력은 허용된 필드만 수용하고 권한·계산·저장 명령으로 실행하지 않는다. 금액은 정수로 검증하며 지출 반영월은 기존 날짜·할부 규칙으로 정한다.
- 원문/첨부 미리보기와 현재 입력·제안 값, 분류·금액 변경을 대조한 뒤 사용자가 폼 반영을 확정한다. 기존 수동 입력을 자동 교체하지 않는다. 잠긴 금액·결제수단·할부 회차는 기존 수정 제한을 유지한다. 결제수단 변경을 반영하면 실사용자도 소유자로 변경됨을 안내하고, 회수 내역은 유지한다.
- 폼 반영은 거래 저장이 아니다. 직접 수정하고 모든 분류·금액·할인 합계·권한·버전 검증을 통과해 지출 저장을 눌러야 기록된다. 해석 전후와 검토·실패·취소 상태에서 예산·실적·잔액·기존 거래를 변경하지 않는다. 결과를 기다리는 동안 폼·원문이 바뀌거나 다른 거래로 이동하면 오래된 결과를 적용하지 않는다.
- 기존 분류별 할인 입력은 유지한다. 새 분류의 할인이나 불명확한 배분은 미입력으로 두며 사용자 입력 또는 기존 할인 자동 배분 버튼의 명시적 실행으로만 채운다. 초안 생성으로 할인 자동 배분을 실행하지 않는다.
- 기존 수동 입력·캡처·카드 파일 거래와 중복 후보를 확인한다. 날짜·사용처·금액·카드 등이 유사한 기록을 제시하고 사용자 확인 없이 병합·삭제·중복 제외하지 않는다. 캡처로 저장한 거래도 후속 카드 파일 대조 대상이며 동일 거래를 새 지출로 중복 확정하지 않도록 기존 연결 흐름을 사용한다.
- 요청 중·초안·실패·시간 초과·재확인 상태를 표시한다. 실패·취소 시 원문과 기존 폼을 유지하고 재시도·수동 입력을 제공한다. 사용자 지우기·저장 완료·화면 종료 시 임시 원본·첨부를 폐기한다. 제공사·전송/보관 조건·마스킹·동의·요청량/비용 한도·인식 정확도와 복귀 흐름은 MVP 출시 전 검증한다. 원본은 DB·로그·백업에 남기지 않고 확정 거래만 암호화해 저장한다.
- 화면설계서는 이미지 첨부를 브라우저 메모리에서만 미리보기하고 합성 초안을 사용한다. 실제 이미지·사용자 문장 해석이나 외부 LLM 호출을 수행한 것처럼 표시하지 않는다.

## 7. 카드 파일 가져오기와 대조

### IMP-01 입력 범위

- 이용·승인내역 파일은 새 거래 등록에, 결제예정·청구내역 파일은 기존 거래 대조와 납부액 보정에 사용한다.
- 카드 파일만 지원한다. 은행 잔액·수입·이체·정산은 수동 입력한다.
- 지원 카드·확장자·다운로드 경로·파일 크기·행 수·암호 파일 처리 범위는 실제 표본으로 확정한다. 모든 카드 파일을 지원한다고 안내하지 않는다.

### IMP-02 등록 흐름

1. 대상 카드와 파일을 선택한다. 파일에 카드사와 마지막 4자리가 있으면 등록 카드의 연결 후보를 제시하고 확인한다. 자료에 있는 상품·소유자 정보를 보조로 활용한다. 번호 누락·부분 마스킹·복수 후보는 사용자가 선택하며 번호만으로 자동 확정하지 않는다.
2. 프로그램이 파일을 읽고 AI가 열 의미·거래 범위·승인·취소·할부 표현을 해석한다. 수식·매크로·AI 생성 코드는 실행하지 않는다.
3. 프로그램이 원본 값으로 거래를 변환하고 날짜·금액·부호·통화·합계·누락·중복 후보를 검증한다.
4. 신규 거래, 기존 예정·할부와의 연결 후보, 금액 보정·취소 후보를 미리 보여준다.
5. 사용자가 모호한 연결과 변경을 확인하고 모든 등록 대상 거래의 분류를 선택한다. AI 추천은 수정 가능하다.
6. 사용자 확정 후 거래를 등록하거나 기존 거래를 보정한다. 분류 없는 거래는 최종 등록하지 않는다.
7. 원본 파일·임시 사본을 폐기하고 확정 거래 및 필요한 출처 메타데이터만 유지한다.

- 행별로 기존 거래 연결·신규 등록·이번 반영 제외를 선택한다. 제안한 연결을 거절할 수 있고 신규로 바꾸면 해당 거래의 분류를 지정한다.
- 제외 행은 등록·계산하지 않는다. 실제 등록 대상은 모두 분류가 필수이며 영구 미분류 보관함은 만들지 않는다.
- 확정 전 신규·연결 보정·제외 건수와 금액을 요약한다. 선택한 반영 묶음은 전체 반영 또는 전체 미반영으로 처리한다.
- 동일 작업번호로 확정 결과를 재조회해 응답 유실에 따른 중복 등록을 방지한다. 통신 오류만으로 미반영을 단정하지 않는다. 임시 자료 만료 시 재선택을 안내하되 확정 거래와 작업 결과는 유지한다.

### IMP-02A 구조 해석과 추천의 효율화

- 파일의 필요한 구조 표본만 AI에 전달하고 날짜·금액·부호·통화 추출과 계산은 프로그램에서 검증한다. 표본을 고정된 상단 15행으로 제한하지 않으며, 복수 시트·다중 거래표·합계 행·누락 가능성을 확인한다.
- 검증된 동일 파일 양식의 열 매핑을 재사용할 수 있으나 매번 필수 열·형식·거래 범위를 확인한다. 구조가 다르면 재매핑하거나 지원 불가를 안내한다. 코드로 파싱한다는 이유만으로 의미 해석과 등록 정확성을 보장하지 않는다.
- 가맹점 분류 이력은 해당 가계부의 현재 활성 분류와 사용자가 확인한 규칙 안에서 후보 추천에 재사용한다. 여러 품목을 파는 사용처나 모호한 내역은 사용자의 확인을 받는다. 분류 캐시도 민감 정보 정책과 가계부 접근 경계를 따른다.
- 중복 가맹점의 추천 요청은 줄일 수 있으나 같은 가맹점의 실제 거래 행은 제거하거나 합치지 않는다.
- 음수 금액만으로 승인 취소를 확정·상계하지 않는다. 원거래·부분 취소·환급 등 연결과 의미를 확인한다.
- 기존 수기 거래와 연결할 때 분류·분할·상세내역·메모를 보존하며, 최종 청구액 등의 금액 보정은 차이와 후속 영향을 보여주고 사용자 확정 후 반영한다.

### IMP-03 중복·해외 결제·월 경계

- 같은 날짜·금액·사용처라는 이유만으로 자동 병합하지 않는다. 실제 별도 결제일 수 있다.
- 결제예정 파일에 없는 거래를 자동 취소·삭제하지 않는다. 전표 매입 전 거래일 수 있다.
- 해외 결제의 승인 금액·원통화와 최종 원화 청구액은 구분해 보존한다. 환율·수수료 차이로 최종 금액이 바뀌면 원거래를 보정한다.
- 월을 넘겨 금액이 확정돼도 원래 거래의 반영월에서 금액을 보정하고 이후 이월금을 재계산한다. 당월 새 지출로 다시 만들지 않는다.
- 이미 준비한 거래라면 차액을 다음 준비금 처리에 연결한다.
- 읽기 실패·시간 초과·취소 시 기존 확정 기록은 유지하고 미확정 변경은 반영하지 않는다. 원본은 보관하지 않으므로 재시도 시 다시 선택하게 할 수 있다.

### IMP-04 표준 양식 일괄 업로드

- 과거 기록 이관 및 대량 거래 입력을 위한 표준 템플릿(CSV, Excel `.xlsx`) 다운로드 및 업로드 기능을 제공한다.
- 템플릿 열은 거래일자(필수), 유형(수입/지출, 필수), 금액(정수 원 단위, 필수), 분류(필수), 결제수단·귀속자(필수), 사용처(선택), 상세내역(선택), 메모(선택), 실사용자(지출 대상: 구성원·미참여, 선택)로 구성된다.
- 템플릿 내 미등록 분류나 결제수단이 포함된 경우, 업로드 확인 화면에서 신규 항목 자동 생성(결제수단은 소유자 지정 필수) 또는 기존 등록 항목과의 1:1 매핑을 선택할 수 있다. 소유자가 확인되지 않은 거래·수입·결제수단은 등록을 차단한다.
- 등록 시점의 현재 월보다 이전인 과거 거래는 '지불 완료' 상태로 등록되어 현재 월의 결제 준비 필요액에 가산되지 않는다.
- 필수값 누락이나 형식 오류가 있는 행은 오류 위치를 구체적으로 안내하고, 오류 행을 제외하고 정상 행만 등록하거나 전체 등록을 취소할 수 있다.
- 확정된 거래 데이터만 암호화하여 저장하며, 업로드된 원본 파일 및 임시 사본은 처리 완료 즉시 폐기한다.

## 8. 준비금·자산현황과 실제 잔액

### 계좌 구성과 생활비 대조

- 설정에서 자산과 카드를 구분해 관리하고, 자산은 사용자가 선택한 구분별로 등록·수정·사용 중지한다. 계좌는 자산현황에서도 같은 항목으로 조회하며 합계에 한 번만 포함한다.
- 한 계좌를 생활비와 카드 결제에 함께 사용할 수 있다. 생활비에 포함할 계좌와 카드별 결제 계좌를 지정하며 계좌 용도를 하나로 제한하지 않는다.
- 카드의 결제 계좌와 송금 계좌가 다르면 실제 이체 후 지불 대기로 기록한다. 두 계좌가 같은 카드는 지출 입력 시 바로 지불 대기로 기록하며 별도 이체 준비를 요구하지 않는다. 실제 지불을 확인하면 지불 완료로 변경한다.
- 생활비 범위에 포함된 결제 계좌에서는 아직 지불하지 않은 의무를 한 번씩 제외한다. 지불 완료 금액이 이미 실제 잔액에 반영됐다면 다시 빼지 않는다. 부분 출금액은 MVP에서 추적하지 않으므로 실제 잔액과 장부 잔액에 차이가 생길 수 있다.

### FUND-01 거래 단위 선택 처리

- 기본 조회에서 `지불 준비 필요`·`지불 대기` 탭은 `기간` 필터(`전체` / `이번 달만` / `이전 달만`), `내역 검색`, `결제 계좌`·`결제 수단` 다중 선택(`전체` 옵션 포함)을 제공하며, 모바일에서는 `상세 검색` 바텀 시트로 제공한다. `지불 완료` 탭은 선택한 조회 월의 내역만 표시하며 기간 필터를 노출하지 않는다. 여러 계좌를 함께 처리할 때 준비 조정과 지불 준비 금액은 계좌별로 구분하며, 상태 변경 시 계좌 잔액 반영 여부도 계좌별로 선택한다. 거래가 `0건`일 때는 하단 선택 액션 바를 노출하지 않으며, 상단에서 `자산 현황 보기`로 바로 이동할 수 있다.
- 지불 준비 필요 목록과 함께 `계좌별 지불 준비 현황` 섹션(금액 이동이나 현금 마련이 필요한 계좌·현금별 `거래 합계`, `보정 금액`, `지불 준비 금액`만 집계)을 표시하고 `보정 금액`·`지불 준비 금액` 열 제목 `?` 팝오버로 각 항목의 의미를 설명한다. 조회·탭·필터 전환 시 표시 중인 거래는 기본으로 전체 선택되며, 상단 계좌별 현황은 항상 현재 선택된 거래만을 기준으로 계산한다(전부 해제 시 합계 `0원`·`선택된 내역 없음` 표시 및 하단 상태 변경 버튼 비활성화). 계좌가 다르면 지불 준비 금액을 이체하고, 같으면 이체 없이 확보하도록 안내한다. 지불 대기로 변경할 때 사용자의 확보 확인 후 기록한다. 지불 준비 필요에서 지불 완료로 바로 변경할 수도 있다.
- 지불 대기에서 지불 완료로 변경하거나, 지불 완료를 지불 대기 또는 지불 준비 필요로 정정할 수 있다. 지불 준비 필요 ↔ 지불 대기 ↔ 지불 완료의 모든 상태 전환은 계좌별로 계좌 잔액 반영 여부를 선택할 수 있게 제공한다(지불 대기·지불 완료 등 다음 단계 전환은 계좌 잔액 반영 기본 선택·해제 시 상태만 변경, 이전 단계로 되돌리기는 지불 상태만 변경 기본·선택 시 반환·복구 계좌 보유금에 반영). 지불 준비 필요에서 지불 대기로 전환할 때는 카드에 필수 연결된 `송금 계좌`를 기본 송금 계좌로 자동 제안한다(동일 결제 계좌에 송금 계좌가 서로 다른 카드 거래가 섞인 경우에만 사용자가 선택).
- 상태 일괄 변경은 외부 은행 송금·출금을 자동 실행하지 않으며, 사용자가 계좌 잔액 반영을 명시적으로 선택한 경우에만 앱 내 보유금을 가감한다. 변경 전 건수·합계와 상태를 확인하고, 이미 반영된 준비 조정을 임의로 되돌리지 않는다. 사용자 확인 및 충돌 방지와 중복 실행 방지를 적용한다.

- 결제 계좌·현금별 미처리 거래를 보여주고 거래 선택·전체 선택을 제공하며, 거래일은 `MM.DD` 형식으로 표시한다.
- 과거 수동 입력의 기본 지불 상태는 결제수단과 거래일에 따라 제안하며, 카드 승인일만으로 카드대금 출금을 확정하지 않는다. 가져온 과거 거래의 상태는 가져오기 흐름의 확인 기준을 따른다.
- 선택한 거래의 합계와 기존 조정을 반영한 이번 이체 필요액을 보여준다.
- 계좌가 다르면 사용자가 외부에서 실제 송금한 뒤, 같으면 이체 없이 확보를 확인한 뒤 선택한 거래만 준비 완료로 기록한다. 실제 송금은 실행하지 않는다.
- 20,000원 거래 5건 중 3건을 선택하면 60,000원을 준비하고 그 3건만 완료한다. 남은 2건은 미처리다.
- 20,000원 한 건에서 10,000원만 처리하는 입력은 제공하지 않는다.
- 처리 취소·금액 변경의 이력이 기존 처리와 연결돼야 한다. 버튼 중복 실행으로 준비금을 두 번 반영하지 않는다.

### FUND-02 준비 후 변경·조정

- 준비 완료 후 감액·취소는 음수 차액, 추가 청구는 양수 차액으로 다음 이체에 반영한다. 단, `지불 대기` 상태 거래의 금액을 수정할 때는(동일 결제계좌 유지 시) 차액을 해당 계좌 보정 금액에 반영할지(계좌 잔여·추가 합산) 또는 반영하지 않을지(반환·별도 송금·입력 오타 정정) 사용자에게 확인한 뒤 반영한다. (`지불 완료` 거래는 현행처럼 직접 금액 수정 차단 유지)
- 지불 관리 화면에서 결제 계좌와 현금 모두 계좌·현금별 보정 금액(결제 계좌나 현금의 입금·준비 오차 보정, 정수 원 단위)을 사용자가 직접 수정하고 음수 조정을 동일하게 차감 적용할 수 있다.
- 조정은 원거래·기존 준비 처리와 연결해 관리한다. 원거래 수정과 별개 새 지출로 중복 집계하지 않는다.
- 조정은 결제 계좌·현금에 귀속한다. 다른 계좌의 조정을 적용하지 않는다. 여러 카드가 같은 결제계좌를 사용하면 해당 계좌 기준으로 준비액을 모은다.
- 확인 화면에 선택 건수·대상 결제계좌·거래 준비액·보정 금액·지불 준비 금액을 표시한다. 이체가 0원인 상계도 사용자 확인 후 기록한다.
- 취소는 원작업에 연결된 역처리로 기록한다. 과거 상태 전체를 복원해 이후 조정이나 다른 준비 기록을 지우지 않는다.
- 다음 이체에 반영한 조정은 소진하고 다시 반영하지 않는다.
- 음수 조정이 필요액보다 커도 잔여를 버리지 않는다. 생활비 계좌로 자동 반환하지 않는다.
- 지불 대기 거래의 결제수단 또는 결제계좌를 변경할 때는 준비 이력을 무시하고 계좌만 교체하지 않으며, 실제 자금 처리 방식을 사용자가 선택한다.

1.  **기존 결제계좌 유지**: 기존 계좌에 음수 조정금을 생성하고 새 계좌는 지불 준비 필요 거래로 등록한다.
2.  **계좌 간 직접 이관**: 사용자가 은행에서 직접 이체한 사실을 확인받고, 기존 계좌 조정금 생성 없이 새 계좌의 거래를 준비 완료로 즉시 이관한다.
3.  **생활비 계좌로 회수**: 기존 계좌의 과다 준비금을 회수 완료 처리(조정금 0원 소진)하고, 새 계좌는 지불 준비 필요 거래로 등록한다.

- 상계·음수 잔여의 계산 사례와 취소 시 역처리 금액을 구현 전 검증한다. 거래 단위 처리 정책은 유지한다.

### FUND-03 카드 청구대금 출금

- 카드대금 전액 출금을 확인한 거래는 사용자가 지불 완료로 변경한다. 결제일이 지났다는 이유만으로 지불 완료로 변경하지 않는다.
- 부분 출금 금액과 미납 잔액을 기록하는 기능은 MVP에서 제공하지 않는다. 전액 지불되기 전에는 지불 완료로 표시하지 않는다. 실제 잔액과 장부 잔액의 차이가 발생할 수 있음을 안내한다.
- 실제 잔액에 이미 반영된 출금은 다시 차감하지 않고, 청구 출금을 새 지출로 중복 생성하지 않는다. 은행 실제 잔액은 직접 입력한다.

### CONF-01 입출금 확인

- **확인 대상**: 예정일(입금 예정일·카드 결제일·지불 예정일)이 지난 미확인 입금(`입금 예정`), 지출(`지불 준비 필요`·`지불 대기`), 카드 결제대금 거래를 대상으로 한다.
- **전역 진입 확인 (`dialog.confirm`)**: 미확인 항목이 `1건` 이상 있을 때 가계부 화면 진입 후 공통 확인 다이얼로그(`dialog.confirm`: 제목 `확인할 입출금이 있어요`, 설명 `날짜가 지난 N건의 입금·지불 여부를 확인해 주세요.`, 하단 균등 2버튼 `나중에` · `확인하기`)를 표시한다(다른 다이얼로그 또는 입력 초점이 활성 중이면 완료 후 확인). `확인하기` 선택 시 `입출금 확인` 모달을 열며, `나중에` 또는 닫기 선택 시 일정 시간(예: 30분) 동안 자동 재노출을 보류한다.
- **알림 아이콘 및 배지 노출 규칙**: 주 메뉴(`결산`·`지출 내역`·`수입 내역`·`자산 현황`·`가계부 설정`)와 모바일 `전체 메뉴` 시트에는 포함하지 않고, 미확인 건수가 `1건` 이상일 때만 프로필 인접 유틸리티 영역(모바일 일반 헤더: 우측 프로필 아이콘 왼쪽, 태블릿 아이콘 레일: 하단 프로필 위 `확인` 아이콘, PC 사이드바: 하단 프로필 위 `입출금 확인` 행)에 아이콘과 건수 원형 배지를 노출한다. 미확인 건수가 `0건`이면 해당 버튼과 배지를 모두 숨긴다. 클릭 시 별도 페이지 이동 없이 `입출금 확인` 목록 모달을 열고, `선택한 N건 확인` 시 최종 확인 `Dialog`가 목록 모달을 덮으며 겹쳐 열린다.
- **구분 통합 목록 및 일괄 완료**: 월별 구분 없이 `입금`·`지출` 섹션으로 통합해 건수·섹션 합계와 함께 최신순으로 표시하고, 상단 `전체 선택`으로 모든 항목을 일괄 선택한다. 개별 행은 유형 라벨 없이 내용 위에 날짜(`MM.DD`)를 배치하고, 내용·계좌·의미색 금액(`입금` 파란색 / `지출·카드 대금` 붉은색)을 표시한다. `선택한 N건 확인` 클릭 시 입금·지불 요약과 계좌별 증감 금액을 확인하고 계좌 잔액 반영 여부를 선택하는 `Dialog`가 위에 덮여 열리며 일괄 완료(`입금 완료` / `지불 완료`) 처리한다.

### BAL-01 잔액과 대조

- 실제 보유금은 사용자가 입력한 은행 실제 잔액을 기준으로 한다. 거래 계산값으로 실제 잔액을 자동 덮어쓰지 않는다.
- 준비금으로 확보한 돈은 다시 쓸 수 있는 생활비로 합산하지 않는다. 결제 계좌 잔액과 준비 의무를 구분한다.
- 준비 처리·수입 입금·정산 기록과 잔액 갱신이 동일 입출금을 이중 반영하지 않도록 설계한다.
- 생활비 계좌·현금 실제 보유금 합계 + 수입예정액(입금 예정·미회수) - 지출예정액(지불 준비 필요·지불 대기)과 예산상 남은 생활비의 차이를 계산한다. `지불 완료`·`입금 완료` 거래는 실제 잔액에 이미 반영된 것으로 보며 계좌 간 내부 이동과 같은 카드 의무는 중복 계산하지 않는다. 자산·계좌·현금·예산·잔액 대조는 **가계부별로 완전 독립** 관리하며 복수 가계부 간 자산을 합산하거나 공유하지 않는다.
- 자산 현황 상단에 가계부·실계좌 차액가 0이 아닐 때만 차이 금액을 알림 배너로 표시한다. 배너의 `계산 내역 보기`로 계좌·현금 합계, 예정 입출금, 기준월의 남은 예산과 차이를 모달에서 보여준다. 자산 현황에는 미회수 금액을 별도 카드로 표시하고, 상대별 미회수 금액은 상세에서 보여준다. 차이가 있어도 저장을 막거나 정리 완료 상태를 요구하지 않는다.
- 차이 0은 입력 자료의 내부 일치이며 실제 누락이 전혀 없음을 보증하지 않는다.
- 준비·정산·수입 입금 저장 후 관련 계좌·최종 수정 시각·선택적 갱신 링크를 제공한다. 잔액 갱신을 필수 후속 단계로 강제하지 않는다.
- 잔액 확인 뒤 기록을 입력했다는 이유만으로 오류를 판정하지 않는다. 거래 발생일·기록 시각·실제잔액에 포함된 범위가 다를 수 있다.

### ASSET-01 자산 목록과 보유금 갱신

- 현금 자산은 자동 생성하지 않는다. 사용자가 자산 구분 `현금·계좌`에서 유형 `현금`을 선택해 소유자·통화별로 등록한다. 통화는 KRW, JPY, VND, USD, THB, PHP, TWD, CNY, HKD, SGD, MYR, IDR, EUR, GBP, AUD, CAD, CHF를 제공하며 같은 소유자의 통화별 현금은 별도 자산으로 관리한다. KRW 현금은 원화 보유량을 직접 입력하고 외화 현금은 보유량에 통화 단위를 표시한다. 현금·계좌 표의 금액 열은 `예상 잔액(평가액)`으로 표시하고, 외화 현금은 원화 환산액과 적용 시세를 보조 정보로 표시한다. 모바일에서는 외화·금 보유량 아래 원화 환산액에 `평가액` 라벨을 붙인다.
- 현금 자산도 다른 자산과 같은 규칙으로 수정·사용 중지한다. 잔액이 남아 있거나 거래·고정 내역·카드에 연결된 자산은 사용 중지할 수 없다. 구성원 탈퇴 시 금융 기록을 삭제하지 않고 기존 기록 보존·가계부 접근 권한 정책을 적용한다. 계좌에서 현금을 인출하면 계좌와 현금 자산 사이의 내부 이동으로 기록하며 수입·지출을 중복 생성하지 않는다.

- `자산 현황`을 별도 메뉴로 제공한다. 생활비 계좌·결제 계좌·현금 외에 예·적금·투자상품·연금·부동산·대출 등 부채의 수동 현황 관리도 MVP에 포함한다.
- 결제수단에 등록한 계좌는 같은 자산을 참조한다. 자산현황용 계좌를 중복 생성하지 않는다. 카드 자체를 예금 자산으로 합산하지 않는다.
- 소유자, 자산 구분, 상품유형, 금융사, 표시명, 현재 보유금액, 최종 수정 시각을 관리한다. 금융사 등 적용되지 않는 필드는 현금에 강제하지 않는다.
- 계좌번호·증권번호는 원본 시트에 있는 항목이지만 서비스 필수 입력으로 확정하지 않는다. 식별에 필요한 최소 정보와 마스킹·암호화 범위는 입력 설계에서 정한다.
- 자산 저장 시 최종 수정 시각을 서버에서 자동 기록하며 사용자가 직접 입력하지 않는다. 이름만 변경해도 갱신되므로 잔액을 새로 확인한 시각이라고 표시하거나 판단하지 않는다. 시세 기준 시각은 별도로 표시한다.
- 은행 실제 잔액은 계좌별로 사용자가 갱신한다. 여러 계좌를 확인해 순서대로 입력할 수 있어야 하며, 잔액 차이가 있어도 저장할 수 있다.
- 자산 입력에서는 자산 구분과 유형을 최상단에 묶어 표시하고, 소유자를 입력 항목의 맨 아래에 배치한다. 금은 금 통장·금 실물 유형으로 보유 형태를 선택한다. 자산 등록 시 소유자를 선택하며 등록 후에는 변경할 수 없다. 서버도 기존 자산의 소유자 변경 요청을 거부한다.
- 신규·기존 자산 모두 상세 조회·잔액 갱신·속성 수정을 제공한다. 자산현황에서는 실제 잔액·평가액 등 금액만 변경하고 자산 속성 수정은 가계부 설정에서 제공한다. 외화·금은 보유량을 변경하고 공통 시세를 적용할 때 원화 평가액을 다시 계산한다. 금 잔액 수정에서는 단위를 돈 또는 그램으로 선택할 수 있으며 단위를 바꾸면 같은 중량을 유지하도록 보유량을 환산한다. 이름·구분·유형·소유자·최종 수정 시각을 재조회할 수 있어야 하며 소유자를 제외한 허용 속성을 수정할 수 있다. 서로 다른 결제계좌의 잔액을 합쳐 하나의 자산으로 저장하지 않는다.
- 단순 잔액 갱신은 수입·지출을 새로 생성하지 않는다. 정산·준비 처리 등과 연결한 경우에도 이미 반영한 입출금을 두 번 가감하지 않는다.
- 가계부의 모든 구성원은 해당 가계부의 자산현황을 조회한다. 참여하지 않은 다른 가계부의 정보는 조회할 수 없다.

### ASSET-02 예정 입출금·합계와 생활비 대조

| 표시 항목          | 의미·처리                                                                                                                                                                                                                                                                                    |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 현재 보유금액      | 사용자가 입력한 실제 잔액. 예상 입금이나 아직 나가지 않은 돈을 임의로 차감한 값으로 바꾸지 않음                                                                                                                                                                                              |
| 수입예정금액       | 아직 입금되지 않은 수입·받을 돈 등. 일반 소득과 정산금의 성격을 구분                                                                                                                                                                                                                         |
| 지출예정금액       | 아직 처리하지 않은 준비금 등 관리 범위의 미처리 지출 의무. `지불 대기`는 카드의 `결제 계좌`(계좌이체·현금은 해당 계좌·현금)에, `지불 준비 필요`는 카드의 필수 `송금 계좌`(현금·계좌이체는 거래에 지정한 `송금 계좌`, 기본값 본인 계좌·현금)에 귀속. 준비 완료·실제 출금과 중복 반영하지 않음 |
| 예상 잔액          | 현재 보유금액 + 수입예정금액 - 지출예정금액. 실제 잔액·즉시 사용 가능 현금과 별개                                                                                                                                                                                                            |
| 소유자별·전체 합계 | 같은 범위와 기준으로 각 금액 열을 합산. 가계부에 등록된 정보를 집계·표시                                                                                                                                                                                                                     |
| 가계부·실계좌 차액 | 생활비 계산에 포함한 자금의 예정 반영 후 금액과 예산상 생활비의 차이                                                                                                                                                                                                                         |

- 자산별 상세의 각 항목에 실제 잔액·평가액, 예정 입금액, 예정 출금액, 예정 반영 후 잔액을 함께 표시한다. 계좌·현금은 마지막 확인 잔액, 부동산·투자 등은 직접 입력한 평가액, 부채는 남은 원금을 표시한다. 확인되지 않은 예정액을 0원으로 단정하지 않는다.
- 수입·받을 돈·미처리 준비금의 기존 기록을 연결해 예정금액을 계산한다. 같은 내용을 자산현황에 다시 독립 입력하도록 요구하지 않는다.
- 한 내부 이체는 출발·도착의 연결된 이동으로 취급한다. 결제 계좌로 들어올 준비금과 생활비 계좌에서 나갈 돈이 전체 금액을 늘리거나 두 번 줄이지 않아야 한다.
- 각 집계 범위에서 출발·도착을 각각 반영한다. 생활비 범위 밖에서 생활비 범위 안으로 들어오는 내부 이동은 생활비의 예정 유입이다. 두 계좌가 모두 전체 자산 범위에 있으면 예정 유출과 예정 유입을 상계하므로 전체 예정 반영 금액이 늘어나지 않는다. 계좌별 최종 수정 시각을 별도로 표시하고 실제 잔액의 확인 시각으로 단정하지 않는다.
- 예정금액에서 관련 거래·정산·준비금 내역과 계산 근거로 이동할 수 있도록 설계한다.
- 돈을 받으면 관련 수입예정액·미정산액을 줄이고 현재 잔액 갱신과 연결한다. 정산금 입금을 새 소득으로 잡거나 이미 갱신한 잔액에 다시 더하지 않는다.
- 결제 계좌에 이미 확보한 준비금도 실제 보유금에는 남을 수 있다. 자산 보유 현황에 보인다는 이유로 다시 쓸 생활비에 포함하지 않는다.
- 생활비에 포함하는 자금 범위를 별도로 식별한다. 전체 자산 합계·예정 반영 후 금액·남은 생활비를 동일한 숫자로 취급하지 않는다.
- 계좌별 최종 수정 시각과 예정금액 기준을 표시한다. 서로 다른 날짜에 입력한 금액의 합계를 특정 시점의 실시간 잔액으로 설명하지 않는다.

### ASSET-03 생활비 외 자산·부채의 수동 현황

저축·투자·연금·부동산·대출 등도 항목을 등록하고 금액을 직접 갱신해 합계를 조회하는 범위까지 MVP에 포함한다.

- 예·적금·투자상품·연금·부동산·부채를 항목으로 등록하고 현재 금액을 직접 갱신한다.
- 자산 등록 시 사용자가 현금·계좌, 저축·투자, 대여·임차보증금, 부채 중 구분을 선택한다. 유형은 선택한 구분에 따라 제공한다. 현금·계좌는 일반계좌와 현금, 저축·투자는 예·적금·투자상품·연금·외화 계좌·금 통장·금 실물·부동산, 대여·임차보증금은 대여금·임차 보증금, 부채는 일반 부채·차입금·임대 보증금 유형을 제공한다. 현금은 자동 생성하지 않으며 통화별로 사용자가 등록한다. KRW 현금은 원화 잔액을 입력하고 외화 현금은 통화별 보유량을 표시하며 예상 잔액에 원화 환산액과 적용 시세를 표시한다. 지원 통화는 KRW, JPY, VND, USD, THB, PHP, TWD, CNY, HKD, SGD, MYR, IDR, EUR, GBP, AUD, CAD, CHF다. 투자상품은 주식·펀드 등으로 사용자가 확인한 원화 평가액을 입력한다. 예·적금과 금 통장은 금융기관 계좌로 관리하며 금융사를 기록한다. 금 실물에는 금융사를 강제하지 않는다. 금의 보유량은 돈 또는 그램 단위로 입력하고 공통 금 시세를 적용한다. 저축·투자의 외화·금 시세는 별도 열 대신 평가액 아래에 표시하고, 대여·임차보증금의 금액 열은 `평가액`으로 표시한다. 모바일 목록은 자산명과 금액을 첫 줄에 표시하고, 다음 줄에 소유자·금융기관·세부유형을 이어서 표시한다. `생활비` 배지는 자산명 옆에 표시한다. 용도·메모 아이콘은 정보 줄 끝에 작게 배치한다. 태블릿·PC 목록은 기존 배치를 유지해 금융기관명 옆에 메모 아이콘을 둔다. 구분을 바꿀 때 기존 유형을 사용할 수 없으면 새 유형을 선택하도록 안내하며 기존 데이터는 저장 전까지 보존한다. 기존 구분이 더 이상 제공되지 않는 자산은 목록에서 구분 확인이 필요한 상태로 유지하고 사용자가 다시 선택할 때까지 기존 기록과 합계를 보존한다. 일반 부채·차입금·임대 보증금은 부채 구분에 둔다. 자산별 상세는 소유자를 합쳐 자산 구분별 합계와 항목을 표시하고 소유자 필터로 개인별 조회를 제공한다. 소유자는 항목의 프로필로 표시하며 같은 자산은 한 그룹에만 포함한다. 구분을 바꿔도 실제 잔액·거래를 자동 변경하지 않는다. 항목별 소유자·구분·유형·현재 금액과 유형별·소유자별 합계를 조회한다. 투자·부동산 등은 사용자가 입력한 평가금액이며 자동 산정한 현재 시세로 설명하지 않는다.
- 대여금은 돌려받을 원금, 차입금은 갚을 원금의 남은 금액으로 관리한다. 원금 지급·반환은 계좌·현금과 채권·부채 사이의 이동이며 일반 수입·지출로 중복 집계하지 않는다. 실제 발생한 이자는 원금과 구분해 별도 수입·지출로 기록할 수 있으며 이자를 자동 계산하지 않는다.
- 대여금·차입금·임차 보증금·임대 보증금은 상대방을 기록한다. 기존 구성원·미참여를 선택하거나 사람 또는 기관 이름을 직접 입력한다. 등록된 사람은 식별 관계와 표시명 스냅샷을 보존하고, 상대방 이름과 관계 정보에도 금융 상세의 암호화 규칙을 적용한다. 기존 기록에 상대방이 없으면 임의로 지정하지 않고 미기록으로 보존하며 수정할 때 확인한다.
- 상대방 지정만으로 상대의 자산·부채를 생성·수정·연결하거나 내부 거래로 자동 상계하지 않는다. 구성원 사이의 지급·반환과 양쪽 기록이 실제로 연결되는 경우에만 확인된 관계를 사용한다.
- 임차인이 맡긴 보증금은 돌려받을 자산으로, 임대인이 받은 보증금은 돌려줄 부채로 등록한다. 양쪽 금액은 소유자의 자산·부채와 순자산에 반영하고 생활비의 수입·지출로 자동 집계하지 않는다. 부동산에는 보증금을 차감하지 않은 평가액을 기록하고 임대 보증금 부채를 한 번 차감한다. 실제 지불·반환은 계좌·현금과 보증금 사이의 이동으로 기록한다. 보증금 금액의 단순 현황 수정은 거래를 자동 생성하지 않는다.
- 부채의 남은 원금은 자산과 구분해 입력·표시한다. 조회 합계는 총자산·총부채·순자산을 구분하고 `순자산 = 총자산 - 총부채`로 계산한다. 부채 원금 전체를 생활비의 당월 지출예정금액에 자동 반영하지 않는다.
- 부채를 자산의 음수와 별도 부채로 동시에 합산하거나 카드 납부 의무를 여러 항목에 중복 반영하지 않는다. 같은 실제 자산·부채는 하나의 항목으로 관리한다.
- 자산 전체 현황에 포함하더라도 생활비로 쓸 자금에 자동 포함하지 않는다.
- 외화 환율과 금 참고 시세를 제외한 시세·평가손익·수익률·연금 수령액·보험 환급금·대출 이자·상환 일정 자동 계산은 제외한다. 단순 금액 등록과 전문 자산관리는 구분한다.
- 금융 자동 연동과 과거 자산 추이 차트는 이 자산 현황에 포함하지 않는다.
- 구성원별·유형별 상세 합계와 전체 상세 합계는 해당 가계부에 등록된 자산을 포함한다.
- 각 항목의 금액·상품·소유 정보에 금융 데이터 암호화 정책을 적용한다.
- 자유로운 자산 예정 입출금 수동 입력의 필요 여부와 부채 변경·실제 거래의 연결 방식은 상세 설계에서 구체화한다. 단순 현황 금액 수정만으로 수입·지출·상환 거래를 자동 생성하지 않는다.

### ASSET-04 외화·금과 공통 시세

- 외화는 외화 계좌·외화 실물, 금은 금 통장·금 실물로 구분해 등록한다. 현금 유형도 통화를 선택해 원화·외화 현금을 각각 등록한다. 외화는 통화 코드·외화 잔액을, 금은 보유량과 돈 또는 그램 단위를 기록한다. 금 통장에는 금융사를 기록하고 금 실물에는 금융사를 강제하지 않는다.
- 공통 환율과 기준 단위의 금 시세는 하루 한 번 조회해 저장한다. 모든 사용자가 같은 시세 자료를 참조하며 제공처·가격 유형·단위·기준 시각·조회 시각을 기록한다. 제공처와 구체적인 가격 기준·조회 시각·이용 조건은 구현 전에 확정한다.
- 외화·금은 공통 시세 적용을 기본으로 하며 원화 환산 평가액은 자동 계산해 읽기 전용으로 표시한다. 사용자는 직접 입력 방식으로 전환해 별도 평가액을 입력할 수 있다. 평가액·보유량·가격의 출처와 확인 시점을 구분하고, 직접 입력을 새 시세로 덮어쓰지 않는다. 금 ETF 등 상품별 가격이 필요한 투자 상품에는 공통 금 시세를 자동 적용하지 않는다.
- 시세 조회 실패 시 마지막 성공 시세의 출처·기준 시각과 갱신 실패를 표시한다. 유효한 시세가 없으면 임의로 평가액을 만들지 않으며 사용자가 직접 입력할 수 있다. 원화 평가액이 확인되지 않은 자산은 미확인으로 표시하고 0원으로 확정하지 않는다.
- 자산별 원화 평가액은 해당 가계부의 총자산에 한 번 포함한다. 거래 환율이나 실제 매매대금과 공통 참고 평가액을 혼동하지 않는다. 보유량과 금액 계산은 화폐·단위별 정밀도를 보존하고 부동소수점으로 금액을 계산하지 않는다. 금융 상세는 기존 암호화 정책을 따른다.

## 9. 수입과 개인자금

### INC-01 수입 종류와 공통 기록

- 수입을 건별로 기록하고 `근로소득`·`사업소득`·`이자소득`·`배당소득`·`연금소득`·`기타소득`·`퇴직소득`·`자산 처분`·`그 밖의 입금`을 제공한다. 수입 종류 옆 팝오버에서 각 종류의 예시를 확인한다.
- 수입 종류·구성원·내용·지급처·실수령액·입금 계좌·입금 상태·입금일 또는 예정일·예산 반영월·귀속월을 기록한다. 입금 계좌는 선택한 구성원의 계좌 목록에서 고른다. 수입 내역은 선택한 예산 반영월별로 조회하며 이전·다음 달로 이동할 수 있다. 종류·내용·지급처·실수령액을 목록에서 확인한다.
- 내 정보(및 가계부 설정 > 구성원 관리)에서 `소득 · 세무 구분`(`근로자` · `근로자의 부양가족` · `해당 없음`)과 본인의 개인사업자 정보를 등록·수정·사용 중지·삭제한다. 사업소득 입력 시 선택 구성원의 개인사업자만 선택적으로 연결한다.
- 수입 추가의 `AI로 초안 작성`에서 급여명세서·사업소득 지급명세서·퇴직소득 명세서 등 수입 자료의 이미지나 PDF 또는 수입 설명을 입력하고 제안된 지급·공제 항목을 검토해 폼에 반영한다. 자료의 연간 합계와 월별 금액, 소득공제와 실제 공제액을 구분하고 확인되지 않은 값은 임의로 확정하지 않는다. 기존 입력은 임의로 덮어쓰지 않으며, 귀속월과 입금 상태는 AI 결과만으로 확정하지 않는다. 사용자가 폼을 확인한 뒤 저장한다. 디자인 앱에서는 합성 예시로 입력·검토·반영 흐름을 시연한다.
- 급여는 명세서의 귀속월·실제 지급일·예산 반영월을 구분한다. 예산 반영월을 후속 연말정산 귀속으로 그대로 사용하지 않는다.
- 입금일을 선택하거나 수정할 때 한국 시간 기준 과거는 `입금 완료`, 오늘 또는 미래는 `입금 예정`을 기본값으로 제안한다. 새 수입의 날짜가 아직 없을 때는 `입금 예정`으로 시작한다. 기존 기록을 열 때는 저장된 상태를 유지하고, 사용자가 현재 입력에서 상태를 직접 선택했다면 날짜를 바꿔도 선택을 유지한다. 기본값은 실제 입금을 보증하지 않으며 계좌 잔액을 자동 갱신하지 않는다.
- 미입금 예상 수입은 수입예정금액으로, 입금된 수입은 실제 보유금으로 구분한다. 이미 받은 급여를 다시 수입예정금으로 집계하지 않는다.
- 전월에 받은 급여를 다음 월 생활비로 배정할 수 있다. 별도 통장 사용이나 전용 자금 잠금 설정을 강제하지 않는다.
- 예정 수입의 동일 기록에서 실제 입금일·실수령액·급여 구성을 확인해 입금 처리한다. 예정 합계에서 제외하며 실제잔액은 자동 가산하지 않는다.
- 수입 종류 전환 중 내용·귀속자·계좌·일자·예산월 등 공통 입력값을 보존한다. 종류별 지급·공제 구성은 초안에서 따로 보존하며 다른 종류의 구성을 자동 적용하지 않는다. 실수령액만으로 지급 총액이나 세금을 역산하지 않는다. 확정 기록을 재조회·수정할 수 있게 한다.

### INC-02 금액 상세와 근로소득 구성

- 근로소득 상세의 기본급·수당 등 **지급 항목**과 소득세·보험료 등 **공제 항목**은 서로 분리된 입력 구역에서 입력하고 사용자 항목을 추가·삭제한다. 지급 합계에서 공제 합계를 빼 실수령액을 계산한다.
- 모든 수입 종류에 지급·공제 기본 항목을 제공한다. 기본 항목의 이름은 고정하고 금액을 입력하며 사용자가 별도 항목을 추가·수정·삭제할 수 있다. 공란인 기본 항목은 합산에서 제외한다. 사용자 추가 행은 항목명과 금액을 입력한다.
- 근로·사업·이자·배당·연금·기타·퇴직소득의 기본 지급 항목은 정해진 `과세` 또는 `비과세`를 표시한다. 사용자 추가 지급 항목은 `과세`가 기본이며 `비과세`로 변경할 수 있다. 공제 항목에는 과세 구분을 표시하지 않는다. 항목의 구분은 세무 신고 판정이 아니다.
- 지급·공제 구성은 다음 입력에 재사용하고 구성 변경이 과거 급여를 바꾸지 않게 한다.
- 모든 수입 종류는 지급·공제 목록으로 기록하며 실수령액을 직접 입력하는 별도 필드나 입력 방식 선택을 두지 않는다. 지급 합계에서 실제 공제 합계를 뺀 결과를 하단에 읽기 전용으로 강조하고 변경 즉시 다시 계산한다. 세율·보험료율을 적용하는 자동 세액·급여 계산기는 구현하지 않는다.
- 신규 수입·고정수입은 종류별 기본 지급·공제 항목을 제공한다. 실수령액만 알면 지급 항목에 확인 금액을 입력하고 공제 기본 항목을 비워 둘 수 있다. 실수령액 직접 입력 필드나 입력 방식 선택은 두지 않는다.
- 종류별 지급·공제 기본 항목과 고유 정보는 아래 기준으로 제공한다. 기본 행의 이름·과세 구분은 변경하지 않고 별도 지급·공제 행을 추가·삭제할 수 있다. 종류별 고유 정보는 귀속월 다음의 추가 정보에서 입력한다. 실제 원천징수와 보험료는 공제 행에서 기록한다.

- 종류별 금액은 실제 지급·차감 사실의 선택 입력이며 해당 세금이 반드시 발생한다는 뜻이 아니다. 금액은 0 이상의 정수 원 단위이며 미입력은 null로 보존한다. 확인된 손익만 음수를 허용한다. 확인한 0원과 구분하고 미입력을 임의로 0원 처리하지 않는다.
- 실수령액은 `지급 항목 합계 − 공제 항목 합계`로 계산한다. 공란인 기본 항목은 합산에서 제외하며 지급 금액은 하나 이상 입력한다. 추가 항목은 이름과 금액을 입력하고 추가 지급 항목의 과세 구분을 선택한다. 금액은 0 이상의 정수로 입력하고 음수 순액은 저장하지 않는다.
- 사업 매출·실수령액을 과세소득금액으로 저장하지 않는다. 부가세는 포함 여부와 별도 금액으로 기록하고 일률적으로 차감액에 더하지 않는다. 필요경비·취득가액·처분 부대비용은 세무·손익 참고 정보이며 실제 입금 시 차감액과 구분한다. 수수료가 부대비용에도 포함되어 있더라도 실수령액에서 이중 차감하지 않는다.

- 저장은 항목명·금액·지급/공제 구분·사용자 과세 구분·기본 항목 출처를 행 단위 스냅샷으로 보존한다. 이름이나 공제 행의 유무로 세무 사실을 추정하지 않는다. 종류 전환 중 편집 구성을 보존하고 고정수입에서 월별 내역을 만들 때 항목 배열을 독립 복사한다. 연간 공제 합계에는 사용자 추가 항목을 포함하며 제거한 항목을 다시 더하지 않는다.

- 지급 합계·공제 합계·실수령액은 장부 집계값이다. 입력이 완성되었거나 공제 행을 제거했다는 이유로 세무상 세전 소득·과세표준·원천징수 확정액이나 세금 없음으로 자동 확정하지 않는다. 사용자 과세 구분 입력도 신고 판단과 분리하며 세무 자료 확인은 후속 기능에서 별도로 다룬다.

### INC-03 개인자금 지급

- 용돈·개인자금으로 빼는 돈은 가계부의 지출로 기록한다. 수입 일부만 가계부 수입으로 잡는 전용 배분 기능을 추가하지 않는다.
- 이후 개인 지출은 별도 개인 가계부로 관리하거나 기록하지 않아도 된다. 자동 생성·연동을 요구하지 않는다.
- 생활비 결제수단으로 개인자금을 사용해 실제로 반환받을 돈이 있다면 회수 상대를 나로 지정한다. 반환은 일반 소득과 구분한다. 같은 가계부에 등록한 계좌 사이의 반환은 내부 이동으로 처리해 전체 자산을 중복 집계하지 않는다.

### INC-04 고정수입(반복 수입)

- 직장인 급여 등 매월 반복되는 고정수입은 `가계부 설정 > 고정 수입 · 지출`에서 등록·수정·일시중지·삭제할 수 있으며, 고정지출과 한 화면에서 함께 관리하고 소유자·관리자·구성원(member) 모두 편집할 수 있다.
- 수입 종류, 내용, 지급처, 입금 예정일(예: 매월 25일), 귀속자, 입금 계좌, 적용 시작월, 예산 반영 방식(입금 당월 또는 익월)을 설정한다. 수입 기록과 동일한 지급·공제 목록에서 예정 실수령액을 자동 계산한다. 지급 한 건·공제 없음으로도 등록할 수 있다. 설정의 항목·금액은 새 월 수입에 독립 복사하고 귀속월은 월별 기록에서 확인한다.
- 아직 생성되지 않은 신규 예산월이 처음 준비·생성될 때 활성 고정수입(예산 반영 방식에 따른 귀속월 >= 적용 시작월)은 해당 예산 반영월의 `'입금 예정'` 수입으로 1회 자동 생성되며, 월별 결산에서 월 예산과 자동으로 대조된다.
- **고정수입 설정과 월별 내역의 완전 분리**: 가계부 설정에서 고정수입을 수정·일시중지·재개·삭제해도 이미 생성된 월의 수입 내역(`'입금 예정'` 포함)과 세부 급여 명세를 자동으로 덮어쓰거나 삭제하지 않고 앞으로 새로 생성되는 신규 월부터만 적용한다. 신규 고정수입을 최초 추가할 때만 사용자가 필요에 따라 `현재 월 이후 수입 내역에도 지금 바로 추가`(이미 생성된 현재 월 및 이후 예정월 중 귀속월 >= 시작월인 월에 즉시 추가) 옵션을 선택할 수 있다. 이미 생성한 미래 예정월을 다시 만들고 싶다면 해당 월 상단의 `예정월 초기화`로 미완료 고정 항목만 비운 뒤 재진입 시 최신 고정 설정으로 재생성할 수 있다.
- 실제 입금 시 새로운 수입을 추가 생성하지 않고, `수입 내역`에서 이미 생성된 해당 예정 수입 기록을 열어 실수령액과 급여 명세 구성을 확인·보정한 뒤 `'입금 완료'`로 처리한다. `수입 기록·수정` 화면의 변경·삭제는 **해당 월 기록 1건에만 반영**되며 가계부 설정의 고정수입이나 다른 달 수입을 변경하지 않는다. `수입 기록·수정`에서는 건별 입력과 예정 수입 입금 확정에 집중하며, 고정 수입 설정으로 바로 이동할 수 있는 경로를 제공한다.

### INC-05 종류별 세무 사실과 집계 경계

- 근로소득은 상용·일용과 명세서 귀속월을, 사업소득은 사업장·거래처·매출·부가세 포함 여부와 금액을, 이자·배당소득은 금융사·지급처·관련 자산/상품을 기록할 수 있다.
- 연금소득은 공적·사적 구분과 지급기관·수령 방식을, 기타소득은 확인된 지급 사유·필요경비를, 퇴직소득은 지급처·근속기간·퇴직급여·연금계좌 이체·과세이연 여부를 기록할 수 있다. 단어·반복 여부만으로 종류나 과세 여부를 판정하지 않는다. `기타소득`은 불명확한 입금의 기본값이 아니다.
- 지급 기본 항목의 과세·비과세 구분은 고정하며 사용자 추가 지급 행은 과세를 기본값으로 과세·비과세를 선택한다. 공제 행에는 과세 구분을 표시하지 않는다. 자산 처분·그 밖의 입금 기본 항목에는 과세 구분을 강제하지 않는다. 세무 분류·세액은 자동 판정하지 않는다.
- 모든 수입 종류의 기본 정보에 `귀속월`을 필수로 입력한다. 최초 기본값은 예산 반영월이며 사용자가 소득이 발생한 연월로 수정할 수 있다. 귀속월은 입금일·예산 반영월과 별도로 저장한다. 별도 귀속연도와 소득 귀속 시작·종료일은 입력하지 않는다. 퇴직소득의 근속 시작일·종료일은 종류별 추가 정보로 구분한다.
- 자산 처분은 관련 자산·처분대금·취득가액·부대비용·처분일을 구분해 기록한다. 처분대금 전체를 양도소득이나 매매 수익으로 간주하지 않는다. 자산 처분의 별도 예산 반영액은 입력하지 않으며, 모든 수입 종류의 실수령액 전체를 예산 반영월의 월 예산과 비교한다.
- 증여·상속·지원금·세금 환급 등은 `그 밖의 입금`에서 실제 사유를 기록하고 소득세상 소득이나 비과세로 일괄 확정하지 않는다. 본인 계좌 이체·대출 실행·대여 원금 회수·보증금 반환·지출금 회수는 일반 수입으로 등록하지 않으며 관련 자산·부채·이동·원지출 흐름에서 처리한다. 대여 이자는 원금과 분리한다. 연금계좌로 직접 이체된 퇴직급여는 생활비 실수령액으로 중복 반영하지 않는다.
- 월별·연간 결산의 수입과 예산 비교 및 `연간 수입액`은 입금 완료·예정 수입의 실수령액을 기준으로 한다. 예산 반영월 기준 장부 집계를 신고용 과세소득 총액으로 제시하지 않는다.
- 종류별 추가 정보는 귀속월 다음에서 선택 입력한다. 근로 구분은 필수이고 사업소득은 선택 구성원의 개인사업자를 선택적으로 연결한다. 지급·공제 항목명·금액·과세 구분·기본 항목 출처와 입력한 추가 정보를 구조적으로 보존한다. 자동 세액 계산·세무 분류 판정·신고 연동은 MVP 범위가 아니다.

## 10. 받을 돈과 정산

### SET-01 회수 금액 관리

- 지출 입력·수정의 `회수 금액` 섹션에서 상대를 추가·수정·제외한다. 회수 대상이 없으면 상대를 추가하지 않는다. 첫 상대를 추가할 때 결제액 전액을 기본 제안한다.
- 상대별 회수 대상 금액·누적 회수한 금액·미회수 금액을 표시한다. 누적 회수한 금액을 늘리면 기존 확정액과의 차이를 새 입금으로 기록한다. 확정된 금액보다 줄이려면 기존 입금 기록을 먼저 정정한다. 입금 시 해당 상대의 입금계좌를 선택하고 여러 건의 입금과 계좌를 보존한다. 입금일은 입력하지 않는다.
- 회수 상대가 가계부 구성원이면 상대의 송금계좌를 선택한다. 해당 가계부에 등록된 그 구성원 소유 계좌와 `가계부에 등록되지 않은 계좌`를 제공한다. 등록되지 않은 계좌는 특정 은행계좌 정보 입력을 강제하지 않는다.
- 등록 계좌를 선택한 경우 정산은 해당 송금계좌와 입금계좌를 연결한 내부 이동이며, 등록되지 않은 계좌는 가계부 범위 밖에서 들어오는 정산이다. 각 입금의 출발·도착을 보존하며 실제 송금과 실제잔액 갱신은 사용자가 처리한다.
- 실제 송금계좌와 수신계좌가 동일한 내부 이동은 허용하지 않는다.

- 회수 대상 금액의 합계는 결제금액 이내이며, 상대별 회수 대상 금액은 회수한 금액보다 작을 수 없다. 거래 취소·환불·감액으로 상대별 회수 대상 금액이 회수한 금액보다 작아지는 수정은 시스템에서 차단한다. 별도의 반환 부채(보낼 돈)나 음수 미수금을 자동 생성하지 않으며, 사용자가 해당 지출의 기존 입금 내역을 먼저 정정한 뒤에만 수정을 허용한다. 상대·회수 대상 금액과 실사용자는 별개다.
- 회수 대상 금액을 줄이거나 미입금 상대를 제외하면 내 부담이 늘어난다. 원지출의 반영월에 반영하고 이후 이월을 재계산한다.
- 이미 받은 내역이 있는 상대는 즉시 제외·변경하거나 체크를 해제할 수 없다. 연결된 입금 내역부터 사용자가 정정한다. 입금 내역을 임의 삭제·이동하지 않는다.
- 변경 전후 생활비 부담과 미회수 금액을 확인한다. 회수 금액 섹션의 변경과 새 입금은 지출 저장 시 함께 확정한다. 지출 취소 시 원본은 유지한다.
- 카드 결제 준비는 전체 결제액 기준이다. 회수 대상 금액 변경·입금 기록은 카드 결제·준비금이나 실제 계좌 잔액을 자동 변경하지 않는다.
- 지출 목록에는 회수한 금액과 미회수 금액을 표시하며 지출 상세의 회수 금액 섹션에서 관리한다.

### SET-02 수동 정산

- 지출 내역의 `회수금 현황` 하위 화면에서 거래 기준 회수 대기·회수 완료 탭을 제공한다. 일부 받은 후 잔액이 남은 거래는 회수 대기에, 회수 대상 금액을 모두 회수한 거래는 회수 완료에 표시한다. 회수 완료에서도 회수한 금액을 보고 지출 상세에서 상대별 회수 기록을 확인·정정한다. 회수 대기에서 거래를 선택하고 `회수 완료`로 일괄 기록한다. 각 거래의 회수한 금액을 보존하고 상대별 남은 금액을 전액 처리한다.
- 확정 전 선택 거래·상대·미회수 금액·송금계좌·합계를 확인하고 상대별로 입금계좌를 하나씩 선택한다. 같은 상대의 선택 거래에는 동일 계좌를 적용한다. 입금일은 입력하지 않는다. 구성원의 송금계좌가 미지정이거나 허용되지 않으면 해당 거래 상세에서 먼저 확인한다. 같은 상대·송금계좌의 건은 함께, 다른 상대·송금계좌는 구분해 기록한다.
- 일부만 받은 경우 지출 상세에서 직접 입력한다. 받을 돈을 입금 전에 등록하지 않았어도 입금 후 상세에서 회수 대상 금액과 회수한 금액을 함께 기록한다. 목록에서 선택한 거래의 정보가 확인 이후 변경되면 최신 값으로 다시 확인하며 일부만 저장하지 않는다.
- 입금은 미회수 금액을 줄이며 일반 수입으로 중복 기록하지 않는다. 입금계좌·금액·거래별 연결을 보존하고 실제 잔액 갱신은 사용자가 선택한다.
- 입금 정정·취소는 연결된 원거래와 입금의 관계를 보존하며 확정 전 영향 범위를 확인한다. 다른 사람이 먼저 결제했다면 실제 송금 후 지출만 기록한다.

## 11. 가계부 접근과 공동 관리

- 가계부 구성원은 해당 가계부의 모든 수입·지출·자산·정산과 과거 기록을 조회한다. 역할은 가계부 설정과 구성원 관리 등 수행 권한을 구분한다.
- 개인적으로 관리할 기록은 별도 가계부에 기록한다. 각 가계부의 데이터와 집계는 분리하며 참여하지 않은 가계부에는 접근할 수 없다.
- 새 구성원은 기존 기록을 볼 수 있다. 탈퇴자의 접근은 종료하고 기존 기록과 합계는 유지한다. 목록·검색·집계·알림·API에서도 가계부 접근 권한을 확인한다.

순자산 = 수동 입력한 현재 자산 금액 합계 - 현재 부채 잔액 합계
실수령액 = 확인된 지급 총액 - 확인된 실제 차감액 합계 (상세 확인 시)
월 수입 합계 = 예산 반영월에 속하는 입금 완료·예정 수입의 실수령액 합계
예산 차이 = 월 수입 합계 - 전월 이월을 제외한 월 예산 합계
추가 준비 필요액 = 선택한 미처리 거래의 준비액 + 이번 처리에 적용할 조정
카드 단계별 부족액 = max(각 단계의 실적 기준 - 해당 조건으로 인정한 실적, 0)

생활비 계좌·현금 예상 잔액 = 계좌·현금 실제 보유금 합계 + 반영 대상 미입금 수입·받을 돈 - 아직 처리하지 않은 지출 의무
잔액 차이 = 생활비 계좌·현금 예상 잔액 - 예산상 생활비

첫 달 시작금액 = 생활비 계좌·현금 예상 잔액 - 첫 달 예산 + 첫 달 생활비 지출 반영 금액
`

- 시작금액을 분류에 배분한 뒤 총액과 분류 합계가 일치해야 한다.
- 실제 보유금에 이미 포함된 입금은 예상 수입·받을 돈에 다시 포함하지 않는다.
- 준비 완료 금액은 사용 가능 보유금과 미처리 의무에서 일관되게 제외한다. 결제 계좌 전체 잔액을 임의로 생활비에서 빼는 계산도 피한다.
- 카드 승인액·할부 원금·이번 회차 금액·생활비 순액·실적 인정액은 서로 대체할 수 없다.
- 월 경계를 넘긴 수정은 관련 이후 월을 다시 계산하되 이미 생성한 월별 예산을 최신 기본값으로 덮어쓰지 않는다.
- 서로 다른 가계부에서 같은 실제 자금을 중복 배정하는 문제와 계좌별 반영 시점 차이는 구현 전 계산 검증 항목이다.

### 화면·저장 계약

- 수입 예산 반영월과 자동 산정한 지출 반영월, 원승인일·카드 실적 집계기간, 준비 대상 의무의 범위, 실제잔액 확인시점을 구분한다. 지출 반영월은 사용자 입력값이 아닌 규칙에 따른 계산 결과로 저장한다. 준비 대상을 근거 없이 금월 거래로만 제한하지 않는다.
- 원승인금액·회차 청구액·카드사 할인·실부담액·분류별 순액·실적 인정액의 정의와 조회/수정 필드를 일치시킨다. 금액은 정수 원 단위이며 배분 전후 합계가 일치해야 한다.
- 저장 요청은 작업번호·원거래 버전·변경 내용을 받는다. 같은 작업번호의 중복 실행을 막고 확인 이후 자료가 바뀌면 최신 차이로 재확인한다.
- 결과 확인 중·저장됨·미반영 확인됨·재확인 필요·임시 자료 만료를 구분한다. 세션 만료는 별도 인증 상태이며 가계부 완료/미완료 상태를 뜻하지 않는다.
- 역할 변경 후 현재 권한을 서버에서 다시 검사해 허용되지 않은 저장을 거절하고 가계부 접근이 종료된 경우 해당 가계부 데이터를 화면 캐시·검색·알림·응답에 남기지 않는다.
- 폼 오류는 해당 필드와 연결하고 첫 오류로 초점을 이동한다. 선택·목록 갱신·모달 종료 후 초점과 스크롤을 보존한다. 긴 목록의 선택 요약은 본문 안에 배치하며 마지막 행을 가리지 않는다.

## 13. 보안·파일 처리·후속 확장

### SEC-01 암호화

- 모든 저장 금액과 금융 상세를 민감 정보로 취급한다. 저장 합계·예산·이월·할인·조정·정산액도 금액 암호화 범위에 포함한다.
- KMS가 영구 데이터 키를 보호하고 암호화한 데이터 키와 금융 암호문을 DB에 저장한다.
- 로그인 식별 쿠키와 별도의 HttpOnly 쿠키 비밀값으로 데이터 키를 암호화해 Redis에 캐시한다. 쿠키 비밀값을 DB·Redis·로그에 함께 저장하지 않는다.
- 미사용 만료와 최대 수명, 로그아웃·권한 변경의 무효화를 둔다. 새 기기·캐시 만료 시 인증과 KMS 경로로 키를 다시 사용할 수 있다.
- 평문 키·상세는 서버 처리 중 일시 존재할 수 있다. 운영자의 단순 조회·저장소 유출에 장벽을 두며 운영자 단독 복호화 불가·서버 전체 장악 방어를 보장하지 않는다.
- 상세 기준은 [암호화·키 관리 규칙](./encryption-policy.md)을 따른다. KMS 제공사·키 단위·TTL은 구현 설계 대상이다.

### SEC-02 원본 비보관과 AI 전송

- 서버의 원본 파일·결제 캡처·임시 이미지는 필요한 동안만 일시 처리하고 성공·실패·취소·만료 시 처리 사본까지 폐기한다. 중단된 작업의 잔여 자료도 정리한다. 입력 중인 캡처는 재시도를 위해 열린 화면의 클라이언트 메모리에서만 미리보기할 수 있으며 지우기·저장 완료·화면 종료 시 해제하고 영구 저장하지 않는다.
- 원본·전체 셀 덤프를 DB·객체 저장소·백업·로그·오류 수집 도구에 보관하지 않는다.
- 확정한 거래는 암호화해 보관하며 재대조에 원본이 필요하면 사용자가 다시 선택한다.
- 외부 AI에는 필요한 정보만 전달하도록 설계한다. 불필요한 인증정보·카드번호·계좌번호·이름은 제거하거나 가린다.
- 원본 비보관이 외부 AI 제공사의 비보관을 자동 보증하지 않는다. 외부 전송 범위·안내 및 동의·제공사 보관 정책은 도입 전 확정·검증한다.
- 사용자 금융 상세·키·쿠키·토큰을 로그·진단·실제 테스트 자료에 남기지 않는다. 운영자 예외 열람을 이 명세로 승인하지 않는다.

### DATA-01 세무 확장 경계

- 원결제와 분할, 승인·최종 청구·할인·실부담, 소유자·실사용자·부담 관계, 실제 날짜·예산월, 할부 회차·취소·정산의 연결을 보존한다.
- 수입 종류·내용·지급처·지급/공제 행·행별 과세 구분·실제 원천징수 내역·귀속월을 보존한다. 실수령액·자산 처분대금·원금·손익을 구분하고 사용자 분류를 법적 판정으로 취급하지 않는다.
- 생활비 부담·카드 실적 인정·향후 세무 분류는 서로 다른 기준이다. 현행 생활비 계산을 후속 세법 계산으로 그대로 재사용하지 않는다.
- 세무 사실의 보존을 이유로 원본 파일이나 불필요한 개인정보를 영구 보관하지 않는다.

### 화면 간 연결

- 사이드바 `결산`에서 `월별`, `연간` 탭을 전환하고 `자산 현황`은 별도 메뉴로 제공한다. 두 탭은 수입 예산 반영월과 지출 반영월을 기준으로 집계한다.

#### 월별 결산

- 선택한 달의 `남은 예산`을 대표 금액으로 크게 표시한다. 같은 카드에 수입·지출·예산(전월 이월 포함)을 표시하며 `남은 예산 = 월 예산 + 전월 이월 − 지출`로 계산한다. 수입은 해당 예산 반영월의 입금 완료·예정 실수령액이다. 구성원 일부를 선택해도 카드에는 전체 기준임을 표시한다. 카드의 `자산 현황`으로 이동한다.
- 헤더의 `구성원` 필터는 `월별 | 연간` 결산이 함께 공유하며, 기본 전체 선택 시 `구성원`으로 표기한다. 팝오버 안에서는 `전체` 해제를 통해 임시 미선택 상태로 전환해 원하는 구성원만 빠르게 선택할 수 있으며, 미선택 상태로 팝오버를 닫으면 이전 선택(또는 전체)을 유지한다.
- 본문은 `예산 · 지출`, `수입 · 공제`, 납부 예정이 있는 경우 `계좌별 카드 납부 예정 금액`, 신용카드가 있는 경우 `카드 현황` 순이며 `확인할 일` 섹션을 두지 않는다. `예산 · 지출`은 지출 합계와 소진율(월 예산과 전월 이월 합계 대비 지출)을 먼저 보여주고, 기본으로 접힌 `분류별 내역`에서 분류별 예산·전월 이월·지출·소진율·남은 예산을 확인한다. 특정 구성원을 선택한 경우 지출 합계와 분류별 지출(도넛 차트 포함)만 선택 구성원 기준으로 표시하고, 지출 영역의 예산·전월 이월·소진율·남은 예산은 숨긴다. 분류별 지출 비율 도넛은 태블릿·PC에서 펼친 내역 안에, 모바일에서는 `지출 비율` 버튼으로 여는 모달에 표시한다. 분류별 소진율 막대는 도넛 범례와 같은 색을 사용한다. `분류 관리`는 `가계부 설정 > 분류 · 예산`으로 연결하며, `예산 수정`은 BUD-02를 따른다.
- `수입 · 공제`는 선택 월·선택 구성원의 입금 완료·예정을 합산한 실수령액을 `수입 합계` 카드에 표시하고 지급액·공제액 합계를 함께 보여준다. 카드의 `지급 · 공제 내역`을 펼치면 선택 구성원의 지급·공제 항목별 합계를 확인한다. 아래의 `구성원별 내역`은 기본으로 접혀 있으며, 펼치면 귀속자마다 개별 카드에 실수령액 합계를 표시한다. 각 카드를 펼치면 해당 귀속자의 수입 종류별 실수령액과 지급·공제 상세를 확인한다.
- `계좌별 카드 납부 예정 금액`은 선택 월과 다음 달의 카드 대금을 결제 계좌별 아코디언으로 묶어 기본 접힘으로 표시한다. 선택 월의 납부일이 지난 카드 대금은 남은 납부액에서 제외한다. 구성원 필터는 결제 계좌 소유자 기준으로 적용하며, 해당 계좌에 연결된 카드 대금은 카드 소유자와 관계없이 합산한다. 각 계좌에 현재 잔액·선택 월 남은 납부액·다음 달 납부 예정액을 표시하고, 펼치면 월별 카드명·납부일·금액을 확인한다. 당월 남은 납부액이 0원이면 다음 달 예정액을 강조하고, 당월 납부액이 현재 잔액보다 크면 부족액을 경고한다. 현재 월 잔액과 비교하는 경고는 실제 현재 월에만 표시한다. 두 달 모두 표시할 납부 예정이 없으면 섹션을 숨긴다.
- `카드 현황`은 카드별 결제대금·적용 혜택·이용 실적을 카드 하나에 모아 기본으로 펼쳐 둔다. 헤더 `구성원` 필터와 카드 내부 `카드사` 복수 선택 필터를 함께 적용해 필터링한다. 신용카드의 선택 월과 다음 달 결제금액은 카드별 청구 대상 기간을 기준으로 나란히 표시하며, 선택 월 납부일 이전이면 선택 월 결제금액을, 납부일이 지났으면 다음 달 결제금액을 강조한다. 라벨 옆 버튼을 누르면 결제일과 청구 대상 기간을 팝오버로 확인한다. 표시할 결제 금액이 없으면 0원으로 보여준다.
- 해당 월의 적용 혜택에는 전월 인정 실적과 적용 단계를, 이용 실적에는 해당 월의 인정 실적과 확인된 단계별 기준·달성 여부·다음 단계 부족액을 표시한다. 해당 월 실적은 등록된 예정 거래를 포함해 카드 조건에 따라 계산한다. 단계 마커와 기준 금액을 단계 경계에 맞춘다. 카드 오른쪽의 `혜택 보기` 버튼을 누르면 모든 단계의 혜택과 한도를 모달에서 확인한다.
- 결제 준비는 `지불 관리`에서, 상대별 미회수 금액은 `회수금 현황`와 `자산 현황`에서 확인한다. 파일 가져오기·지출 추가는 `지출 내역`과 전역 지출 추가 흐름에서 제공한다.

#### 연간 결산

- 헤더의 `구성원` 필터에서 전체 또는 여러 구성원을 선택한다. 수입·공제는 수입 귀속자, 지출은 결제수단 소유자 기준이다. 전체에는 탈퇴 구성원의 기록을 포함하며, 소유자가 확인되지 않은 항목은 등록을 차단하고 팝오버를 닫은 뒤에도 최소 1명 이상 선택을 유지한다. 카드 실적과 귀속연도별 세무 통계는 연간 결산에서 제외한다.
- 요약에 선택 대상의 `연간 수입액`, `연간 지출액`, `연간 잔액`을 표시한다. 연간 수입액은 입금 완료·예정을 합한 실수령액이다. PC는 수입 카드에 지급액·공제액을 함께 표시하고, 모바일·태블릿은 잔액과 수입액·지출액을 한 카드에 표시한다. 연간 잔액 제목의 팝오버에서 집계 기준을 확인한다. 연간 잔액은 선택 연도 1월부터 기준월까지의 선택 수입 실수령액에서 선택 지출을 뺀 값으로 전년도 이월을 제외한다. 현재 연도는 금월, 과거 연도는 12월이 기준월이며 미래 연도는 기준월이 없다. 입금 예정과 예정 지출을 포함하며 해당 기간에 수입·지출 기록이 모두 없거나 기준월이 없으면 미기록으로 표시한다.
- 가계부 전체의 월별 실수령 수입에서 이월을 제외한 저장 예산을 빼서 차이를 계산한다. 양수·음수 차이가 있는 달이 하나라도 있으면 기본으로 접힌 알림에 부호 있는 차이 합계를 표시하고, 펼쳤을 때 차이가 0이 아닌 달과 월별 차액만 보여준다. 합계는 비교 결과이며 가용 예산으로 집계하지 않는다. 수입 기록이나 완전한 월 예산이 없으면 차이를 추정하지 않으며, 수입은 있으나 예산을 확인할 수 없는 달은 별도로 표시한다.
- `월별 수입 · 지출`은 실수령 수입과 생활비 지출의 12개월 꺾은선을 공통 금액 축과 가로 기준선에 표시한다. 양수와 음수에 같은 금액 비율을 적용하고, 값이 없는 달에서는 해당 선을 끊는다. 범례에서 항목을 구분하며 `월별 금액 자세히 보기`를 펼치면 수입·지출·차액을 비교할 수 있다.
- 예산·지출 상세는 기본으로 접어 둔다. 모바일은 월별 예산·지출을 별도 열로 표시하고 각 월과 연간 합계를 펼쳐 분류를 확인한다. 태블릿·PC는 1~12월과 연간 합계를 행으로, 분류와 월 합계를 열로 배치하며 각 셀은 전체 지출을 위에, 이월을 제외한 저장 예산을 아래에 표시한다. 월 열을 고정하며 `월 합계로 이동`은 표에 가로 스크롤이 있을 때만 제공한다. 일부 구성원을 선택하면 해당 소유자들의 지출을 별도로 표시한다. 선택분은 가계부 전체 지출에 포함되며 분할·할인·회수 반영 후의 분류별 합계는 월별·연간 생활비 지출 합계와 일치한다.
- `분류별 그래프 보기`는 기본으로 접혀 있으며 분류를 복수 선택할 수 있다. 기본값은 전체다. 선택 분류의 가계부 전체 지출은 월별 누적 막대로, 해당 분류의 가계부 예산은 실선으로 표시한다. 일부 구성원을 선택하면 선택 분류에 속하는 해당 소유자들의 지출 합계선을 추가한다. 선택 분류의 예산이 일부라도 없으면 해당 월의 예산선을 끊고 일부 미확인으로 표시한다. 양수·음수 지출을 0선 양쪽에 누적하며 부호를 반영해 합산한다. 표에서 분류를 누르면 해당 분류만 선택해 차트를 연다.
- 연간 `수입 · 공제`도 기본으로 접어 둔다. 모바일은 월별·연간 실수령액 합계를 먼저 표시하고 펼치면 해당 기간의 수입 종류별 금액을 보여준다. 태블릿·PC는 1~12월과 연간 합계를 행으로, 기록이 있는 수입 종류와 월 합계를 열로 표시한다. 종류별 금액을 누르면 선택한 월 또는 연간 합계 행 안에 지급과 공제를 나눠 표시한다. 월에 표시할 기록이 없는 수입 종류는 모바일 상세에서 생략한다. 연간 지급·공제 상세는 선택 대상 안에서 종류별로 합산한다. 공제 미입력은 공제 0원으로 해석하지 않는다.
- `수입 종류별 그래프 보기`는 기본으로 접혀 있다. 기본 전체이며 복수 선택한 종류의 월별 실수령액을 누적 막대로 표시한다. 두 누적 차트에서 선택을 해제해 남은 항목이 없으면 차트 대신 선택을 요청한다. 좁은 화면에서는 막대 폭과 월 간격을 줄인다.
- 차트의 월은 마우스·터치·키보드로 조회하며 해당 월 근처의 툴팁에서 금액을 확인한다. 필터가 있는 차트의 범례·그래프·툴팁에는 선택 항목만 반영한다. 툴팁의 미기록 금액 행은 생략하고, 실제 0원은 표시한다.
- 등록된 예정 내역을 집계하며 생성되지 않은 월, 생성됐지만 내역이 없는 월, 기록된 0원을 구분한다. 미생성 월에 이미 등록된 거래도 집계하며 조회만으로 월을 생성하거나 미등록 값을 추정하지 않는다. 월 예산은 이월을 제외한 저장액으로 0원·음수도 그대로 표시한다. 연간 예산은 저장된 금액과 예산이 있는 개월 수를, 연간 지출은 연중 기록을 표시한다. 공동 예산을 구성원별로 임의 배분하거나 집계 대상 월이 서로 다른 연간 예산·지출의 차액이나 소진율을 가용 잔액이나 성과로 표시하지 않는다.

#### 관련 메뉴

- 가계부 설정은 `자산 · 카드`(기본 탭), `분류 · 예산`, `고정 수입 · 지출`, `구성원 · 권한`, `가계부 관리` 탭으로 구분한다:
- **자산 · 카드**: 구성원별 자산·부채 목록과 등록 카드 목록, 결제 계좌 연결, 개인 맞춤 실적 조건 및 안전 사용 중지를 제공한다.
- **분류 · 예산**: 한 단계 분류 목록, 활성 분류 배치 순서 변경(드래그 및 위·아래 이동), 새 분류 간소화 추가(이름만 입력하여 기본 예산 0원으로 생성), 고정 수입 대비 기본 예산·차액 요약, 분류 비활성화 정산 모달(고정/할부/미래 거래 사용처 안내 및 잔액 0원 정리)을 제공한다. 고정 수입·지출은 이 탭에 포함하지 않고 `고정 수입 · 지출` 탭에서만 관리한다.
- **고정 수입 · 지출**: 매월 반복되는 고정 지출과 고정 수입을 한 탭에서 통합 관리한다. 신규 월 생성 시에만 예정 거래로 복사 생성되며, 고정 수입·지출 추가(현재 월 즉시 추가 선택 옵션 포함)·수정(급여형 지급·공제 분리 입력 포함)·일시중지/재개·삭제는 이미 생성된 월의 내역과 완전히 분리된다. 당월 지출·수입 내역 연동 바로가기를 제공하며, 소유자·관리자·구성원(member) 모두 편집할 수 있다.
- **구성원 · 권한**: 참여 구성원 목록(소유자·관리자·구성원 역할 관리, 소유권 이전, 사용자별 프로필 이미지 등록·변경 및 미등록·로드 실패 시 폴백할 고정 9색 배경색 선택·배경 명도에 따른 고대비 글자색 자동 적용), 초대 대기 목록(이메일 초대장 발송 및 취소), 미참여 인물 독립 관리 목록(수기 추가, 삭제 전 과거 거래 보존 경고 안내, `[구성원 계정과 연결]` 모달을 통한 과거 지출 실사용자 및 회수 내역 일괄 승계·통합)을 제공한다.
- **가계부 관리**: 시작 기준월 과거로 앞당기기, `세무정보 기록하기` 체크박스(기본값 OFF — 체크 시 수입·지출 입력 폼에 세무 항목 노출), 가계부 삭제(소유자 전용, 30일 복구 유예)를 제공한다.
- 조회할 수 있는 설정은 수정 권한이 없더라도 읽기 전용으로 제공한다. 조회 권한이 없는 메뉴는 숨기고 직접 접근·저장 시에도 권한을 확인한다.

- 수입 내역의 `실수령액 합계`는 입금 완료·예정 금액을 함께 보여주고 모바일에서는 지급·공제·고정 수입 합계를 상세 보기로 접는다. 검색·필터 적용 시 검색 결과를 집계한다.
- 지출 내역의 `생활비 지출 합계`는 실결제 금액에서 회수 대상 금액을 뺀 값이다. 모바일에서는 실결제·회수 대상 금액을 먼저 보여주고 결제·승인·할인 금액을 상세 보기로 접는다. 검색·필터 적용 시 검색 결과를 집계한다.
- 지출 내역은 자동 산정해 저장한 반영월별로 조회하며 이전·다음 달로 이동할 수 있다.
- 지출 내역 상단 툴바에서 `고정 지출 설정`, `카드 내역 가져오기`, `지출 추가`를 전 태블릿·PC 해상도에서 동일한 버튼 스타일·아이콘(`Repeat`·`Upload`·`Plus`)과 전체 라벨로 제공하며(모바일은 `지출 관리` 바텀 시트에서 동일 3종 액션 제공), 본문 3열 액션 카드로 `지불 관리(지불 준비 필요 건수)`·`할부 현황(진행중 건수)`·`회수금 현황(미회수 금액)`에 진입한다(복귀 시 이전 조회 월과 검색 조건 복원). 목록 상단에 `내역 검색`과 `분류`·`결제 수단`·`실사용자`·`지불 상태` 다중 선택 필터(`전체` 옵션 포함, 모바일은 `상세 검색` 바텀 시트)를 제공하며, 지출 목록은 `일반 지출`, `할부 지출`, `고정 지출` 3개 테이블로 분리해 각 섹션의 건수와 실결제·생활비 합계를 함께 표시한다(거래일은 `MM.DD` 형식, `table-fixed` 정렬). 할부는 해당 월의 할부 지출 테이블에서 사용처 옆 회차 배지(`N/M회차`)로 표시하며, `할부 현황`에서 상단 `월별 할부 청구 예정` 세로 아코디언과 하단 `할부 내역`(`진행 중 | 완료 · 조기 완납` 탭 · `내역 검색`·`결제 수단` 필터 · `완료` 탭 전용 완료일 기준 `완료 기간` `DatePicker` 2개 기본 최근 3개월 자동 입력 및 최대 6개월 선택 · 원거래 아코디언 카드 · 회차 행 클릭 상세 수정·조기 완납·할부 삭제)을 처리한다(변경 결과는 `지출 내역`·`지불 관리`·`결산`에 함께 반영). 단건 지출 수정에서는 `지불 준비 필요` 상태이면서 회수금 입금 기록이 없는 일반·고정 지출만 삭제할 수 있다(`지불 대기`·`지불 완료` 거래·할부 2회차 이후·회수금 입금 기록이 있는 지출은 삭제 차단).
- `회수금 현황(receivables)`:
- 상단 월 선택기 없이 거래일 기준 전체 기간 현황을 기본으로 표시하며, 상단 전체 미회수 KPI(`?` 기준 안내 팝오버 포함)·상대별 미회수 금액 필터 칩과 `대기 중인 회수`·`회수 완료` 탭을 제공한다.
- `내역 검색`·`상대방`·`입금 계좌` 다중 선택 필터(모바일은 `상세 검색` 시트)를 제공하며, `대기 중인 회수` 탭은 기간 필터 없이 전체 미회수를, `회수 완료` 탭은 별도 기간 필터 없이 `최근 3개월` 완료 내역(목록 헤더에 `최근 3개월` 표시)을 조회한다. `대기 중인 회수` 탭에서 다중 선택 체크박스를 통해 여러 건의 미회수 금액 전액을 한 번에 회수 처리(상대별 입금 계좌·구성원 송금 계좌·실제 계좌 잔액 반영 여부 선택)할 수 있다.
- 부분 입금이나 상대방별 정정(회수 상대 직접 입력 및 회수한 금액 변경 시 입금 계좌 잔액 반영 여부 선택 포함)은 거래 행 클릭으로 여는 지출 기록·수정 상세 팝업에서 처리하며 저장 시 `회수금 현황` 목록에 즉시 갱신 반영된다.
- `지불 관리(funds)`:
  - 최상단 히어로 요약 카드에 `지불 준비 금액 합계`(준비 필요 건수 배지 포함)와 `지불 대기`·`지불 완료` 건수·금액을 표시하고, `지불 준비 필요`·`지불 대기`·`지불 완료` 탭 바로 아래에 통일된 접이식 디자인으로 탭별 계좌 현황을 배치한다(`지불 준비 필요`는 `계좌별 지불 준비 현황`으로 결제 계좌·현금별 `거래 합계`·`보정 금액`·`지불 준비 금액` 요약[각 열 `?` 안내 팝오버 및 현금 포함 조정 수정 지원]을 기본 펼침으로, `지불 대기`·`지불 완료`는 계좌·현금별 건수·금액 통계를 기본 접힘으로 제공).
  - 요약 영역 아래에 `내역 검색`, `기간`(`전체` / `이번 달만` / `이전 달만`, `지불 완료` 탭은 선택 월만 조회해 미노출), `결제 계좌`·`결제 수단` 다중 선택 필터(`전체` 포함, 모바일은 `상세 검색` 시트)를 제공하며, 상단에 `자산 현황 보기` 이동 버튼을 둔다. 거래 목록 표에서는 `거래일(MM.DD)` 컬럼을 체크박스 오른쪽 맨 앞에 분리 표시하고, 다중 선택 체크박스를 통해 여러 거래의 지불 상태를 일괄 변경(지불 준비 필요 ↔ 지불 대기 ↔ 지불 완료)할 수 있다. 거래가 없으면 하단 선택 액션 바를 숨기며, 거래 단위 전체 준비 정책을 유지한다.
- `입출금 확인(TransactionConfirmationModal)`:
  - 주 메뉴·모바일 `전체 메뉴` 시트에서 분리해 예정일이 지난 미확인 거래가 `1건` 이상일 때만 모바일 일반 헤더 프로필 왼쪽과 태블릿·PC 사이드바 프로필 위에 아이콘·건수 배지를 노출하고(`0건` 시 숨김), 클릭 시 별도 페이지 이동 없이 `입출금 확인` 오버레이(모바일 바텀시트 / 태블릿·PC `Dialog size="lg"`)를 연다.
  - 월별 구분 없이 `입금`·`지출` 2개 섹션 통합 목록과 상단 `전체 선택`을 제공하고, 개별 행은 내용 위 날짜(`MM.DD`)·계좌·의미색 금액을 표시한다. `선택한 N건 확인` 클릭 시 계좌 잔액 반영 여부를 선택하는 확인 `Dialog`(`실제로 입출금되었나요?`)가 목록 모달 위에 덮여 열리며 일괄 완료 처리한다.
- 파일 가져오기 완료·취소 후 지출의 이전 월과 검색 조건을 복원한다.

| 초기 자금 범위 · 계산 기준 시점    | ① 첫 달 시작금액 자동 역산은 생활비 포함 계좌와 현금만 포함(겸용 계좌의 미지불 의무는 차감) ② 계산 기준 시점은 시작월 1일 기준이며 상태 기반(`지불 완료`·`입금 완료`는 실제 잔액 반영, `지불 준비 필요·지불 대기`·`입금 예정`·`미회수`만 예정 가감)으로 중복 계산 방지 ③ 자산·계좌·잔액 대조는 가계부별 완전 독립 관리(가계부 간 합산·공유 없음)                                   |
