## 1. 목적과 범위

예정 고정지출·할부를 포함한 남은 생활비, 카드별 실적과 목표 부족액, 결제 계좌별 준비금과 받을 돈을 관리한다. 자산현황에서 현재 보유금과 예정 입출금·예정 반영 후 금액을 함께 확인한다. 카드 거래 파일을 가져온 뒤 필요한 내용을 확인하고, 실제 송금·잔액·정산은 사용자가 기록한다.

| 포함          | 범위                                                                                                          |
| ------------- | ------------------------------------------------------------------------------------------------------------- |
| 계정·가계부   | 카카오 로그인, 초대 가입, 개인·공동 가계부, 역할·설정 권한                                                    |
| 초기 설정     | 시작 기준월, 현재 실제 잔액, 기존 납부·준비금·받을 돈, 시작금액 역산                                          |
| 예산          | 한 단계 분류, 추천 분류, 기본·월별 예산, 이월, 기본값 리셋                                                    |
| 결제수단·사람 | 카드·계좌의 소유자, 결제 계좌, 별도 실사용자 목록                                                             |
| 카드 정보     | 공용 카드, 없는 카드의 AI 공식 자료 탐색, 사용자 상품 확인, 개인용 카드, 운영자 공용 조건 검수                |

| 파일 가져오기 | 카드 이용내역과 결제예정·청구내역의 대조, 중복 후보 확인, 등록 전 필수 분류                                   |

| 자산현황      | 계좌·현금·저축·투자·연금·부동산·대출 등 수동 현황, 예정 입출금, 유형·소유자별 합계와 순자산, 생활비 대조 연결 |
| 수입          | 급여·비급여 건별 기록, 급여 구성·공제 사용자 정의, 예산 반영월 분리                                           |
| 정산          | 돌려받을 금액과 사용자 지정 정산 완료금액                                                                     |
| 공개          | 결제수단 기본 공개 수준, 거래별 우선 예외, 과거 적용 선택                                                     |

### 제외

- 모바일 지원, 유료 구독·결제, 일반 공개 가입.
- 마이데이터·오픈뱅킹, 은행 거래 파일 가져오기, 문자·푸시 상시 수집, 자동 송금·결제.
- PDF·이미지·영수증 인식. 실제 지원할 카드 파일 형식은 표본 검증 후 확정한다.
- 한 거래 금액의 일부만 준비 처리하는 기능.
- 입금 자동 정산, 별도 보낼 돈 관리, 실사용자별 자동 정산 규칙.
- 개인자금 지급 이후 개인 지출 관리의 강제·자동 연동.
- 잔액이 맞았던 시점 이후의 변경을 모아 원인을 찾는 고급 추적.
- 연말정산·절세 계산·추천 화면. 후속 확장에 필요한 거래 사실은 유지한다.
- 모든 카드 약관의 상시 자동 갱신, 혜택 금액 전체의 최적화·카드 자동 추천.

## 2. 용어와 공통 불변 조건

| 용어        | 정의                                                                               |
| ----------- | ---------------------------------------------------------------------------------- |
| 가계부      | 구성원·예산·거래·권한을 관리하는 단위. 한 명으로도 사용 가능                       |
| 예산 반영월 | 수입·지출을 생활비 관리에 반영할 월. 실제 거래일과 별도                            |
| 소유자      | 가계부의 최상위 역할 또는 결제수단의 명의자. 두 개념을 구분해 표시                 |
| 실사용자    | 지출을 실제로 사용한 사람. 가입자·소유자·비용 부담자와 별개                        |
| 준비 처리   | 카드 결제 계좌에 필요한 돈을 확보했다는 사용자 기록. 카드대금 실제 출금과 별개     |
| 통계제외    | 해당 금액을 생활비 지출에 중복 합산하지 않는 처리. 실적·준비·후속 세무 제외와 별개 |
| 받을 돈     | 대신 결제한 금액 중 돌려받기로 기록한 미정산액. 일반 소득과 별개                   |

1. KRW 금액은 정수 원 단위로 계산한다. 모든 배분 합계는 원래 금액과 일치해야 한다.
2. 지출 등록, 준비금 이체, 카드대금 출금을 각각 새 지출로 중복 집계하지 않는다.
3. 계좌 간 이동·정산금 입금을 일반 수입으로 집계하지 않는다.
4. 한 실제 결제는 하나의 원거래다. 분류 분할·할부 회차·취소·파일 대조는 원거래와 연결한다.
5. 거래일은 기본적으로 Asia/Seoul의 달력 날짜로 다루고 업로드 시각과 구분한다.
6. 금융 기록의 병합·변경·삭제는 사용자 확인 흐름과 서버 권한 검사를 거친다.
7. 원본 파일 없이도 확정 거래의 금액·출처 메타데이터·적용 규칙을 유지하되, 전체 셀 덤프를 보관하지 않는다.

## 3. 계정·가계부·역할

### AUTH-01 로그인과 초대

- 카카오 로그인만 지원한다. 초대받은 사용자만 무료 알파에 가입할 수 있다.
- 기존 가계부 소유자·관리자는 구성원을 초대할 수 있으며, 초대받은 신규 사용자도 가입 가능하다.
- 로그인 후 여러 기기에서 같은 기록을 사용할 수 있다. 한 기기에만 데이터를 보관하지 않는다.
- 개인 가계부와 공동 가계부를 지원하되 개인 가계부 생성을 공동 사용의 선행 절차로 강제하지 않는다.
- 초대 토큰 수명·재사용 방지·첫 알파 진입 초대 발급 방식은 구현 설계에서 정한다.

### AUTH-02 권한

| 작업                                         | 소유자 | 관리자 | 설정 권한을 받은 구성원 | 일반 구성원 |
| -------------------------------------------- | ------ | ------ | ----------------------- | ----------- |
| 본인에게 공개된 상세 거래 조회·입력·수정     | 가능   | 가능   | 가능                    | 가능        |
| 분류·기본 예산·월별 예산 등 가계부 설정 수정 | 가능   | 가능   | 부여 범위 내 가능       | 불가        |
| 구성원 초대·설정 수정 권한 부여              | 가능   | 가능   | 불가                    | 불가        |
| 가계부 소유권 이전·가계부 삭제               | 가능   | 불가   | 불가                    | 불가        |
| 타인의 비공개 상세 열람                      | 불가   | 불가   | 불가                    | 불가        |

- 생성자가 소유자가 되며 한 가계부의 소유자는 한 명이다. 관리자는 여러 명 지정할 수 있다.
- 상세 공유된 거래의 금액·분류 등은 모든 구성원이 수정할 수 있다. 수정 권한으로 타인의 결제수단 공개 설정이나 거래 공개 예외를 바꿀 수 있게 하지 않는다.
- 소유권은 다른 구성원에게 이전할 수 있다. 수락 절차·관리자 지정 및 해제의 세부 권한은 구현 전 설계 항목이다.
- 새 구성원은 과거 공유 기록도 볼 수 있다. 탈퇴한 구성원의 가계부 접근은 종료한다.
- 탈퇴해도 기존 공동 기록·합계는 유지한다. 비공개 기록을 새로 공개하지 않는다.

### AUTH-03 삭제와 복구

- 가계부 삭제는 소유자만 실행할 수 있다. 삭제 중인 가계부에는 구성원이 접근할 수 없다.
- 삭제일부터 30일간 서비스 운영자에게 문의해 복구를 요청한다. 사용자용 직접 복구 버튼은 제공하지 않는다.
- 운영자는 요청자의 소유 권한을 확인하고 복구한다. 이를 위해 금융 상세를 열람할 필요가 없도록 설계한다.
- 30일 후 영구 삭제 대상으로 처리한다. 실제 삭제 작업과 백업 잔존·삭제 일정은 운영 설계에서 확정하며 즉시 모든 백업에서 제거된다고 표시하지 않는다.

## 4. 시작 설정·분류·예산

### INIT-01 시작월과 잔액

- 사용자가 시작 기준월을 선택하며 관리 범위는 그 달 1일부터다.
- 초기에는 현재 실제 계좌 잔액을 입력한다. 과거 월초 잔액을 찾아 입력하게 하지 않는다.
- 시작월의 거래와 진행 중인 고정지출·할부, 이미 준비한 금액, 기존 카드 납부 의무, 받을 돈을 함께 반영할 수 있어야 한다. 시작월 이전 승인 거래의 이번 달 납부액을 누락하지 않는다.
- 첫 달의 전월 이월금인 시작금액은 입력한 현재 자료로 역산한다. 사용자가 과거 이월금을 임의로 맞추는 것을 기본 절차로 두지 않는다.
- 시작금액은 분류별 예산 비율로 자동 배분하고 수정할 수 있게 한다. 음수도 배분하며 분류별 합은 시작금액과 일치한다.
- 잔액 대조의 완료·미완료 상태를 두지 않는다. 차이가 있어도 저장·사용할 수 있고 잔액 차이만 보여준다.
- 역산은 초기 기준 설정을 위한 것이다. 이후 거래 수정 때마다 시작금액을 자동 변경해 오차를 없애지 않는다.

### BUD-01 한 단계 분류

- 가계부 생성 때 분류를 정한다. 추천 항목은 클릭으로 추가하고 직접 입력도 가능하다.
- 상하위 분류는 사용하지 않는다. 예를 들어 `생활/동물`은 단일 분류명이다.
- 거래가 있는 분류의 삭제 요청은 비활성화로 처리하고 과거 거래·집계를 유지한다.
- 비활성 분류의 예정 거래·미래 예산 처리와 거래가 전혀 없는 분류의 삭제 방식은 상세 설계에서 정한다.

### BUD-02 기본 예산·월별 예산·이월

- 분류별 기본 예산을 두고 새 월에는 해당 시점의 기본값을 적용한다.
- 월별 예산은 예상 수입·큰 지출 계획에 맞게 변경할 수 있다. 월별 변경이 기본값을 바꾸지 않는다.
- 기본 예산 변경은 이미 생성된 월별 예산을 덮어쓰지 않는다.
- 현재 월과 미래 월에는 기본 예산으로 리셋하는 기능을 제공한다. 과거 월에는 제공하지 않는다.
- 리셋은 대상 월 예산만 바꾸고 거래·정산·이월금을 초기화하지 않는다.
- 남은 분류별 금액과 초과 지출에 따른 음수 금액은 다음 달에 이월한다. 연도 전환에도 같은 규칙을 따른다.

## 5. 계좌·카드·사람과 카드 조건

### PAY-01 결제수단·실사용자

- 카드·계좌에 소유자를 등록한다. 거래마다 소유자를 반복 입력하게 하지 않는다.
- 카드에는 결제 계좌를 연결하고 계좌별 준비금을 합산한다.
- 실사용자 목록에는 가계부 구성원을 기본 포함하고, 가입하지 않은 가족·친구도 추가할 수 있다.
- 실사용자 등록은 로그인·조회 권한을 부여하지 않는다. 실사용자 변경만으로 정산·통계제외를 자동 지정하지 않는다.
- 사람과 결제수단 변경이 과거 명의·사용 관계를 지우지 않도록 기록한다.

### CARD-01 카드 선택·AI 탐색·공용 검수

1. 사용자는 등록된 공용 카드에서 상품을 선택한다.
2. 없는 카드는 카드사·상품 정보를 입력해 AI가 공식 자료를 찾아 정리하도록 요청한다.
3. 사용자가 상품명·발급사·버전·공식 링크 등으로 본인이 등록할 카드와 일치하는지 먼저 확인한다.
4. 확인한 카드는 개인용으로 사용하고 AI가 찾은 조건으로 실적을 계산할 수 있다.
5. 찾지 못했거나 애매한 조건은 확정값으로 만들지 않고 운영자 검수 대상으로 표시한다.
6. 공용 카드 조건은 운영자가 검수한 뒤 제공한다. 사용자 확인은 상품 식별이며 공용 조건 검수를 대신하지 않는다.

- 공식 자료의 출처·확인일·조건 버전을 기록한다.
- 개인 설정이 공용 조건과 다르면 별도 개인용 카드로 저장한다. 공용 정보를 덮어쓰거나 개인 설정을 자동 공개하지 않는다.
- 공용 조건이 나중에 바뀌어도 개인 조건·과거 계산을 조용히 덮어쓰지 않는다. 버전 적용 절차는 상세 설계 항목이다.

### CARD-02 실적 계산

- AI는 조건을 추출하고 프로그램이 금액을 계산한다.
- 예정 고정지출을 포함한 실적, 목표 금액과 부족액을 보여준다. 사용자는 이를 보고 평소 사용할 카드를 판단한다.
- 할부 실적은 첫 달 전체 승인금액 인정 또는 월별 납부액 인정 등 카드 조건을 적용한다.
- 세금 등 제외 대상, 할인받은 거래 전체 제외·할인액만 제외·전액 인정 조건을 구분한다.
- 생활비 통계제외와 카드 실적 제외는 독립적이다.
- 현재 사용 카드의 집계는 매월 1일~말일이다. 전체 카드 상품의 보편 정책으로 단정하지 않고 공식 조건을 기록한다.
- 조건 미확정으로 결과가 불완전하면 해당 사유를 표시한다. 모르는 조건을 확정한 것으로 계산 완료 표시하지 않는다.

## 6. 지출·분할·예정 거래

### EXP-01 거래 입력

- 카드·현금·직접 계좌이체 지출을 수동으로 입력·수정한다.
- 거래의 날짜, 결제수단, 금액, 분류와 필요한 사용처·메모·실사용자·할인·정산 정보를 기록한다.
- 소유자 참조·공개 기본값·카드 조건 등은 자동 적용하고 예외만 수정하게 한다. 기존 Y/N 열 전체를 반복 입력하게 하지 않는다.
- 생활비 반영 금액, 승인금액, 카드사 할인, 청구·납부 금액을 구분하며 미래 세무 집계용 원거래 사실을 보존한다.
- 모든 최종 등록 거래는 분류가 있어야 한다. 분할 거래는 각 분할의 분류가 필요하다.
- 현금·직접 이체는 실제 지급 완료와 카드의 준비 처리를 구분한다.

### EXP-02 한 결제의 분류별 분할

- 기본은 분류 하나이고 필요하면 하나의 원거래 안에서 여러 분류로 나눈다.
- 분할금액 합계는 전체 결제금액과 같아야 한다. 불일치하면 해당 거래의 등록을 막고 차액을 안내한다.
- 카드사 할인은 분할 전 금액 비율로 자동 배분하고 정수 원 단위 잔여를 처리한다.
- 상품 자체 할인은 이미 결제금액에 반영된 것으로 취급한다. 별도의 상품 할인 입력 기능을 추가하지 않는다.
- 실적·준비금·파일 대조는 원거래 한 건 기준으로 처리하고 분류별 통계만 분할 기준으로 집계한다.
- 예: 100,000원을 80,000원·20,000원으로 나누고 카드사 할인 5,000원이 있으면 할인 4,000원·1,000원, 순액 76,000원·19,000원이다.
- 원 단위 잔여의 배분 순서와 부분 취소·할부·정산이 결합한 분할 보정은 구현 전 계산 설계 대상으로 남긴다. 사용자 확인 없이 기존 분류 배분을 임의로 바꾸지 않는다.

### EXP-03 고정지출

- 반복할 고정지출을 실제 결제 전에 예정 금액으로 반영한다. 예정일·고정지출 여부를 별도로 두고 정렬 때문에 거래일을 1일로 바꾸지 않는다.
- 예정 금액은 해당 월 생활비와 해당 카드의 실적에 미리 포함한다.
- 실제 내역이 들어오면 원래 예정 거래와 연결해 금액을 보정한다. 별도 지출로 중복 등록하지 않는다.
- 매 건의 결제 확인 버튼을 필수 업무로 추가하지 않는다. 파일 대조·차이 확인 흐름에서 필요한 확인을 받는 방향으로 설계한다.
- 반복 생성 시점·범위, 반복 설정 변경의 미래 적용 방식은 화면·데이터 설계에서 구체화한다.

### EXP-04 할부

- 전체 승인 거래와 회차별 납부 일정을 연결하고 시작 시 미래 회차도 만든다.
- 600,000원 3개월 할부는 생활비·준비액에 월 200,000원씩 반영한다. 첫 달 전체 실적 인정 카드라면 실적은 첫 달 600,000원, 이후 0원이다.
- 나누어떨어지지 않는 금액은 합계가 맞는 임시 배분 후 카드사 확정 회차 금액으로 보정한다. 임시 배분을 확정 청구액으로 설명하지 않는다.
- 장기 반복 납입을 전부 카드 할부로 추정하지 않는다.

## 7. 카드 파일 가져오기와 대조

### IMP-01 입력 범위

- 이용·승인내역 파일은 새 거래 등록에, 결제예정·청구내역 파일은 기존 거래 대조와 납부액 보정에 사용한다.
- 카드 파일만 지원한다. 은행 잔액·수입·이체·정산은 수동 입력한다.
- 지원 카드·확장자·다운로드 경로·파일 크기·행 수·암호 파일 처리 범위는 실제 표본으로 확정한다. 모든 카드 파일을 지원한다고 안내하지 않는다.

### IMP-02 등록 흐름

1. 대상 카드와 파일을 선택한다.
2. 프로그램이 파일을 읽고 AI가 열 의미·거래 범위·승인·취소·할부 표현을 해석한다. 수식·매크로·AI 생성 코드는 실행하지 않는다.
3. 프로그램이 원본 값으로 거래를 변환하고 날짜·금액·부호·통화·합계·누락·중복 후보를 검증한다.
4. 신규 거래, 기존 예정·할부와의 연결 후보, 금액 보정·취소 후보를 미리 보여준다.
5. 사용자가 모호한 연결과 변경을 확인하고 모든 등록 대상 거래의 분류를 선택한다. AI 추천은 수정 가능하다.
6. 사용자 확정 후 거래를 등록하거나 기존 거래를 보정한다. 분류 없는 거래는 최종 등록하지 않는다.
7. 원본 파일·임시 사본을 폐기하고 확정 거래 및 필요한 출처 메타데이터만 유지한다.

### IMP-03 중복·해외 결제·월 경계

- 같은 날짜·금액·사용처라는 이유만으로 자동 병합하지 않는다. 실제 별도 결제일 수 있다.
- 결제예정 파일에 없는 거래를 자동 취소·삭제하지 않는다. 전표 매입 전 거래일 수 있다.
- 해외 결제의 승인 금액·원통화와 최종 원화 청구액은 구분해 보존한다. 환율·수수료 차이로 최종 금액이 바뀌면 원거래를 보정한다.
- 월을 넘겨 금액이 확정돼도 원래 거래의 예산 반영월에서 금액을 보정하고 이후 이월금을 재계산한다. 당월 새 지출로 다시 만들지 않는다.
- 이미 준비한 거래라면 차액을 다음 준비금 처리에 연결한다.
- 읽기 실패·시간 초과·취소 시 기존 확정 기록은 유지하고 미확정 변경은 반영하지 않는다. 원본은 보관하지 않으므로 재시도 시 다시 선택하게 할 수 있다.

## 8. 준비금·자산현황과 실제 잔액

### FUND-01 거래 단위 선택 처리

- 결제 계좌별 미처리 거래를 보여주고 거래 선택·전체 선택을 제공한다.
- 선택한 거래의 합계와 기존 조정을 반영한 이번 이체 필요액을 보여준다.
- 사용자가 외부에서 실제 송금한 뒤 처리하면 선택한 거래만 준비 완료로 기록한다. 실제 송금은 실행하지 않는다.
- 20,000원 거래 5건 중 3건을 선택하면 60,000원을 준비하고 그 3건만 완료한다. 남은 2건은 미처리다.
- 20,000원 한 건에서 10,000원만 처리하는 입력은 제공하지 않는다.
- 처리 취소·금액 변경의 이력이 기존 처리와 연결돼야 한다. 버튼 중복 실행으로 준비금을 두 번 반영하지 않는다.

### FUND-02 준비 후 변경·조정

- 준비 완료 후 감액·취소는 음수 차액, 추가 청구는 양수 차액으로 다음 이체에 반영한다.
- 조정은 원거래·기존 준비 처리와 연결해 관리한다. 원거래 수정과 별개 새 지출로 중복 집계하지 않는다.
- 다음 이체에 반영한 조정은 소진하고 다시 반영하지 않는다.
- 음수 조정이 필요액보다 커도 잔여를 버리지 않는다. 생활비 계좌로 자동 반환하지 않는다.
- 차액 자동 산출·반영 확인 화면, 실제 이체가 0원인 상계 처리와 남은 음수 조정의 소진 절차는 구현 전 상세 설계로 확정한다. 거래 단위 처리 정책은 유지한다.

### BAL-01 잔액과 대조

- 실제 보유금은 사용자가 입력한 은행 실제 잔액을 기준으로 한다. 거래 계산값으로 실제 잔액을 자동 덮어쓰지 않는다.
- 준비금으로 확보한 돈은 다시 쓸 수 있는 생활비로 합산하지 않는다. 결제 계좌 잔액과 준비 의무를 구분한다.
- 준비 처리·수입 입금·정산 기록과 잔액 갱신이 동일 입출금을 이중 반영하지 않도록 설계한다.
- 잔액 차이와 계산 근거·기준 시점을 보여준다. 차이가 있어도 저장을 막거나 정리 완료 상태를 요구하지 않는다.
- 차이 0은 입력 자료의 내부 일치이며 실제 누락이 전혀 없음을 보증하지 않는다.

### ASSET-01 자산 목록과 보유금 갱신

- 자산현황을 별도 화면으로 제공한다. 생활비 계좌·결제 계좌·현금 외에 저축·투자·연금·부동산·기타 자산·대출 등 부채의 수동 현황 관리도 MVP에 포함한다.
- 결제수단에 등록한 계좌는 같은 자산을 참조한다. 자산현황용 계좌를 중복 생성하지 않는다. 카드 자체를 예금 자산으로 합산하지 않는다.
- 소유자, 상품유형, 용도, 금융사, 표시명, 현재 보유금액, 잔액 확인 시점을 관리한다. 금융사 등 적용되지 않는 필드는 현금에 강제하지 않는다.
- 계좌번호·증권번호는 원본 시트에 있는 항목이지만 서비스 필수 입력으로 확정하지 않는다. 식별에 필요한 최소 정보와 마스킹·암호화 범위는 입력 설계에서 정한다.
- 은행 실제 잔액은 계좌별로 사용자가 갱신한다. 여러 계좌를 확인해 순서대로 입력할 수 있어야 하며, 잔액 차이가 있어도 저장할 수 있다.
- 단순 잔액 갱신은 수입·지출을 새로 생성하지 않는다. 정산·준비 처리 등과 연결한 경우에도 이미 반영한 입출금을 두 번 가감하지 않는다.
- 본인 열람과 공동 공개를 구분한다. 자산현황을 열었다는 이유로 타인의 나만 보기 계좌·보유금·상품 정보가 공개되지 않는다.

### ASSET-02 예정 입출금·합계와 생활비 대조

| 표시 항목          | 의미·처리                                                                                           |
| ------------------ | --------------------------------------------------------------------------------------------------- |
| 현재 보유금액      | 사용자가 입력한 실제 잔액. 예상 입금이나 아직 나가지 않은 돈을 임의로 차감한 값으로 바꾸지 않음     |
| 수입예정금액       | 아직 입금되지 않은 수입·받을 돈 등. 일반 소득과 정산금의 성격을 구분                                |
| 지출예정금액       | 아직 처리하지 않은 준비금 등 관리 범위의 미처리 지출 의무. 준비 완료·실제 출금과 중복 반영하지 않음 |
| 예정 반영 후 금액  | 현재 보유금액 + 수입예정금액 - 지출예정금액. 실제 잔액·즉시 사용 가능 현금과 별개                   |
| 소유자별·전체 합계 | 같은 범위와 기준으로 각 금액 열을 합산. 권한상 공개 가능한 정보만 집계·표시                         |
| 생활비 잔액 차이   | 생활비 계산에 포함한 자금의 예정 반영 후 금액과 예산상 생활비의 차이                                |

- 수입·받을 돈·미처리 준비금의 기존 기록을 연결해 예정금액을 계산한다. 같은 내용을 자산현황에 다시 독립 입력하도록 요구하지 않는다.
- 한 내부 이체는 출발·도착의 연결된 이동으로 취급한다. 결제 계좌로 들어올 준비금과 생활비 계좌에서 나갈 돈이 전체 금액을 늘리거나 두 번 줄이지 않아야 한다.
- 예정금액에서 관련 거래·정산·준비금 내역과 계산 근거로 이동할 수 있도록 설계한다. 비공개 내역의 상세는 권한을 따른다.
- 돈을 받으면 관련 수입예정액·미정산액을 줄이고 현재 잔액 갱신과 연결한다. 정산금 입금을 새 소득으로 잡거나 이미 갱신한 잔액에 다시 더하지 않는다.
- 결제 계좌에 이미 확보한 준비금도 실제 보유금에는 남을 수 있다. 자산 보유 현황에 보인다는 이유로 다시 쓸 생활비에 포함하지 않는다.
- 생활비에 포함하는 자금 범위를 별도로 식별한다. 전체 자산 합계·예정 반영 후 금액·남은 생활비를 동일한 숫자로 취급하지 않는다.
- 계좌별 잔액 확인 시점과 예정금액 기준을 표시한다. 서로 다른 날짜에 입력한 금액의 합계를 특정 시점의 실시간 잔액으로 설명하지 않는다.

### ASSET-03 생활비 외 자산·부채의 수동 현황

저축·투자·연금·부동산·대출 등도 항목을 등록하고 금액을 직접 갱신해 합계를 조회하는 범위까지 MVP에 포함한다.

- 저축·투자·연금·부동산·기타 자산·부채를 항목으로 등록하고 현재 금액을 직접 갱신한다.
- 항목별 소유자·유형·용도·현재 금액과 유형별·소유자별 합계를 조회한다. 투자·부동산 등은 사용자가 입력한 평가금액이며 자동 산정한 현재 시세로 설명하지 않는다.
- 부채의 남은 원금은 자산과 구분해 입력·표시한다. 조회 합계는 총자산·총부채·순자산을 구분하고 `순자산 = 총자산 - 총부채`로 계산한다. 부채 원금 전체를 생활비의 당월 지출예정금액에 자동 반영하지 않는다.
- 부채를 자산의 음수와 별도 부채로 동시에 합산하거나 카드 납부 의무를 여러 항목에 중복 반영하지 않는다. 같은 실제 자산·부채는 하나의 항목으로 관리한다.
- 자산 전체 현황에 포함하더라도 생활비로 쓸 자금에 자동 포함하지 않는다.
- 시세·평가손익·수익률·연금 수령액·보험 환급금·대출 이자·상환 일정 자동 계산은 제외한다. 단순 금액 등록과 전문 자산관리는 구분한다.
- 금융 자동 연동·외화자산 환산 자동화·과거 자산 추이 차트는 이 수동 현황 관리에 포함하지 않는다.
- 각 항목의 금액·상품·소유 정보에도 기존 공개·암호화 규칙을 적용한다. 유형별 합계로 비공개 자산 금액을 우회 노출하지 않는다.
- 자유로운 자산 예정 입출금 수동 입력의 필요 여부와 부채 변경·실제 거래의 연결 방식은 상세 설계에서 구체화한다. 단순 현황 금액 수정만으로 수입·지출·상환 거래를 자동 생성하지 않는다.

## 9. 수입과 개인자금

### INC-01 급여·비급여

- 수입을 건별로 기록하고 급여·비급여로 입력 흐름을 나눈다.
- 수입 귀속자, 입금 계좌, 입금일 또는 예정일, 예산 반영월을 기록한다.
- 급여는 명세서의 귀속 연월·실제 지급일·예산 반영월을 구분한다. 예산 반영월을 후속 연말정산 귀속으로 그대로 사용하지 않는다.
- 미입금 예상 수입은 수입예정금액으로, 입금된 수입은 실제 보유금으로 구분한다. 이미 받은 급여를 다시 수입예정금으로 집계하지 않는다.
- 전월에 받은 급여를 다음 월 생활비로 배정할 수 있다. 별도 통장 사용이나 전용 자금 잠금 설정을 강제하지 않는다.

### INC-02 급여 구성과 사용자 정의

- 기본급·수당 등 지급 항목과 소득세·보험료 등 공제 항목을 나눠 입력하고 실수령액을 계산한다.
- 기본 항목을 제공하되 사용자가 항목을 추가·수정할 수 있다. 회사별 수당을 고정 목록으로 제한하지 않는다.
- 지급 항목은 급여명세서에 따라 과세·비과세를 선택하고 구체적인 내용은 메모할 수 있다. 항목명만으로 세무 성격을 추정하지 않는다.
- 지급·공제 구성은 다음 입력에 재사용하고 구성 변경이 과거 급여를 바꾸지 않게 한다.
- 실수령액은 지급 합계에서 공제 합계를 뺀 금액이다. 세율·보험료율을 적용한 급여 자동 계산기는 구현하지 않는다.
- 비급여는 내용·금액 중심으로 간단히 기록한다. 추가 원천징수 상세 입력 범위는 화면 설계에서 정한다.

### INC-03 개인자금 지급

- 용돈·개인자금으로 빼는 돈은 가계부의 지출로 기록한다. 수입 일부만 가계부 수입으로 잡는 전용 배분 기능을 추가하지 않는다.
- 이후 개인 지출은 별도 개인 가계부로 관리하거나 기록하지 않아도 된다. 자동 생성·연동을 요구하지 않는다.
- 이미 지출 처리한 용돈의 사용을 같은 가계부에 기록하면 통계제외로 중복 지출을 막는다. 생활비 결제수단 사용 시 개인자금의 반환은 일반 소득과 구분한다.

## 10. 받을 돈과 정산

### SET-01 받을 돈 등록

- 지출에서 `돌려받을 금액 있음`을 체크하면 전액을 기본 입력하고 일부만 받을 경우 수정한다.
- 실사용자와 받을 상대방·금액은 별도 정보다. 실제 사용자가 다르다는 이유만으로 받을 돈을 생성하지 않는다.
- 전체 카드 결제액은 준비하고 내 부담액만 생활비 지출로 잡는다. 받을 돈은 입금 전에도 예정금액으로 반영한다.
- 예: 90,000원 중 내 부담이 30,000원이면 생활비 지출 30,000원, 받을 돈 60,000원, 결제 준비 90,000원이다.

### SET-02 수동 정산

- 여러 거래의 합산 입금, 여러 사람의 시차 입금을 지원한다. 사용자가 거래·상대별 정산 완료금액을 지정한다.
- 부분 정산을 허용한다. 이는 한 거래의 준비금 일부 처리 제외 정책과 별개다.
- 입금 시 미정산액을 줄이고 실제 보유금 갱신과 연결하되 일반 소득으로 기록하지 않는다.
- 정산 취소·오입력 수정 시 원래 미정산액과 연결을 복원하고 같은 입금을 중복 반영하지 않는다.
- 거래·사람별 배분 화면과 잔액 갱신의 구체적인 순서는 상세 설계 대상이다. 은행 입금만으로 정산을 자동 확정하지 않는다.
- 다른 사람이 먼저 결제한 경우에는 실제 송금 후 지출만 기록한다.

## 11. 공개와 공동 관리

### SHARE-01 기본 공개와 거래 예외

- 카드·계좌의 기본 공개는 나만 보기다. 사용자가 합계 공유·상세 공유를 선택할 수 있다.
- 공동생활비에 반영할지와 상세를 공개할지는 별개다. 상세 비공개로 준비금·공동 합계 계산을 누락하지 않는다.
- 거래마다 명시적인 공개 예외를 지정할 수 있다. 예외는 결제수단 기본값보다 우선한다.
- 기본 공개 변경 시 사용자가 이후 거래만 적용할지 기존 거래에도 적용할지 선택한다. 기존 거래 적용을 선택해도 거래별 명시 예외를 덮어쓰지 않는다.
- 새 구성원에게도 과거 공유 내역을 보여주되 현재 공개 정책과 거래 예외를 따른다.
- 관리자·소유자라는 이유로 개인 상세를 볼 수 없다. 서비스 운영자의 기술적 복호화 능력과 가계부 구성원의 조회 권한은 다른 계층이다.
- 목록·검색·집계 세부·알림·API 등에서 비공개 상세가 우회 노출되지 않도록 서버에서 검사한다. 합계 공유를 완전한 익명성으로 설명하지 않는다.

## 12. 계산 계약

아래는 기능 구현이 지켜야 할 개념식이다. 계좌 포함 범위·시점과 조정 항목의 집계 귀속을 구체화한 계산 명세는 구현 전 별도로 검증한다.

```text
분류별 남은 생활비 = 월별 예산 + 전월 이월금 - 해당 월 생활비 반영 지출
미정산액 = 돌려받을 금액 - 정산 완료금액
순자산 = 수동 입력한 현재 자산 금액 합계 - 현재 부채 잔액 합계
급여 실수령액 = 지급 항목 합계 - 공제 항목 합계
추가 준비 필요액 = 선택한 미처리 거래의 준비액 + 이번 처리에 적용할 조정
카드 목표 부족액 = max(목표 실적 - 해당 조건으로 인정한 실적, 0)

대조용 생활비 = 생활비에 포함한 실제 보유금
              + 반영 대상 미입금 수입·받을 돈
              - 아직 처리하지 않은 지출 의무
잔액 차이 = 대조용 생활비 - 예산상 생활비

첫 달 시작금액 = 대조용 생활비 - 첫 달 예산 + 첫 달 생활비 반영 지출
```

- 시작금액을 분류에 배분한 뒤 총액과 분류 합계가 일치해야 한다.
- 실제 보유금에 이미 포함된 입금은 예상 수입·받을 돈에 다시 포함하지 않는다.
- 준비 완료 금액은 사용 가능 보유금과 미처리 의무에서 일관되게 제외한다. 결제 계좌 전체 잔액을 임의로 생활비에서 빼는 계산도 피한다.
- 카드 승인액·할부 원금·이번 회차 금액·생활비 순액·실적 인정액은 서로 대체할 수 없다.
- 월 경계를 넘긴 수정은 관련 이후 월을 다시 계산하되 이미 생성한 월별 예산을 최신 기본값으로 덮어쓰지 않는다.
- 서로 다른 가계부에서 같은 실제 자금을 중복 배정하는 문제와 계좌별 반영 시점 차이는 구현 전 계산 검증 항목이다.

## 13. 보안·파일 처리·후속 확장

### SEC-01 암호화

- 모든 저장 금액과 금융 상세를 민감 정보로 취급한다. 저장 합계·예산·이월·할인·조정·정산액도 금액 암호화 범위에 포함한다.
- KMS가 영구 데이터 키를 보호하고 암호화한 데이터 키와 금융 암호문을 DB에 저장한다.
- 로그인 식별 쿠키와 별도의 HttpOnly 쿠키 비밀값으로 데이터 키를 암호화해 Redis에 캐시한다. 쿠키 비밀값을 DB·Redis·로그에 함께 저장하지 않는다.
- 미사용 만료와 최대 수명, 로그아웃·권한 변경의 무효화를 둔다. 새 기기·캐시 만료 시 인증과 KMS 경로로 키를 다시 사용할 수 있다.
- 평문 키·상세는 서버 처리 중 일시 존재할 수 있다. 운영자의 단순 조회·저장소 유출에 장벽을 두며 운영자 단독 복호화 불가·서버 전체 장악 방어를 보장하지 않는다.
- 상세 기준은 [암호화·키 관리 규칙](./encryption-policy.md)을 따른다. KMS 제공사·키 단위·TTL은 구현 설계 대상이다.

### SEC-02 원본 비보관과 AI 전송

- 원본 파일은 필요한 동안만 일시 처리하고 성공·실패·취소·만료 시 임시 사본까지 폐기한다. 중단된 작업의 잔여 자료도 정리한다.
- 원본·전체 셀 덤프를 DB·객체 저장소·백업·로그·오류 수집 도구에 보관하지 않는다.
- 확정한 거래는 암호화해 보관하며 재대조에 원본이 필요하면 사용자가 다시 선택한다.
- 외부 AI에는 필요한 정보만 전달하도록 설계한다. 불필요한 인증정보·카드번호·계좌번호·이름은 제거하거나 가린다.
- 원본 비보관이 외부 AI 제공사의 비보관을 자동 보증하지 않는다. 외부 전송 범위·안내 및 동의·제공사 보관 정책은 도입 전 확정·검증한다.
- 사용자 금융 상세·키·쿠키·토큰을 로그·진단·실제 테스트 자료에 남기지 않는다. 운영자 예외 열람을 이 명세로 승인하지 않는다.

### DATA-01 세무 확장 경계

- 원결제와 분할, 승인·최종 청구·할인·실부담, 소유자·실사용자·부담 관계, 실제 날짜·예산월, 할부 회차·취소·정산의 연결을 보존한다.
- 급여 귀속 연월과 지급·공제 항목, 과세·비과세 입력 사실을 보존한다.
- 통계제외·실적 인정·향후 세무 분류는 독립적인 속성이다. 현행 생활비 계산을 후속 세법 계산으로 그대로 재사용하지 않는다.
- 세무 사실의 보존을 이유로 원본 파일이나 불필요한 개인정보를 영구 보관하지 않는다.
