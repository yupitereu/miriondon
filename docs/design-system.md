# 미리온돈 디자인 시스템 설계서

기준 환경: Tailwind CSS v4 + shadcn/ui 기반 [`@repo/ui-core`](../packages/ui-core/package.json)(Core Primitives), [`@repo/ui-composition`](../packages/ui-composition/package.json)(도메인 중립 Composite UI), [`apps/design`](../apps/design/package.json)(디자인 시스템 카탈로그 및 화면 시안 워크벤치, 포트 4100), `apps/client`(가계부 Domain UI), 반응형 웹(최소 320px · 모바일 375px · 태블릿 768px · PC 1280px 지원).

---

## 1. Foundations (디자인 토큰)

모든 스타일 토큰은 [`packages/ui-core/lib/globals.css`](../packages/ui-core/lib/globals.css)에 정의된 CSS 변수와 `@theme` 매핑을 단일 기준(SSOT)으로 사용한다.

### 1.2 타이포그래피 & 수치 표현

- **기본 서체**: `Noto Sans KR` (시스템 산세리프 폴백). `--font-sans`는 서체 선택 토큰이며 폰트 파일을 다운로드하지 않는다. 동일한 서체를 보장하려면 소비 앱에서 웹폰트를 로드한다.
- **금액·날짜·회차 표기 원칙**:
  - 모든 금액·수치·백분율 요소에는 `tabular-nums`(`font-variant-numeric: tabular-nums`)를 필수로 적용해 자릿수 정렬을 유지한다.
  - 상단 `PeriodPicker`로 연·월이 고정된 목록·표의 거래일은 전 해상도 `MM.DD`로 통일하고(자산 수정 시각은 `MM.DD HH:mm`), 불필요한 연도를 반복 표시하지 않는다.
  - 할부 회차(`N/M회차`)는 사용자 입력 상세내역(`memo`)에 합치지 않고 사용처 옆 `Badge`(`tabular-nums`)로 분리 표시한다.
- **스케일**:
  - `Hero Amount`: `30px` (PC `36px`), `ExtraBold (800)`, 자간 `-0.02em`
  - `Card Amount`: `18px ~ 20px`, `ExtraBold (800)`
  - `Section Title`: `15px ~ 18px`, `Bold (700)`
  - `Body / Label`: `14px`, `Medium (500) ~ SemiBold (600)`
  - `Caption / Meta`: `11px ~ 12px`, `Regular (400) ~ Medium (500)`

### 1.3 모서리 둥글기 & 계층 (Radius & Elevation)

- `--radius`: `0.75rem` (`12px`) 기본.
  - `Card`: `12px` (`rounded-lg`)
  - `Hero Card / Modal / BottomSheet`: `16px` (`rounded-xl`)
  - `Input / Button`: `10px` (`rounded-md`)
  - `Badge / Tab Pill`: `999px` (`rounded-full`)
- **계층 표현**: 그림자 남용을 피하고 `배경(#FAF9F8) + 카드(#FFFFFF) + 1px 보더(#EAE4E5)` 대비로 계층을 구분한다.

### 1.4 다크 테마 설계 규칙

1. **표면 계층 (Surface Elevation)**: 그림자 대신 명도 단계와 1px 보더(`--border` `#33292C` / `--border-strong` `#44363A`)로 계층을 구분한다.
   - Base (`--background` `#130F10`) → Card (`--card` `#1C1618`) → Elevated Modal/Sheet/Popover (`--surface-elevated` `#251D20`) → Control/Muted (`--muted` `#2D2427`)
2. **Primary 반전과 Hero Card 분리**:
   - 일반 `Primary` 버튼·활성 탭·링은 시인성을 위해 보라 계열 플럼(`--primary` `#CA91DE`) + 어두운 텍스트(`--primary-foreground` `#1C1320`)로 반전한다.
   - `Hero Card`는 눈부심 방지와 브랜드 일관성을 위해 `--hero-from`(`#441E52`) → `--hero-to`(`#2C1335`) 딥 플럼 그라데이션과 흰색 텍스트(`--hero-foreground`)를 유지한다.
3. **Semantic Tint 저채도화**: `Badge`와 `NoticeBox` 배경에는 Light용 파스텔 색상을 쓰지 않고, 다크 전용 딥 틴트(`--positive-tint` `#133531`, `--destructive-tint` `#3B1616`, `--warning-tint` `#3B2811`)와 고대비 전경색(`#2DD4BF`, `#F87171`, `#FBBF24`)을 조합한다.
4. **입력창·포커스·네비게이션**: 다크 입력창 배경은 `--background`(`#130F10`) 또는 `--card`(`#1C1618`)에 `--border-strong`을 적용하고, 텍스트 입력창(`Input`·`textarea`) 포커스 시 외부 링 없이 테두리(`--primary`)만 강조한다(일반 버튼·선택 컨트롤 포커스 링은 `hsl(var(--primary) / 0.24)` 글로우 사용). 하단 탭바 및 사이드바 활성 항목은 `--primary-tint`(`#2B1C30`) + `--primary`(`#CA91DE`)를 사용한다.

### 1.5 크기 변경 및 반응형 규칙

크기 변경 시 글자 크기를 자동 축소하지 않는다. 디자인앱과 본 앱 모두 `flex`/`grid`·너비·최소 높이·줄바꿈으로 같은 반응형 동작을 구성한다.

| :--------------------------------------- | :------------------------------------------------------------------------------------------------ | :------------------------------------------------------------ |

- rem의 px 표기는 기본 루트 글자 크기 16px 기준이다. `md:` / `lg:`는 전환점, `min-h-control-lg`, `p-card-mobile`, `lg:p-card-desktop`, `max-w-dialog` 등은 크기 유틸리티로 사용한다. 토큰 정의만으로 기존 컴포넌트의 동작이 바뀌지는 않는다.
- 모바일은 한 열과 하단 탭바, 태블릿은 아이콘 레일, PC는 전체 사이드바를 사용한다. 두 열은 카드마다 280px을 확보할 수 있을 때만 사용하고, 공간이 부족하면 한 열로 배치한다.
- 카드·입력창·선택창·안내문은 부모 너비를 채우고 높이는 내용에 맞춘다. 제목·설명·오류 문구는 줄바꿈하며 말줄임하지 않는다.
- 버튼·배지는 기본적으로 내용에 맞춘 너비(Hug)를 사용한다. 폼 제출 버튼이나 긴 문구의 버튼은 부모 너비(Fill)와 줄바꿈을 사용한다. 버튼 높이는 고정 상한이 아닌 최소 높이이며 모바일 주요 액션은 44px 이상을 확보한다.
- `Button size="icon-xs"`는 항목 편집·삭제처럼 좁은 입력 행에 놓는 28px 보조 아이콘 버튼이다. 저장·추가 등 주요 액션에는 쓰지 않는다.
- 탭은 너비를 균등 분배하고 선택 표시도 항목 너비를 따른다. 금액은 한 줄·우측 정렬을 유지하며, 공간이 부족하면 주변 라벨과 설명을 다음 줄로 배치한다.
- 다이얼로그 기본(`size="default"`) 너비는 `min(380px, 100% - 32px)`이며, 다열 폼 모달(`size="lg"`)은 태블릿 `560px`(`35rem`), PC `620px`(`38.75rem`) 상한을 사용한다. 본문은 최대 480px과 남은 뷰포트 높이 중 작은 값 안에서 스크롤하고, 제목·액션은 보존한다. 모바일 입력 시트는 기존 `90dvh` 상한을 적용한다.
- 모바일 거래 목록은 카드, 태블릿 이상은 표를 사용한다. 열이 좁아지면 보조 정보를 같은 셀의 두 번째 줄에 배치하며, 금액을 축소하거나 잘라서 맞추지 않는다.
- 한 화면에 여러 표가 세로로 나열될 때(`일반`·`고정`·`할부` 등)는 `table-fixed`와 고정 열 너비(`날짜·분류`, `결제 수단`, `실사용자`, `지불 상태`, `금액`) + `내역` 1열 가변 조합을 사용하고, 긴 텍스트는 `truncate` 처리해 모든 표의 세로 열 경계선을 일치시킨다.
- 표 열 정렬은 `날짜(· 분류)`·`분류`·`실사용자`·`지불 상태` 가운데 정렬(`text-center`), `내역`·`결제 수단`·`결제 계좌` 좌측 정렬, `금액` 등 수치 열 우측 정렬(`text-right tabular-nums`)을 따른다.
- 라벨 없는 `Checkbox`는 `44px × 44px`(`min-w-touch`) 중앙 정렬 래퍼를 가지므로, 체크박스 열은 최소 `48px`(`w-12 pl-1 pr-0`, 셀 `py-1`) 이상을 확보해 인접 열 패딩과 겹치지 않게 한다.
- 화면 시안과 컴포넌트 카탈로그는 `apps/design`(포트 `4100`)에서 실제 CSS 미디어 쿼리(`md:`/`lg:`)와 `4단 비교`(`320·375·768·1280px`), `단독 보기`(브라우저 리사이즈), `html.dark` 테마 전환으로 직접 검증한다.
- 검증 너비는 320·375·768·1280px이다. 긴 가계부명·여러 줄 설명·`123,456,789원`을 넣어 내용이 보존되는지 확인한다.

### 3.1 `CommonDialog` (JS 명령형 Alert / Confirm / Prompt)

`dialog.alert()`, `dialog.confirm()`, `dialog.prompt()` 형태로 어디서든 호출 가능한 공통 다이얼로그 시스템.

| 유형                 | 옵션 스펙                                                                             | 버튼 규칙 (2~4자 단일 단어)                                        |
| :------------------- | :------------------------------------------------------------------------------------ | :----------------------------------------------------------------- |
| **`Alert`**          | `{ title, description, confirmText? }`                                                | 1버튼 (`확인` / 예외 시 `다시 시도`)                               |
| **`Confirm` (일반)** | `{ title, description, notice?, confirmText, variant: 'default' }`                    | 2버튼 (`취소` / 구체적 동사 `연결`, `변경`, `적용`)                |
| **`Confirm` (위험)** | `{ title, description, notice?, confirmText, variant: 'destructive' }`                | 2버튼 (`취소` / 파괴적 동사 `삭제`, `초기화`, `내보내기`)          |
| **`Prompt`**         | `{ title, description?, label, placeholder?, defaultValue?, validate?, confirmText }` | 2버튼 (`취소` / 제출 동사 `추가`, `변경`, `저장`) + 하단 에러 표시 |

- `notice` 슬롯은 금융 기록 보존 고지(예: 미참여 인물 삭제 시 과거 거래 이름 보존) 등 필수 안심 문구가 필요할 때만 렌더링한다.

### 3.2 검색 · 상세 필터 · 액션 카드 · 보조 안내 규격

- **검색 · 다중/단일 필터 바 (`FilterSingleSelect` · `FilterMultiSelect`)**:
  - 검색창 기본 플레이스홀더는 `내역 검색`을 사용한다.
  - 필터 트리거는 기본 상태(`전체`)에서 라벨만 표시(`기간`, `결제 계좌`, `결제 수단`, `분류`, `실사용자`, `지불 상태`)하고, 선택 시에만 `기간: 이번 달만` 또는 `라벨 N` 및 브랜드 틴트(`border-primary bg-primary-tint`)를 적용한다.
  - 열린 드롭다운 목록과 모바일 `상세 검색` 바텀 시트 각 그룹 선두에는 명시적인 `전체` 항목·칩을 배치하며 헤더의 중복 선택 해제 버튼은 두지 않는다.
  - 텍스트 검색창과 버튼 필터가 함께 있는 툴바는 `SearchFilterToolbar`를 사용한다. 배치만 공통으로 담당하며, 검색·모바일 상세 검색·필터 동작과 화면별 보조 액션은 각 화면에서 전달한다.
  - 태블릿 이상(`>= 768px`)에서는 검색창을 `112px` 이상 `256px` 이하로 유연하게 조절하고 버튼 필터와 한 줄에 배치한다. `1024px` 이상에서는 검색창을 `256px`로 고정한다. 모바일(`< 768px`)은 검색창과 `상세 검색` 시트 버튼(선택 건수 배지, `360px` 미만 아이콘+배지)을 한 줄로 배치한다.
  - 활성 필터 툴바의 초기화 액션은 `Button variant="ghost" size="icon"`과 `RotateCcw` 아이콘으로 표시한다. `aria-label="필터 초기화"`를 지정하고 호버·키보드 포커스 시 같은 문구의 `Tooltip`을 제공한다. 빈 결과 화면의 초기화 액션은 텍스트 버튼으로 유지한다.
- **이동용 액션 카드**: 다른 관리 화면으로 이동하는 요약 카드는 정적 KPI 카드와 구분되도록 메뉴명을 진한 굵은 글씨(`font-bold text-foreground`) 주체로 두고, 아이콘 뱃지와 우측 원형 `>`(`ChevronRight`) 버튼으로 이동 어포던스를 드러내며 상태 수치는 아래 보조 정보로 배치한다.
- **행 내 수정 액션 & `?` 안내 팝오버**:
  - 표·카드 행 내에 독립적인 금액·속성 수정 버튼을 둘 때는 전 해상도 `size-7` 테두리형 `Pencil` 아이콘 버튼(`aria-label`, `title` 병기)을 사용한다(행 전체 클릭으로 상세 진입하는 목록은 생략 가능).
  - 보조 용어·기준 안내는 호버 전용 `Tooltip` 대신 모바일·PC 모두 동작하는 카드 제목 옆 `?` `Popover`(`align="start"`, `w-[min(18rem,calc(100vw-2rem))]`)로 제공한다.
- **설명 문구 최소화 · 사용자 행동 중심 · 단일 지점 노출**: 화면·카드·모달에 자명한 부연 설명이나 `NoticeBox`를 불필요하게 넣지 않으며, 기능을 정의·개선하는 과정의 변경 이력이나 설계 결정 배경은 절대 작성하지 않는다. 설명이 필요할 때는 **사용자가 이 기능을 실제로 이용하는 데 필요한 안내만** 하나의 행동 흐름(목록·모달·확인 창 등) 안에서 중복 없이 크리티컬 액션 시점(추가·수정·삭제·비활성화 확인 등)에 최대한 간결하게 표현한다.

### 3.3 폼 유효성 검증 · 에러 표기

- **에러 안내 (`dialog.alert`)**: 폼 저장 실패·유효성 검증 오류 안내는 하단 오류 요약 박스나 개별 필드 아래 중복 문구 대신 기본적으로 `CommonDialog`의 `dialog.alert()`로 표시한다.
- **오류 필드 강조 (`invalid` prop)**: 제출·검증 실패 시 원인이 된 모든 폼 컨트롤(`Input`, `NumberInput`, `Select`, `DatePicker`, `PeriodPicker`)에 `invalid` prop을 전달해 빨간 테두리(`border-destructive`, `Select`·`DatePicker`·`PeriodPicker` 포커스 시 `ring-destructive/25`)와 `aria-invalid="true"`로 시각적·접근성 오류 상태를 표시한다.
- **표시·해제 타이밍**: 초기 렌더링에서는 오류를 미리 드러내지 않고 저장/제출 시점에 활성화하며, 사용자가 값을 수정해 조건을 충족하거나 저장 성공·초기화·창 닫기가 일어나면 해당 필드의 오류 표시를 즉시 해제한다. 접힌 상세 영역 내부 필드에 오류가 있으면 해당 영역을 함께 펼친다.

### 4.1 가계부 `AppShell` 배치 기준

- 사이드바와 태블릿 아이콘 레일(`76px`)·PC 풀 사이드바(`236px`)·모바일 하단 탭바(`68px`)는 공용 내비게이션 셸(`apps/design`에서는 `DesignAppShell`, `apps/client`에서는 도메인 `AppShell`)로 일관되게 관리한다.
- 태블릿 아이콘 레일과 PC 풀 사이드바에는 내비게이션과 가계부 전환 요소만 배치하고 `+ 지출 추가` CTA는 화면 상단 헤더로 올린다. 모바일에서만 하단 탭바 중앙의 원형 `+` · `지출 추가` 라벨 버튼으로 즉시 지출 입력을 연다.
- PC 메뉴 항목은 왼쪽 정렬·`20px` 아이콘·`14px` 좌측 여백으로 라벨 시작점을 맞추고, 태블릿 레일은 아이콘과 라벨을 중앙 정렬한다. 가계부 전환은 PC 사이드바 상단 드롭다운, 태블릿 레일 상단 아이콘 트리거의 `Popover`, 모바일 `전체` 메뉴 바텀 시트의 `가계부 선택`에서 제공한다. 모바일 상단 pill은 현재 가계부를 식별하는 정적 표기다.
- 개별 화면에서 사이드바 메뉴 정렬이나 자식 너비를 임의로 덮어쓰지 않고, 헤더 슬롯(제목·서브탭·기간 선택기·보조 액션)으로만 차이를 주입한다.

### 4.2 `AmountText` (금융 금액 포맷터)

- 원화(`KRW`) 정수 단위를 `1,420,000원` 형식으로 출력하며 항상 `tabular-nums`를 적용한다.
- 옵션: `sign`: `'auto'` (`+` / `−` 표시) \| `'none'`, `tone`: `'neutral'` \| `'semantic'` (양수 `--positive`, 음수 `--destructive`).
- 음수 기호는 하이픈(`-`) 대신 유니코드 마이너스(`−`)를 사용한다.

### 4.3 `LedgerMonthPicker` / `YearPicker` & `LedgerSwitcher`

- `LedgerMonthPicker`: `@repo/ui-composition` `PeriodPicker(mode="month")` 기반의 `< 2026.11 >` 컨트롤. 중앙 클릭 시 12개월 그리드(생성됨/미생성 상태 표시)를 열며, 미생성 미래 월(최대 +2개월) 진입 시 생성 확인 `CommonDialog`와 연동한다.
- `YearPicker`: `@repo/ui-composition` `PeriodPicker(mode="year")` 기반의 `< 2026 >` 컨트롤. `결산 > 연간` 탭 등 연도별 조회에 사용하며 중앙 클릭 시 연도 그리드를 연다.
- `LedgerSwitcher`: 현재 가계부별 설정 아이콘과 가계부명을 표시하고 복수 가계부를 전환하는 컴포넌트. PC(사이드바 상단 드롭다운)·태블릿(`76px` 레일 상단 아이콘 트리거와 우측 `Popover`)에 배치한다. 모바일 상단 헤더는 현재 가계부 아이콘·이름 pill만 표시하며, 전환은 `전체` 메뉴 바텀 시트 안의 `가계부 선택`에서 제공한다.

### 4.4 `TransactionFormSheet` & `PersonSelector`

- `TransactionFormSheet`: 지출·수입 입력 및 수정을 담당하는 바텀시트/모달 셸. 지출은 예산 반영월 입력을 제공하지 않고 일반·고정 지출은 거래일·예정일, 할부는 현재 조회 월·회차 번호로 반영월을 계산해 미리보기에서 보여준다. 수입은 예산 반영월 입력을 유지한다. 지출은 금액·날짜·분류·결제수단과 분류 분할·할부·실사용자·회수 금액을 구성한다. 신규 실사용자는 결제수단 소유자를 기본으로 하고 결제수단 변경마다 새 소유자로 다시 지정한다. 사용자는 이후 직접 변경할 수 있으며 회수 내역은 연동 변경하지 않는다. 수입은 종류·실수령액·입금 계좌·일자·예산월을 기본으로 두고, 별도 입력 방식 선택 없이 지급·공제 목록으로 통일한다. 모든 종류는 종류별 기본 항목이 있는 지급·차감 목록을 사용하며 각 목록의 추가 버튼과 행별 제거 버튼, 항목명·금액 편집을 제공한다. 종류별 고유 정보는 금액 목록과 구분한다. 실수령액은 지급 합계에서 실제 공제 합계를 빼 읽기 전용으로 표시하며 별도 입력란을 두지 않는다. 단일 지급·공제 없음도 허용한다. 일반 지급 항목 하나만 남겨 실수령액을 기록할 수 있으며, 전용 추가 버튼·배지·혼용 제한은 두지 않는다. 지급·공제 합계는 장부 입력값으로 표시하고 세무상 확정 금액으로 표현하지 않는다. `가계부 설정 > 가계부 관리`의 `세무정보 기록하기` 체크박스(기본값 ON)에 따라 수입·지출 모두 별도의 `세무 정보 (선택)` 섹션 노출을 제어한다. OFF일 때는 수입의 `세무 정보 (선택)` 섹션(귀속월·근로 구분·사업자 선택·`INCOME_DETAIL_FIELDS`)·지급 행 `과세/비과세` 구분과 지출의 `세무 정보 (선택)` 섹션을 숨기고 실수령 계산용 공제 행만 유지한다. ON일 때는 수입은 구성원, 지출은 결제 수단 소유자의 `내 정보`(구성원 관리)에 기록된 `소득 · 세무 구분`(`근로자` · `근로자의 부양가족` · `해당 없음`, `근로자`는 사업자와 동시 등록 가능하며 활성 사업자 보유 시 `근로자의 부양가족` 미노출) 및 활성 사업자 보유 여부에 따라 각각의 `세무 정보 (선택)` 섹션 항목을 노출한다(수입: 귀속월, `근로자` 시 근로 구분, 등록 사업자 보유 시 사업자 선택, 종류별 세무 상세 및 지급 행 `과세/비과세` 구분; 지출: `실사용자`와 무관하게 결제 수단 소유자 기준으로 제어하며, `근로자` 또는 `근로자의 부양가족` 시 `근로자(부양가족)` 연말정산 항목 노출, `해당 없음`·무사업자면 섹션 숨김, 비대상·사업자 보유 시 `사업자 경비`만 노출, 두 조건에 모두 해당하면 `적용 구분`(`근로자(부양가족)`·`사업자`, 초기 접힘 유지·값 선택된 수정 시 자동 펼침·펼치면 `근로자(부양가족)` 탭 기본 활성·두 탭 모두 실제 항목 선택 및 `사업 경비로 기록` 체크 시에만 저장)으로 한 가지만 배타 적용해 근로자(부양가족)은 공제 구분·현금/계좌이체 시 현금영수증을, 사업자는 `사업 경비로 기록` 체크 후 연결 사업자·적격증빙·매입 부가세를 입력하며, 다른 소유자의 결제 수단으로 변경 시 기존 세무 입력값을 초기화). 명세서 귀속월 또는 소득 귀속 기간은 세무 정보 섹션에서 예산월과 분리한다. 미입력 금액과 확인된 0원을 구분한다.
- `PersonSelector`: 가계부 구성원(본인 `(나)` 표기 포함)과 등록된 `미참여` 인물을 그룹핑해 선택한다. 실사용자 목록에는 가상 `공통` 항목을 두지 않으며, `지출금 회수` 상대 선택 드롭다운은 구분선 하단의 `직접 입력`을 통해 미등록 인물 입력을 허용한다.

- 수입의 `귀속월`은 세무정보 기록이 켜져 있을 때 필수로 기록한다. 신규 입력에서는 예산 반영월을 기본값으로 채우며, 입금일·예산 반영월과 별도 값으로 보존한다. 근로소득의 근로 구분은 필수이며, 사업소득의 사업자 선택은 해당 구성원의 활성 개인사업자 중 선택 사항이다.

- 지출 기록 상단의 선택형 AI 입력 보조는 캡처 붙여넣기·한 장 첨부·끌어놓기·작성한 설명을 받는다. 원문과 현재/제안 값·분류 변경을 대조한 뒤 폼에 반영하고 기존 지출 저장으로 확정한다. 생성 중·실패·재확인·중복 후보를 구분하고 수동 입력을 유지한다. 참고화면은 합성 해석 결과임을 표시하며 실제 첨부는 로컬 미리보기만 한다.

### 4.5 카드 현황과 이용 실적

- 월별 결산의 `카드 현황`은 선택한 구성원의 신용카드가 있을 때 카드사 필터와 카드별 패널을 제공한다. 카드사 필터에는 선택한 구성원이 보유한 카드사만 표시하며, 구성원 선택이 바뀌면 더 이상 해당하지 않는 카드사 선택을 해제한다. 신용카드가 없으면 섹션을 숨기며, 카드사 필터 결과만 없는 경우에는 필터를 유지한다. 패널에는 카드명·구성원·카드번호 끝 네 자리, 이번 달과 다음 달 결제금액, 이번 달 적용 혜택과 전월 인정 실적, 이번 달 이용 실적을 표시한다.
- 카드별 패널은 테두리·배경과 내부 여백으로 구분한다. 모바일은 한 열, 태블릿 이상은 두 열로 배치한다.
- 카드명 옆 `혜택 보기`에서 단계별 기준액·혜택·한도를 표시하고 적용 중인 단계를 강조한다. 한도가 포인트인 경우 원화로 바꾸지 않는다.
- `CardPerformanceSegment`는 단계별 진행 구간을 구성하고 컨테이너 너비가 바뀌어도 채움 비율을 유지한다. 구간 진행률은 이전 단계 기준부터 현재 단계 기준까지의 달성 비율이다. 카드별 누적 실적을 모든 구간의 기준액으로 각각 나누지 않는다. 각 구간은 0~100%로 표시한다.
- 단계 경계에는 `CardPerformanceMilestone`의 10px 원형 마커를 연속 트랙 위에 겹쳐 둔다. 달성한 단계는 브랜드색 점, 미달 단계는 트랙과 같은 배경의 얇은 원으로 구분하며 체크 기호는 사용하지 않는다. 구간 사이 간격과 내부 모서리 라운드를 제거해 막대가 하나로 이어지도록 한다. 달성 여부는 상태 문구와 단계 상세로도 표시한다.
- 단계 라벨의 오른쪽 끝과 마커 중심을 해당 구간의 오른쪽 경계에 맞춘다. 라벨을 구간 중앙에 배치하지 않으며 기준액을 줄바꿈할 수 있게 해 인접 라벨과 겹치지 않도록 한다.
- 상태는 `미달`, `일부 단계 달성`, `목표 달성`, `확인된 단계 없음`, `일부 조건 확인 필요`를 구분한다. 월별 혜택 요약에서 조건이 확인되지 않으면 적용 단계 배지 대신 경고 배지 `조건 확인 필요`를 표시하고, 제목도 `적용 혜택`으로 단정하지 않는다.
- 디자인 예시는 화면설계서의 30만·60만·100만 원 기준과 생활 영역 할인·월 한도 1만·2만·3만 원을 사용한다. 실적 480,000원은 1단계 달성·2단계까지 120,000원·3단계까지 520,000원 부족으로 표시한다.
- 단계 수에 맞춰 진행 구간과 단계 라벨을 표시한다. 디자인앱 시안의 실적·부족액·진행률은 예시 상태로 동작하며 실제 서버 계산을 수행하지 않는다.

### 4.6 결산 정보 우선순위와 행 정렬

- `결산 > 월별`은 예산과 수입에 차이가 있으면 경고를 표시하고, `남은 예산` 요약 → `예산 · 지출` → `수입 · 공제` → `계좌별 카드 납부 예정 금액` → `카드 현황` 순으로 배치한다.
- `남은 예산` 요약은 가계부 전체 기준으로 남은 예산, 수입, 지출, 이월 포함 예산을 표시한다. 구성원을 일부 선택하면 전체 기준임을 표시한다.
- `예산 · 지출`은 지출 합계를 먼저 표시하고 전체 구성원 선택 시 소진율, 월 예산, 전월 이월, 남은 예산을 함께 표시한다. `분류별 내역`은 기본 접힘이며, 모바일은 분류별 목록과 별도 `지출 비율` 모달을, 태블릿·PC는 도넛 차트와 분류별 표를 제공한다. 구성원을 일부 선택하면 선택 구성원의 지출만 표시하고 개인별 예산·이월·잔액·소진율은 숨긴다.
- `수입 · 공제`는 수입 합계와 지급액·공제액을 먼저 표시하고 지급·공제 내역과 구성원별 내역을 각각 펼쳐 볼 수 있다.
- `계좌별 카드 납부 예정 금액`은 계좌별로 기본 접힌 아코디언을 제공한다. 현재 잔액과 선택 월의 남은 납부액·다음 달 납부 예정액을 함께 표시한다. 선택 월에 남은 금액이 없으면 다음 달 금액을 강조한다. 펼치면 월별 카드명·결제일·금액을 표시한다. 선택 월의 결제일이 지난 항목은 제외하며, 두 달 모두 표시할 납부 예정이 없으면 섹션을 숨긴다.
- 계좌별 납부액은 구성원 필터에서 선택한 소유자의 계좌만 표시하고, 각 계좌에 연결된 카드의 납부액은 카드 소유자와 관계없이 합산한다. 현재 월의 남은 납부액이 현재 잔액보다 크면 그 차액을 안내한다.
- 태블릿·PC 헤더에서는 `PeriodPicker`(월·연도 선택기)를 제목 바로 옆에 배치하며, 결산에서는 `구성원` 필터 뒤에 `월별 | 연간` 탭을 가장 오른쪽에 배치한다. 모바일 지출·수입 내역은 1행에 `제목` + `PeriodPicker`를 두고 고정 설정은 목록 카드 헤더 우측(`고정 지출` 카드 `설정`, `수입 목록` 카드 `고정 수입`)에 배치하며, 지불 관리 등 기간 선택이 필요한 모바일 서브페이지는 고정 헤더 우측에 `PeriodPicker`를 배치한다. 모바일 결산은 1행에 `월별 결산`/`연간 결산` + `월별 | 연간` 세그먼트, 2행에 `PeriodPicker` + `구성원` 필터를 배치한다.
- `결산 > 연간`은 가계부 전체의 예산 공지(차이·미확인 존재 시 헤더 바로 아래 최상단), 헤더에서 공유하는 연도·복수 선택 가능한 `구성원` 필터, 연간 요약, 월별 수입·지출 그래프, 분류별 예산·지출 표, 수입·공제 내역 순으로 배치한다. 별도 구성원별 합계는 두지 않는다.
- 연간 요약은 `연간 잔액`을 대표 금액으로 표시하고, 상세에서 선택 대상의 `연간 수입액`과 `연간 지출액`을 제공한다. 수입액은 실수령액 기준이다. 잔액에는 `1~11월 수입 − 지출`처럼 기준월과 계산 관계를 표시하며 전년도 이월은 포함하지 않는다.
- 연간 분류표의 제목은 모바일에서 `예산(이월 제외) · 지출`, 태블릿·PC에서 `지출 / 예산(이월 제외)`으로 표시한다. 모바일은 월별 아코디언 안에 분류별 금액을 두고 `예산` 다음 줄에 `지출`을 보여준다. 태블릿·PC는 월을 행, 분류를 열로 배치하고 각 칸에 `지출 / 예산`을 표시한다. 행·열 합계와 월 자료가 있는 개월 수를 함께 표시하며 월 열을 고정한다. 선택 구성원의 지출은 전체 지출에 포함된 별도 하위 값으로 표시한다. 가로 스크롤이 생길 때만 월 합계로 이동하는 버튼을 제공한다.
- 표 아래의 `분류별 그래프 보기`는 기본 접힘이며 `분류` 선택기에서 여러 분류를 고른다. 기본 전체 선택이며 표에서 분류를 누르면 해당 분류만 선택해 그래프를 연다. 선택 분류의 월별 전체 지출을 누적 막대, 예산 합계를 실선으로 표시하고 구성원을 일부 선택한 경우 선택 지출을 점선으로 추가한다. 선택 분류가 없으면 `분류를 선택해 주세요`를 표시한다. 범례·차트·툴팁은 선택한 분류만 표시하며 미확인 예산을 0원으로 대체하지 않는다.
- 월별 수입·지출 추이는 좌측 금액 축이 있는 꺾은선 그래프로 표시한다. 마우스 호버·터치·키보드로 월을 선택하면 해당 월의 금액 툴팁을 보여주며, 기록이 없는 항목은 툴팁에서 생략한다. 양수와 음수에는 같은 금액 비율을 사용하고, 음수·기록된 0원·내역 없음·월 준비 전을 구분한다. 월 예산은 이월을 제외한 저장된 배정액이며 연간 예산에 포함된 개월 수와 월 준비 전의 기등록 지출을 표시한다. 예산과 지출의 대상 월이 다를 수 있으므로 두 합계의 차액·소진율을 가용 잔액으로 표현하지 않는다. 조회만으로 월을 생성하거나 미등록 거래를 예측하지 않는다.
- 수입·공제 표는 태블릿·PC에서 월을 행, 소득 분류를 열로 두고 실수령액을 비교한다. 모바일은 월별 아코디언으로 같은 내용을 제공한다. 소득 분류 금액을 누르면 해당 월의 지급·공제 상세가 열리며 별도 구성원별 합계는 두지 않는다. `소득 분류별 그래프 보기`는 다중 선택한 소득 분류만 누적 막대와 툴팁에 표시한다. 귀속연도별 세무 통계는 제공하지 않는다.

### 4.7 디자인앱 공통 패턴 (`apps/design/shared`)

- `MemberAvatar`는 구성원 식별을 공통화한다. `icon-label`은 아이콘과 이름, `icon-hover`는 아이콘만 두고 호버·터치 상호작용으로 이름을 확인하며, `icon-interactive`는 이름 확인과 프로필 편집을 제공한다. 목록과 필터에서는 공간에 맞는 모드를 선택한다.
- `TransactionListHeader`와 `TransactionMobileRow`는 수입·지출 목록에서 공유한다. 헤더는 제목·건수를 정렬하고 모바일 보조 액션을 받는다. 모바일 행은 날짜·분류·내용·금액·메타 정보·상태 슬롯 순서를 유지하며, 상세가 있는 행은 카드 전체를 눌러 연다. 태블릿·PC 표의 열 구성은 각 화면이 관리한다.
- `SearchFilterToolbar`는 검색창·필터·초기화·화면별 액션의 배치만 담당한다. 검색 및 필터 상태와 모바일 상세 검색 시트 동작은 화면에서 전달한다. 초기화 버튼은 `FilterResetButton`을 사용한다.
- `IncomeLineItemsEditor`는 수입 입력과 고정 수입 설정에서 지급·공제 항목 편집을 공유한다. 항목별 금액과 섹션 합계를 제공하고, 추가한 항목만 이름 수정·삭제할 수 있다. 과세 구분은 세무정보 기록을 켠 경우 지급 항목에만 표시한다.
- `IncomeTaxSection`과 `ExpenseTaxSection`은 각각 수입·고정 수입, 지출·고정 지출의 세무 입력을 공유한다. 입력할 세무 정보가 없거나 가계부의 세무정보 기록이 꺼져 있으면 섹션을 렌더링하지 않는다.
- `TransactionConfirmationModal`은 셸에서 입금·지불 확인이 필요한 거래가 있을 때 여는 공통 처리 흐름이다.

## 5. 카피 및 마이크로카피 원칙

- **모바일 탭/버튼 길이 제한**: 하단 탭 및 서브탭은 2자(`결산`, `지출`, `수입`, `전체` / `월별`, `연간`), 태블릿 레일 2자(`결산`, `지출`, `수입`, `자산`, `설정`), PC 사이드바 및 모바일 `전체 메뉴` 시트는 명확한 전체 명칭(`결산`, `지출 내역`, `수입 내역`, `자산 현황`, `가계부 설정`)을 사용한다. 다이얼로그 버튼은 2~4자 이내로 제한해 줄바꿈을 방지한다.
- **금융 경계 고지**: `남은 생활비`와 `실제 통장 잔액`은 항상 구분해 표현하며, 단순 데이터 기준 시점 안내에는 경고 배너 대신 `11.04 기준 입력 · 실시간 은행 잔액과 다름` 형태의 1줄 메타 텍스트를 사용한다.
- **표준 도메인 용어**:
  - 역할/인물: `소유자`, `관리자`, `구성원`, `미참여`
  - 지불·지출 용어 및 띄어쓰기: `결제 수단`, `지불 상태`, `거래 내역`, `결제 계좌`, `송금 계좌`, `실결제 금액`, `생활비 지출 반영 금액`, `보정 금액`, `지불 준비 금액`, `계좌별 지불 준비 현황`, `가계부·실계좌 차액`, `지불 관리`, `할부 현황`, `회수금 현황`, `내역 검색`
  - 지불 상태: `준비 필요`, `지불 대기`, `지불 완료`
  - 수입 상태 배지: `입금 완료`는 연한 청록색(`positive`)으로 표현하고, `입금 예정`은 중립색으로 표시한다.
  - 지불 상태 배지: `준비 필요`는 사용자 조치가 필요한 상태로 브랜드색 채움(`bg-primary text-primary-foreground`)으로 가장 강하게 강조한다. `지불 대기`는 자금 확보가 끝난 정상 진행 상태로 청록색(`positive`), `지불 완료`는 추가 조치가 없는 상태로 회색(`neutral`)을 사용한다. 모바일 목록과 PC 표에 동일하게 적용하며 상태명도 함께 표시한다. 노란 주의색은 조건 미확정·검토 필요 등에 사용하고 정상적인 지불 대기에는 사용하지 않는다.
  - 지출금 회수: `회수 대상 금액`, `미회수 금액`, `회수한 금액`
- **안내 문구 작성 원칙**: 두 개념(`지불 준비 금액` vs `보정 금액` 등)이 함께 설명될 때는 각 문장의 주어를 명시하고, 실시간 합산 표·입력칸 `placeholder` 등으로 이미 자명한 부호 안내(`− 덜 채움 / + 더 채움` 등)는 중복 서술하지 않는다.
