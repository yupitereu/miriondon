# 미리온돈 디자인 시스템 설계서

기준 환경: Tailwind CSS v4 + shadcn/ui 기반 [`@repo/ui-core`](../packages/ui-core/package.json)(Core Primitives), [`@repo/ui-composition`](../packages/ui-composition/package.json)(도메인 중립 Composite UI), [`apps/design`](../apps/design/package.json)(디자인 시스템 카탈로그 및 화면 시안 워크벤치, 포트 4100), `apps/client`(가계부 Domain UI), 반응형 웹(최소 320px · 모바일 375px · 태블릿 768px · PC 1280px 지원).

---

## 1. Foundations (디자인 토큰)

모든 스타일 토큰은 [`packages/ui-core/lib/globals.css`](../packages/ui-core/lib/globals.css)에 정의된 CSS 변수와 `@theme` 매핑을 단일 기준(SSOT)으로 사용한다.

### 1.2 타이포그래피 & 수치 표현

- **기본 서체**: `Noto Sans KR` (시스템 산세리프 폴백). `--font-sans`는 서체 선택 토큰이며 폰트 파일을 다운로드하지 않는다. 동일한 서체를 보장하려면 소비 앱에서 웹폰트를 로드한다.
- **금액·날짜·회차 표기 원칙**:
  - 모든 금액·수치·백분율 요소에는 `tabular-nums`(`font-variant-numeric: tabular-nums`)를 필수로 적용해 자릿수 정렬을 유지한다.
  - 상단 `PeriodPicker`로 연·월이 고정된 목록·표의 거래일은 전 해상도 `MM.DD`로 통일하고(자산 수정 시각은 `MM.DD HH:mm`), 불필요한 연도를 반복 표시하지 않는다.
  - 할부 회차(`N/M회차`)는 사용자 입력 상세내역(`memo`)에 합치지 않고 사용처 옆 `Badge`(`tabular-nums`)로 분리 표시한다.
- **스케일**:
  - `Hero Amount`: `30px` (PC `36px`), `ExtraBold (800)`, 자간 `-0.02em`
  - `Card Amount`: `18px ~ 20px`, `ExtraBold (800)`
  - `Section Title`: `15px ~ 18px`, `Bold (700)`
  - `Body / Label`: `14px`, `Medium (500) ~ SemiBold (600)`
  - `Caption / Meta`: `11px ~ 12px`, `Regular (400) ~ Medium (500)`

### 1.3 모서리 둥글기 & 계층 (Radius & Elevation)

- `--radius`: `0.75rem` (`12px`) 기본.
  - `Card`: `12px` (`rounded-lg`)
  - `Hero Card / Modal / BottomSheet`: `16px` (`rounded-xl`)
  - `Input / Button`: `10px` (`rounded-md`)
  - `Badge / Tab Pill`: `999px` (`rounded-full`)
- **계층 표현**: 그림자 남용을 피하고 `배경(#FAF9F8) + 카드(#FFFFFF) + 1px 보더(#EAE4E5)` 대비로 계층을 구분한다.

### 1.4 다크 테마 설계 규칙

1. **표면 계층 (Surface Elevation)**: 그림자 대신 명도 단계와 1px 보더(`--border` `#33292C` / `--border-strong` `#44363A`)로 계층을 구분한다.
   - Base (`--background` `#130F10`) → Card (`--card` `#1C1618`) → Elevated Modal/Sheet/Popover (`--surface-elevated` `#251D20`) → Control/Muted (`--muted` `#2D2427`)
2. **Primary 반전과 Hero Card 분리**:
   - 일반 `Primary` 버튼·활성 탭·링은 시인성을 위해 보라 계열 플럼(`--primary` `#CA91DE`) + 어두운 텍스트(`--primary-foreground` `#1C1320`)로 반전한다.
   - `Hero Card`는 눈부심 방지와 브랜드 일관성을 위해 `--hero-from`(`#441E52`) → `--hero-to`(`#2C1335`) 딥 플럼 그라데이션과 흰색 텍스트(`--hero-foreground`)를 유지한다.
3. **Semantic Tint 저채도화**: `Badge`와 `NoticeBox` 배경에는 Light용 파스텔 색상을 쓰지 않고, 다크 전용 딥 틴트(`--positive-tint` `#133531`, `--destructive-tint` `#3B1616`, `--warning-tint` `#3B2811`)와 고대비 전경색(`#2DD4BF`, `#F87171`, `#FBBF24`)을 조합한다.
4. **입력창·포커스·네비게이션**: 다크 입력창 배경은 `--background`(`#130F10`) 또는 `--card`(`#1C1618`)에 `--border-strong`을 적용하고, 포커스 링은 `hsl(var(--primary) / 0.24)` 글로우를 사용한다. 하단 탭바 및 사이드바 활성 항목은 `--primary-tint`(`#2B1C30`) + `--primary`(`#CA91DE`)를 사용한다.

### 1.5 크기 변경 및 반응형 규칙

크기 변경 시 글자 크기를 자동 축소하지 않는다. 디자인앱과 본 앱 모두 `flex`/`grid`·너비·최소 높이·줄바꿈으로 같은 반응형 동작을 구성한다.

| 기준                                    | 코드 토큰                                                                              | 값                                           |
| :-------------------------------------- | :------------------------------------------------------------------------------------- | :------------------------------------------- |
| 태블릿 / PC 전환점                      | `--breakpoint-md` / `--breakpoint-lg`                                                  | 48rem / 64rem (768px / 1024px)               |
| 최소 검증 화면 너비                     | `--container-viewport-min`                                                             | 20rem (320px)                                |
| 카드 두 열 배치의 최소 너비             | `--spacing-card-min`                                                                   | 17.5rem (280px)                              |
| 카드 내부 여백: 모바일 / PC             | `--spacing-card-mobile` / `--spacing-card-desktop`                                     | 1rem / 1.25rem (16px / 20px)                 |
| 컨트롤 최소 높이: sm / md / lg          | `--spacing-control-sm` / `--spacing-control-md` / `--spacing-control-lg`               | 2rem / 2.5rem / 2.75rem (32px / 40px / 44px) |
| 배지 / 탭 / 탭 항목 / 달력 셀 최소 높이 | `--spacing-badge` / `--spacing-tab` / `--spacing-tab-item` / `--spacing-calendar-cell` | 22px / 38px / 32px / 36px                    |
| 컨트롤 좌우 여백 / 모바일 터치 크기     | `--spacing-control-inline` / `--spacing-touch`                                         | 0.75rem / 2.75rem (12px / 44px)              |
| 다이얼로그 최대 너비 / 화면 좌우 여백   | `--container-dialog` / `--spacing-dialog-gutter`                                       | 23.75rem / 1rem (380px / 16px)               |
| 다이얼로그 내부 여백 / 본문 최대 높이   | `--spacing-dialog-padding` / `--spacing-dialog-body-max`                               | 1.25rem / 30rem (20px / 480px)               |

| 콘텐츠 간격: 모바일 / PC                | `--spacing-stack-mobile` / `--spacing-stack-desktop`                                   | 0.875rem / 1.125rem (14px / 18px)            |
| 헤더 높이: 모바일 / 태블릿·PC           | `--spacing-header-mobile` / `--spacing-header-desktop`                                 | 3.5rem / 4rem (56px / 64px)                  |
| 사이드바: 아이콘 레일 / 전체            | `--spacing-sidebar-rail` / `--spacing-sidebar-full`                                    | 4.75rem / 14.75rem (76px / 236px)            |
| 하단 탭바 / 진행 막대 높이              | `--spacing-bottom-nav` / `--spacing-progress-track`                                    | 4.25rem / 0.375rem (68px / 6px)              |

- rem의 px 표기는 기본 루트 글자 크기 16px 기준이다. `md:` / `lg:`는 전환점, `min-h-control-lg`, `p-card-mobile`, `lg:p-card-desktop`, `max-w-dialog` 등은 크기 유틸리티로 사용한다. 토큰 정의만으로 기존 컴포넌트의 동작이 바뀌지는 않는다.
- 모바일은 한 열과 하단 탭바, 태블릿은 아이콘 레일, PC는 전체 사이드바를 사용한다. 두 열은 카드마다 280px을 확보할 수 있을 때만 사용하고, 공간이 부족하면 한 열로 배치한다.
- 카드·입력창·선택창·안내문은 부모 너비를 채우고 높이는 내용에 맞춘다. 제목·설명·오류 문구는 줄바꿈하며 말줄임하지 않는다.
- 버튼·배지는 기본적으로 내용에 맞춘 너비(Hug)를 사용한다. 폼 제출 버튼이나 긴 문구의 버튼은 부모 너비(Fill)와 줄바꿈을 사용한다. 버튼 높이는 고정 상한이 아닌 최소 높이이며 모바일 주요 액션은 44px 이상을 확보한다.
- 탭은 너비를 균등 분배하고 선택 표시도 항목 너비를 따른다. 금액은 한 줄·우측 정렬을 유지하며, 공간이 부족하면 주변 라벨과 설명을 다음 줄로 배치한다.
- 다이얼로그 기본(`size="default"`) 너비는 `min(380px, 100% - 32px)`이며, 다열 폼 모달(`size="lg"`)은 태블릿 `560px`(`35rem`), PC `620px`(`38.75rem`) 상한을 사용한다. 본문은 최대 480px과 남은 뷰포트 높이 중 작은 값 안에서 스크롤하고, 제목·액션은 보존한다. 모바일 입력 시트는 기존 `90dvh` 상한을 적용한다.
- 모바일 거래 목록은 카드, 태블릿 이상은 표를 사용한다. 열이 좁아지면 보조 정보를 같은 셀의 두 번째 줄에 배치하며, 금액을 축소하거나 잘라서 맞추지 않는다.
- 한 화면에 여러 표가 세로로 나열될 때(`일반`·`고정`·`할부` 등)는 `table-fixed`와 고정 열 너비(`날짜·분류`, `결제 수단`, `실사용자`, `지불 상태`, `금액`) + `내역` 1열 가변 조합을 사용하고, 긴 텍스트는 `truncate` 처리해 모든 표의 세로 열 경계선을 일치시킨다.
- 표 열 정렬은 `날짜(· 분류)`·`분류`·`실사용자`·`지불 상태` 가운데 정렬(`text-center`), `내역`·`결제 수단`·`결제 계좌` 좌측 정렬, `금액` 등 수치 열 우측 정렬(`text-right tabular-nums`)을 따른다.
- 라벨 없는 `Checkbox`는 `44px × 44px`(`min-w-touch`) 중앙 정렬 래퍼를 가지므로, 체크박스 열은 최소 `48px`(`w-12 pl-1 pr-0`, 셀 `py-1`) 이상을 확보해 인접 열 패딩과 겹치지 않게 한다.
- 화면 시안과 컴포넌트 카탈로그는 `apps/design`(포트 `4100`)에서 실제 CSS 미디어 쿼리(`md:`/`lg:`)와 `4단 비교`(`320·375·768·1280px`), `단독 보기`(브라우저 리사이즈), `html.dark` 테마 전환으로 직접 검증한다.
- 검증 너비는 320·375·768·1280px이다. 긴 가계부명·여러 줄 설명·`123,456,789원`을 넣어 내용이 보존되는지 확인한다.

## 3. Composite Components (`@repo/ui-composition`)

`@repo/ui-core` 기본 부품을 조합한 도메인 중립 공용 컴포넌트로 `packages/ui-composition/`에 위치하며 현재 사용처는 `apps/client`와 `apps/design`이다. 별도 관리자 앱은 확정된 제공 범위에 포함하지 않는다.

| 컴포넌트                                                           | 주요 Props / 역할                                                               | 크기 / 규격                            | 비고                                                                          |

### 3.1 `CommonDialog` (JS 명령형 Alert / Confirm / Prompt)

`dialog.alert()`, `dialog.confirm()`, `dialog.prompt()` 형태로 어디서든 호출 가능한 공통 다이얼로그 시스템.

| 유형                 | 옵션 스펙                                                                             | 버튼 규칙 (2~4자 단일 단어)                                        |
| :------------------- | :------------------------------------------------------------------------------------ | :----------------------------------------------------------------- |
| **`Alert`**          | `{ title, description, confirmText? }`                                                | 1버튼 (`확인` / 예외 시 `다시 시도`)                               |
| **`Confirm` (일반)** | `{ title, description, notice?, confirmText, variant: 'default' }`                    | 2버튼 (`취소` / 구체적 동사 `연결`, `변경`, `적용`)                |
| **`Confirm` (위험)** | `{ title, description, notice?, confirmText, variant: 'destructive' }`                | 2버튼 (`취소` / 파괴적 동사 `삭제`, `초기화`, `내보내기`)          |
| **`Prompt`**         | `{ title, description?, label, placeholder?, defaultValue?, validate?, confirmText }` | 2버튼 (`취소` / 제출 동사 `추가`, `변경`, `저장`) + 하단 에러 표시 |

- `notice` 슬롯은 금융 기록 보존 고지(예: 미참여 인물 삭제 시 과거 거래 이름 보존) 등 필수 안심 문구가 필요할 때만 렌더링한다.

### 3.2 검색 · 상세 필터 · 액션 카드 · 보조 안내 규격

- **검색 · 다중/단일 필터 바 (`FilterSingleSelect` · `FilterMultiSelect`)**:
  - 검색창 기본 플레이스홀더는 `내역 검색`을 사용한다.
  - 필터 트리거는 기본 상태(`전체`)에서 라벨만 표시(`기간`, `결제 계좌`, `결제 수단`, `분류`, `실사용자`, `지불 상태`)하고, 선택 시에만 `기간: 이번 달만` 또는 `라벨 N` 및 브랜드 틴트(`border-primary bg-primary-tint`)를 적용한다.
  - 열린 드롭다운 목록과 모바일 `상세 검색` 바텀 시트 각 그룹 선두에는 명시적인 `전체` 항목·칩을 배치하며 헤더의 중복 선택 해제 버튼은 두지 않는다.
  - 태블릿 이상(`>= 768px`)은 검색 인풋(`md:min-w-36 md:max-w-44 md:flex-1 lg:w-64 lg:flex-none`)과 필터 버튼 묶음(`md:shrink-0`)을 한 줄 가로 행으로 유지하고, 모바일(`< 768px`)은 검색 인풋 + `상세 검색` 시트 버튼(선택 건수 배지, `360px` 미만 아이콘+배지) 1줄 조합을 사용한다.
- **이동용 액션 카드**: 다른 관리 화면으로 이동하는 요약 카드는 정적 KPI 카드와 구분되도록 메뉴명을 진한 굵은 글씨(`font-bold text-foreground`) 주체로 두고, 아이콘 뱃지와 우측 원형 `>`(`ChevronRight`) 버튼으로 이동 어포던스를 드러내며 상태 수치는 아래 보조 정보로 배치한다.
- **행 내 수정 액션 & `?` 안내 팝오버**:
  - 표·카드 행의 금액·속성 수정 버튼은 전 해상도 `size-7` 테두리형 `Pencil` 아이콘 버튼(`aria-label`, `title` 병기)으로 통일한다.
  - 보조 용어·기준 안내는 호버 전용 `Tooltip` 대신 모바일·PC 모두 동작하는 카드 제목 옆 `?` `Popover`(`align="start"`, `w-[min(18rem,calc(100vw-2rem))]`)로 제공한다.

## 4. Domain Components & 화면 규격 (`apps/client`)

가계부 업무 규칙·라우팅·도메인 모델과 결합된 컴포넌트로 `apps/client/components/`에 위치한다.

### 4.1 가계부 `AppShell` 배치 기준

| 뷰포트                        | 네비게이션 구조                                                                        | 보조 UI                                                                                                                   |
| :---------------------------- | :------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------ |
| **모바일 (`< 768px`)**        | 하단 5칸 탭바 (`결산 · 지출 · [+ 지출 추가] · 수입 · 전체`, `68px`)                    | 상단 헤더(`56px`): 화면 제목 + 월 선택기 + 가져오기·더보기(`[⋯]`), `전체` 바텀 시트(상단 가계부 드롭다운 + 5종 전체 메뉴) |
| **태블릿 (`768px ~ 1023px`)** | 좌측 `76px` 아이콘 레일 (상단 가계부 전환 아이콘 + `결산 · 지출 · 수입 · 자산 · 설정`) | 상단 헤더(`64px`): 화면 제목 + 서브탭 + 월 선택기 + `+ 지출 추가`                                                         |
| **PC (`≥ 1024px`)**           | 좌측 `236px` 풀 사이드바 (`결산 · 지출 내역 · 수입 내역 · 자산 현황 · 가계부 설정`)    | 상단 헤더(`64px`): 페이지 제목 + 서브탭 + 월 선택기 + 보조 액션 + `+ 지출 추가`                                           |

- 사이드바와 태블릿 아이콘 레일(`76px`)·PC 풀 사이드바(`236px`)·모바일 하단 탭바(`68px`)는 공용 내비게이션 셸(`apps/design`에서는 `DesignAppShell`, `apps/client`에서는 도메인 `AppShell`)로 일관되게 관리한다.
- 태블릿 아이콘 레일과 PC 풀 사이드바에는 내비게이션과 가계부 전환 요소만 배치하고 `+ 지출 추가` CTA는 화면 상단 헤더로 올린다. 모바일에서만 하단 탭바 중앙의 원형 `+` · `지출 추가` 라벨 버튼으로 즉시 지출 입력을 연다.
- PC 메뉴 항목은 왼쪽 정렬·`20px` 아이콘·`14px` 좌측 여백으로 라벨 시작점을 맞추고, 태블릿 레일은 아이콘과 라벨을 중앙 정렬한다. 가계부 전환기는 PC 사이드바 상단 전체 너비 드롭다운, 태블릿 레일 상단 아이콘·축약명 트리거(우측 `Popover`), 모바일 `전체` 메뉴 바텀 시트 상단 드롭다운으로 통일한다.
- 개별 화면에서 사이드바 메뉴 정렬이나 자식 너비를 임의로 덮어쓰지 않고, 헤더 슬롯(제목·서브탭·기간 선택기·보조 액션)으로만 차이를 주입한다.

### 4.2 `AmountText` (금융 금액 포맷터)

- 원화(`KRW`) 정수 단위를 `1,420,000원` 형식으로 출력하며 항상 `tabular-nums`를 적용한다.
- 옵션: `sign`: `'auto'` (`+` / `−` 표시) \| `'none'`, `tone`: `'neutral'` \| `'semantic'` (양수 `--positive`, 음수 `--destructive`).
- 음수 기호는 하이픈(`-`) 대신 유니코드 마이너스(`−`)를 사용한다.

### 4.3 `LedgerMonthPicker` / `YearPicker` & `LedgerSwitcher`

- `LedgerMonthPicker`: `@repo/ui-composition` `PeriodPicker(mode="month")` 기반의 `< 2026.11 >` 컨트롤. 중앙 클릭 시 12개월 그리드(생성됨/미생성 상태 표시)를 열며, 미생성 미래 월(최대 +2개월) 진입 시 생성 확인 `CommonDialog`와 연동한다.
- `YearPicker`: `@repo/ui-composition` `PeriodPicker(mode="year")` 기반의 `< 2026 >` 컨트롤. `결산 > 연간` 탭 등 연도별 조회에 사용하며 중앙 클릭 시 연도 그리드를 연다.
- `LedgerSwitcher`: 현재 가계부명 표시 및 복수 가계부 전환용 컴포넌트. 태블릿(`76px` 레일 상단 아이콘+우측 `Popover`)·PC(사이드바 상단 드롭다운)·모바일(`전체` 메뉴 바텀 시트 내 스크롤 드롭다운)로 배치한다.

### 4.4 `TransactionFormSheet` & `PersonSelector`

- `TransactionFormSheet`: 지출·수입 입력 및 수정을 담당하는 바텀시트/모달 셸. 지출은 예산 반영월 입력을 제공하지 않고 일반·고정 지출은 거래일·예정일, 할부는 현재 조회 월·회차 번호로 반영월을 계산해 미리보기에서 보여준다. 수입은 예산 반영월 입력을 유지한다. 지출은 금액·날짜·분류·결제수단과 분류 분할·할부·실사용자·회수 금액을 구성한다. 신규 실사용자는 결제수단 소유자를 기본으로 하고 결제수단 변경마다 새 소유자로 다시 지정한다. 사용자는 이후 직접 변경할 수 있으며 회수 내역은 연동 변경하지 않는다. 수입은 종류·실수령액·입금 계좌·일자·예산월을 기본으로 두고, 별도 입력 방식 선택 없이 지급·공제 목록으로 통일한다. 모든 종류는 종류별 기본 항목이 있는 지급·차감 목록을 사용하며 각 목록의 추가 버튼과 행별 제거 버튼, 항목명·금액 편집을 제공한다. 종류별 고유 정보는 금액 목록과 구분한다. 실수령액은 지급 합계에서 실제 공제 합계를 빼 읽기 전용으로 표시하며 별도 입력란을 두지 않는다. 단일 지급·공제 없음도 허용한다. 일반 지급 항목 하나만 남겨 실수령액을 기록할 수 있으며, 전용 추가 버튼·배지·혼용 제한은 두지 않는다. 지급·공제 합계는 장부 입력값으로 표시하고 세무상 확정 금액으로 표현하지 않는다. 미입력 금액을 0원으로 계산하지 않는다. 별도 공통 세무 정보 섹션은 두지 않는다. 해당 소득의 지급 행에 과세 구분을 두고 세금·보험료는 공제 행에서 입력한다. 명세서 귀속월 또는 소득 귀속 기간은 기본 정보의 선택값으로 두고 예산월과 분리한다. 미입력 금액과 확인된 0원을 구분한다.
- `PersonSelector`: 가계부 구성원(본인 `(나)` 표기 포함)과 등록된 `미참여` 인물을 그룹핑해 선택한다. 실사용자 목록에는 가상 `공통` 항목을 두지 않으며, `지출금 회수` 상대 선택 드롭다운은 구분선 하단의 `직접 입력`을 통해 미등록 인물 입력을 허용한다.

- 수입 기본 정보의 `귀속연도 · 선택`은 확인한 자료의 연도를 입력하며 모르면 비워 둘 수 있다. 명세서 귀속 연월·소득 귀속 기간, 입금일 및 예산 반영월과 따로 보존하고 자동 확정하지 않는다.

- 지출 기록 상단의 선택형 AI 입력 보조는 캡처 붙여넣기·한 장 첨부·끌어놓기·작성한 설명을 받는다. 원문과 현재/제안 값·분류 변경을 대조한 뒤 폼에 반영하고 기존 지출 저장으로 확정한다. 생성 중·실패·재확인·중복 후보를 구분하고 수동 입력을 유지한다. 참고화면은 합성 해석 결과임을 표시하며 실제 첨부는 로컬 미리보기만 한다.

### 4.5 `CardPerformancePanel` / `CardPerformanceTier`

- 월별 현황 섹션 제목은 `카드별 이용 실적`이다. 예정 거래 포함 여부는 제목과 분리해 `예정 거래 포함`으로 안내한다.
- 카드별 실적 패널에는 1px 강조 구분선(`--border-strong`)·12px 모서리·16px 내부 여백과 배경색(`--background`)을 적용해 카드 사이를 구분한다. 패널 사이 간격은 유지하고 같은 행의 너비·높이를 맞춘다.
- 카드별 실적 금액, 달성 상태, 단계별 진행 구간과 상세 행을 표시한다. 기준액은 오름차순으로 정렬하고 모든 확인된 단계를 표시하며 첫 단계나 다음 단계만 보여주지 않는다.
- 각 단계 행에는 `단계 · 기준액 이상`, `부족액 남음` 또는 `기준 이상`, 혜택 내용, 월 한도와 단위를 표시한다. 한도가 포인트인 경우 원화로 바꾸지 않는다.
- `CardPerformanceSegment`는 단계별 진행 구간을 구성하고 컨테이너 너비가 바뀌어도 채움 비율을 유지한다. 구간 진행률은 이전 단계 기준부터 현재 단계 기준까지의 달성 비율이다. 카드별 누적 실적을 모든 구간의 기준액으로 각각 나누지 않는다. 각 구간은 0~100%로 표시한다.
- 단계 경계에는 `CardPerformanceMilestone`의 10px 원형 마커를 연속 트랙 위에 겹쳐 둔다. 달성한 단계는 브랜드색 점, 미달 단계는 트랙과 같은 배경의 얇은 원으로 구분하며 체크 기호는 사용하지 않는다. 구간 사이 간격과 내부 모서리 라운드를 제거해 막대가 하나로 이어지도록 한다. 달성 여부는 상태 문구와 단계 상세로도 표시한다.
- 단계 라벨의 오른쪽 끝과 마커 중심을 해당 구간의 오른쪽 경계에 맞춘다. 라벨을 구간 중앙에 배치하지 않으며 기준액을 줄바꿈할 수 있게 해 인접 라벨과 겹치지 않도록 한다.
- 상태는 `미달`, `일부 단계 달성`, `목표 달성`, `확인된 단계 없음`, `일부 조건 확인 필요`를 구분한다. 조건 확인 안내가 필요해도 확인된 단계의 정보를 숨기지 않는다.
- 디자인 예시는 화면설계서의 30만·60만·100만 원 기준과 생활 영역 할인·월 한도 1만·2만·3만 원을 사용한다. 실적 480,000원은 1단계 달성·2단계까지 120,000원·3단계까지 520,000원 부족으로 표시한다.
- `CardPerformanceTier` 인스턴스를 단계별로 조합하고 단계 수가 바뀌면 행과 진행 구간 수도 함께 맞춘다. 디자인앱 시안의 실적·부족액·진행률은 예시 상태로 동작하며 실제 서버 계산을 수행하지 않는다.
- 모바일에서는 한 카드의 모든 단계를 세로로 표시한다. 기준액·부족액이 같은 줄에 들어가지 않으면 줄바꿈하며 금액은 축소하거나 말줄임하지 않는다.

### 4.6 결산 정보 우선순위와 행 정렬

- 모바일 `결산 > 월별` 순서는 `남은 생활비 → 자료 기준 → 분류별 예산 · 지출 → 확인할 일 → 카드별 이용 실적`이다.
- 태블릿·PC는 첫 행에 남은 생활비와 확인할 일을 동일 너비·높이로 배치하고, 다음에 분류별 예산·지출을 전체 너비로 표시한다. 카드별 이용 실적은 그 아래 전체 너비 영역에 두고 카드 A/B를 같은 너비·높이로 비교한다.
- 분류별 영역 제목은 `분류별 예산 · 지출`이다. 모바일은 예산과 지출을 같은 크기의 두 열로 표시하고, 남은 금액 또는 초과 금액을 별도로 강조한다. 전월 이월은 보조 정보로 표시한다. 태블릿·PC는 월 예산·이월·지출·소진율·남은 금액 표를 사용한다.
- 별도 소비 요약 카드 대신 분류별 영역에 이월 반영 여부·예산 초과 분류 수를 짧게 표시한다. 긴 카드 실적이 분류별 예산·지출보다 먼저 나오지 않도록 한다.
- 태블릿·PC의 `월별 | 연간` 탭은 왼쪽의 `결산` 제목 뒤에 `16px` 간격으로 묶는다. 왼쪽 그룹은 내용 너비(Hug)로 유지하고, 월·연도 선택기, 가져오기, `+ 지출 추가`는 오른쪽에 배치한다.
- 같은 행의 카드에는 여백·테두리가 없는 동일한 바깥 열 컨테이너를 사용하고, 그 안의 카드를 Fill로 배치한다. 패딩이 다른 카드 자체에 너비를 분배해 좌우 바깥 크기가 달라지지 않게 한다.
- 같은 행은 가장 긴 콘텐츠를 담을 수 있는 높이로 맞추고 양쪽 카드를 세로 Fill로 정렬한다. 금액·설명을 축소하거나 잘라 높이를 맞추지 않는다. 자료 기준 안내는 첫 행 아래의 공통 줄로 분리한다.
- `결산 > 연간`은 연도·복수 선택 가능한 집계 대상, 연간 요약, 가계부 전체의 예산 공지, 월별 수입·지출 그래프, 분류별 예산·지출 표, 수입·공제 내역 순으로 배치한다. 별도 구성원별 합계는 두지 않는다.
- 연간 요약은 선택 대상의 `연간 수입 총액`, `연간 지출 총액`, `연간 잔액` 카드로 구성한다. 수입 총액은 실수령액 기준이다. 잔액에는 `1~11월 수입 − 지출`처럼 기준월과 계산 관계를 표시한다. 전년도 이월은 잔액에 포함하지 않는다.
- `분류별 지출 / 예산(이월 제외)`은 모든 화면에서 `분류 | 1월 … 12월 | 연간 합계` 교차표를 사용한다. 금액은 `지출 / 예산` 순서로 표시하고 표에 원 단위를 표시한다. 모바일에서는 지출과 예산을 두 줄로 표시하고 표의 열 너비를 줄인다. 분류명·월 제목·금액은 가운데 정렬한다. 구성원을 선택하면 표 제목의 지출을 전체 지출로 명시하고 집계 대상 지출을 들여써 표시한다. 구성원 지출은 전체에 포함되며 결제수단 소유자 기준이다. 분류 열을 고정하고 표 내부에서 좌우로 이동하며 연간 합계와 1월로 바로 이동하는 동작을 제공한다.
- 표 아래의 `분류별 그래프 보기`는 기본 접힘이며 `분류` 선택기에서 여러 분류를 고른다. 기본 전체 선택이며 표에서 분류를 누르면 해당 분류만 선택해 그래프를 연다. 선택 분류의 월별 전체 지출을 누적 막대, 예산 합계를 실선으로 표시하고 구성원을 일부 선택한 경우 선택 지출을 점선으로 추가한다. 선택 분류가 없으면 `분류를 선택해 주세요`를 표시한다. 범례·차트·툴팁은 선택한 분류만 표시하며 미확인 예산을 0원으로 대체하지 않는다.
- 연간 그래프는 마우스 호버·터치·키보드로 선택한 월의 금액을 제공하고 양수와 음수에 동일한 금액 비율을 사용한다. 색상에 더해 범례와 금액 상세를 제공하고 음수·기록된 0원·내역 없음·월 준비 전을 구분한다. 월 예산은 이월을 제외한 저장된 배정액이며 연간 예산에 포함된 개월 수와 월 준비 전의 기등록 지출을 표시한다. 예산과 지출의 대상 월이 다를 수 있으므로 두 합계의 차액·소진율을 가용 잔액으로 표현하지 않는다. 조회만으로 월을 생성하거나 미등록 거래를 예측하지 않는다.
- 수입·공제는 연간 합계와 1~12월 실수령액을 표시한다. 접힌 연간 합계에는 입력 지급·공제 합계와 항목별 연간 합계를, 각 월에는 해당 월의 합계와 수입별 상세를 제공한다. 귀속연도별 세무 통계는 제공하지 않는다.

## 5. 카피 및 마이크로카피 원칙

- **모바일 탭/버튼 길이 제한**: 하단 탭 및 서브탭은 2자(`결산`, `지출`, `수입`, `전체` / `월별`, `연간`), 태블릿 레일 2자(`결산`, `지출`, `수입`, `자산`, `설정`), PC 사이드바 및 모바일 `전체 메뉴` 시트는 명확한 전체 명칭(`결산`, `지출 내역`, `수입 내역`, `자산 현황`, `가계부 설정`)을 사용한다. 다이얼로그 버튼은 2~4자 이내로 제한해 줄바꿈을 방지한다.
- **금융 경계 고지**: `남은 생활비`와 `실제 통장 잔액`은 항상 구분해 표현하며, 단순 데이터 기준 시점 안내에는 경고 배너 대신 `11.04 기준 입력 · 실시간 은행 잔액과 다름` 형태의 1줄 메타 텍스트를 사용한다.
- **표준 도메인 용어**:
  - 역할/인물: `소유자`, `관리자`, `구성원`, `미참여`
  - 지불·지출 용어 및 띄어쓰기: `결제 수단`, `지불 상태`, `거래 내역`, `결제 계좌`, `채울 금액`, `계좌별 채울 금액`, `지불 관리`, `할부 관리`, `회수금 관리`, `내역 검색`
  - 지불 상태: `준비 필요`, `지불 대기`, `지불 완료`
  - 지불 상태 배지: `준비 필요`는 사용자 조치가 필요한 상태로 브랜드색 채움(`bg-primary text-primary-foreground`)으로 가장 강하게 강조한다. `지불 대기`는 자금 확보가 끝난 정상 진행 상태로 청록색(`positive`), `지불 완료`는 추가 조치가 없는 상태로 회색(`neutral`)을 사용한다. 모바일 목록과 PC 표에 동일하게 적용하며 상태명도 함께 표시한다. 노란 주의색은 조건 미확정·검토 필요 등에 사용하고 정상적인 지불 대기에는 사용하지 않는다.
  - 지출금 회수: `회수 대상 금액`, `미회수 금액`, `회수한 금액`
- **안내 문구 작성 원칙**: 두 개념(`채울 금액` vs `조정 금액` 등)이 함께 설명될 때는 각 문장의 주어를 명시하고, 실시간 합산 표·입력칸 `placeholder` 등으로 이미 자명한 부호 안내(`− 덜 채움 / + 더 채움` 등)는 중복 서술하지 않는다.
